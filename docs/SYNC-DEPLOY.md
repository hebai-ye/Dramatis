# 部署方案答卷（P2-6 第四步·下）

> 面向的问题：**你有一台自己的服务器，想把同步后端放上去；项目是公开仓库，
> 但你的服务器地址与个人设置不能进仓库。** 这份文档把「放哪、怎么放、
> 什么会公开、我需要你提供什么」一次讲清，供你决定。
>
> 相关：[SYNC.md](./SYNC.md)（协议与选型）、[../tools/sync-server/README.md](../tools/sync-server/README.md)（操作手册）。
> 最后更新：2026-09-20。

## 一、目标与硬约束

| # | 约束 | 出处 |
| --- | --- | --- |
| 1 | 本地库是唯一真相源，服务器挂了也不影响使用 | SYNC §2 |

## 二、信息分层：什么会公开，什么留在哪

这是这份答卷的核心。三类信息严格分开：

| 层 | 内容 | 存放位置 | 会不会进 GitHub |
| --- | --- | --- | --- |
| **公开层** | 协议、内核代码、服务端实现、部署脚本、文档模板（全部用占位符） | 仓库 | ✅ 会，且**应该**会 |
| **本机层** | 你的服务器地址、用户 id、同步密码、恢复码、应用里的世界线数据 | ① 应用设置里（浏览器 IndexedDB）② 你本机的 `.env` / 命令历史 | ❌ 不会（`.gitignore` 已挡住 `.env` / `*.db` / `backups/` / `dist/`） |
| **服务器层** | SQLite 里的密文、两份凭证哈希、两份钥匙封装、systemd 环境变量 | 你的服务器（`/var/lib/dramatis-sync`、`/etc/systemd/system/…`） | ❌ 不会（根本不在仓库里） |

**几个容易漏的地方，先说清**：

1. **服务器地址一旦 commit 就洗不掉**（Git 历史永久保留），所以地址只写在
   你本机的 `.env` 与应用设置里，文档里一律写 `你的域名` / `<你的服务端地址>`。
2. **`git status` 是最后一道门**：部署期间每次提交前用它确认没有 `.env`、`.db`、
   日志、证书被带进去。
3. **截图与录屏**同样会泄露地址——要发到仓库里的截图先把地址栏遮掉。
4. **同步密码永远不会离开你的设备**，所以「密码泄露」只可能发生在你自己那边：
   别写进仓库、别贴进 issue。

## 三、部署形态三选一

> 前提：应用页面必须是安全上下文，否则端到端加密用的 WebCrypto 不存在。

| 形态 | 服务端对外方式 | 应用页面 | 手机能用 | 要域名/备案 | 外网可达 |
| --- | --- | --- | --- | --- | --- |
| **A. Tailscale（推荐先试）** | 服务监听 `127.0.0.1`，由 Tailscale 暴露给 tailnet | 桌面用 `http://127.0.0.1:5273`（安全上下文 ✓）<br>手机用 tailnet 里的 https 地址 | ✅ | ❌ 不需要 | ❌ 只有你自己的设备 |
| **B. 域名 + HTTPS** | Caddy 反代 + Let's Encrypt | 可以就用 `https://你的域名` 直接打开应用 | ✅ | 国内服务器**需要 ICP 备案** | ✅ 公网可访问（凭证不对仍是 401） |
| **C. 只在本机验证** | 不对外，服务与页面都在这台电脑上 | `http://127.0.0.1:5273` | ❌ | ❌ | ❌ |

**我的建议**：先用 **A** 把「手机 ↔ 电脑同一条世界线」跑通（今天就能做，零成本、
零暴露），等你确认体验没问题、也确实想要一个独立网址，再决定要不要为 **B** 走备案。

## 七、验收标准（部署完成的定义）

1. `systemctl status dramatis-sync` 是 running，重启机器后自动起来；
2. 手机与电脑各同步一次后，**两端看到同一条世界线**（消息条数与顺序一致）；
3. 在服务器上 `sqlite3 … "SELECT space_handle, COUNT(*) …"` 能看到记录，
   但**看不到任何明文**（内容全是密文）；
4. 断网时应用照常可用（本地优先），恢复网络后能补同步；
5. `journalctl` 里没有凭证、没有对话内容；
6. 备份文件生成，恢复演练通过；
7. 仓库里 `rg -n "你的域名|你的IP|<你的 id>"` 搜不到真实值。

## 八、回滚与退出

| 场景 | 怎么做 |
| --- | --- |
| 只是不想同步了 | 应用设置里清掉服务端地址即可；本地数据一个字都不动 |
| 想换服务器 | 在新机器上跑同样的服务；应用里改一个地址，客户端会自动从零拉一遍（旧服务器可留着当备份） |
| 想彻底删掉服务器上的数据 | `DELETE FROM records/heads/spaces WHERE space_handle='<句柄>'`（见 README 第 7 节） |
| 服务器到期 | 备份文件 + 各设备本地库都在，数据不会丢；换机器重跑一次部署即可 |

## 九、你的具体情况对应的方案（2026-09-20 更新）

你的诉求：**自己的多台设备随时随地用 + 邀请一些朋友用 + 没有域名（备案要时间）+ 想部署在这台腾讯云上 + 电脑能留 2GB 做备份**。

### 9.1 先看一件容易被忽略的事

朋友要用的不只是「同步服务端」，还有**网页本身**。所以部署要包含两样：

1. **同步 API**（`tools/sync-server`，已就绪）；
2. **网页**（`apps/web` 的构建产物，`pnpm build` 产出 `apps/web/dist`）。

把两者放在**同一个地址**下最省事（不用 CORS、一张证书、朋友只记一个网址），
模板见 [deploy/README.md](../deploy/README.md)。

另外有一个**代码前提**：应用界面还没有接上同步（设置里还没有「服务端地址 + id + 密码」
那一块）。朋友打开网页要能看到它，这一步必须先做完——我可以接着做。

### 9.2 通道选择（关键决策）

| 方案 | 要不要域名 | 要不要备案 | 大陆访问 | 朋友怎么用 | 评价 |
| --- | --- | --- | --- | --- | --- |
| **A. Tailscale（只给自己）** | 否 | 否 | 好（打洞成功时几乎局域网速度） | 朋友用不了（或也要加入你的 tailnet） | ✅ **今天就能用**，零暴露、零合规问题 |
| **B. 域名 + 8443（先不备案）** | 要（¥10/年起） | 否（绕开 80/443） | 好（国内直连） | 浏览器打开即可 | ⚠️ 技术上可行、很常见，但严格说属灰色地带；朋友用建议尽快转 C |
| **C. 域名 + 443（备案后）** | 要 | 要（2–4 周） | 最好 | 浏览器打开即可 | ✅ 唯一"完全合规"的国内方案 |
| **D. Cloudflare Tunnel / Tailscale Funnel（无域名公网）** | 否 | 否 | **不稳**（走境外边缘，可能被墙/慢） | 浏览器打开即可 | 🧊 应急可用，不适合当长期主路；URL 与可用性要实测 |
| **E. 换成香港/境外小 VPS** | 要 | 否 | 中（跨境延迟 50–150ms） | 浏览器打开即可 | 🧊 不想备案时的"干净"替代，但数据离开国内 |

### 9.3 建议的路线（分三段，都能独立验收）

**第一段 · 今天：先把「自己多设备」跑通（方案 A + 备份）**

1. 服务器上部署同步服务端（systemd，只听 `127.0.0.1:8787`）；
2. 装 Tailscale，`tailscale serve --bg --https 443 http://127.0.0.1:8787`；
3. 你自己的电脑/手机装 Tailscale，应用里填 tailnet 的 https 地址 + 用户 id + 同步密码；
4. 电脑上设一个每日任务，从服务器拉一份备份（下一节）。

这一段**不花额外的钱、不碰备案、服务器端口一个都不用对公网开放**。

**第二段 · 朋友进来（方案 B，或等 C）**

1. 买一个域名（¥10–60/年），A 记录指向服务器；
2. 用 DNS-01 签证书（`acme.sh --dns dns_dp`），nginx 用 `deploy/nginx-8443.conf.example` 起 8443；
3. 把网页与 API 都放到这个域名下（同源），朋友打开 `https://sync.你的域名:8443` 注册自己的 id；
4. **同时启动备案**（腾讯云控制台走流程，2–4 周）。

**第三段 · 备案下来（方案 C，长期）**

1. 换成 `deploy/Caddyfile.example`，证书自动续期，走标准 443；
2. 朋友那边**不用改任何设置**（同一个域名，只是去掉了端口号）；
3. 把 8443 关掉。

### 9.4 朋友用的时候，哪些是他们该知道的

1. **每人一个独立空间**：自己填 id + 自己设密码，服务端按句柄完全隔离；谁也看不到谁的数据。
2. **服务端看不见内容**：只有密文、凭证哈希、时间与大小；但**服务端管理员（你）能看到元数据**
   ——谁的空间、多少条、什么时候同步过、每条多大小的。这一点要在邀请时讲清楚。
3. **别用手机号当 id**：句柄虽然是折过的，但 id 本身会进服务端查询（SYNC §3.1 有说明）。
4. **忘了密码只能靠恢复码或封存文件**：没有找回通道，这是端到端加密的代价。
5. **一人一份封存**：让他们偶尔在「设置 → 封存」里导出一次，等于自带兜底。

### 9.5 你电脑那 2GB 怎么用

两种情况，**都够**（服务端实测常驻内存 ≈ 60–100 MB）：

| 做法 | 内存占用 | 说明 |
| --- | --- | --- |
| **① 只拉备份（推荐）** | 几乎为 0（不用常驻进程） | Windows 计划任务每天 `scp root@服务器:/var/backups/dramatis/*.bak D:\dramatis-backup\`；服务器上已有 `backup.mjs`（VACUUM INTO 在线快照 + 保留 30 份） |
| **② 电脑也跑一台（热备）** | ~100 MB | 同一份代码，`DRAMATIS_SYNC_DATA` 指向本地文件；定期把服务器的 `.db` 拉过来即可。真要切换时，把应用里的地址改成电脑的（前提是电脑能被你的设备访问，通常还要 Tailscale） |

建议：**① 为主 + 每次大改动前手动导出一份封存**。你留的 2GB 连 ② 都绰绰有余，
所以想更稳可以两个都上（①每天拉、②每周对齐一次）。
