## 2. 现有流程及卡点

| 入口 | 实际路径 | 卡点 |
| --- | --- | --- |
| 首次打开 | 自动建立“玩家”身份及默认模型配置；没有世界、角色卡或世界书；直接显示完整工作台 | 同时出现新对话、创建、导入、三种素材、主副切换、面板、账户、设置；中心空态只讲去哪里，没有主要操作 |
| 新对话 | 五个文本字段：世界名、首条对话名、场景名、地点、世界内时间；再选角色卡和世界书 | 默认值可提交，却把五项和两组选择全展开；无卡也能“开始”，后续发送被“没有可回应角色”拒绝 |
| 导入角色卡 | 左栏导入，保存角色卡；没有世界时自动建世界并加入卡；有内嵌世界书时保存并关联 | 与素材库导入不同：后者仅保存素材，不直接开始；成功后缺少一致的下一步表达 |
| 导入世界书 / 身份 | 保存至素材库；不自动建立可聊天的角色和场景 | 新用户容易以为“导入成功”就能聊天 |
| 创建 | 没有世界则先建空世界，再打开副对话“世界管理员” | 用户需要先理解起草、采纳，再自行把素材加入主对话；Key 未配时又要转接 |
| 手写角色 | 进入角色素材库，再进编辑区，再新建；名字、昵称、描述、立绘、性格、作者、版本、标签均可见 | 缺少“用此角色开始”的连续动作，填完要回新对话重新选择 |
| 首次发送 | 无可用 Key 时“生成提示词”，先逐人接角色回复，再接可选记忆分析 | 大段说明重复出现在空态、输入区、转接面板；设置路径仍有旧“模型接入”名称 |
| 已有 Key | 发送 → 可能先进行发言安排 → 角色逐个生成 → 保存 / 后台任务 | 需区分生成、保存、失败和费用未知，不能一律报“成功” |
| 世界封存 | 设置 → 数据与备份 → 导入封存；导入新世界并尝试打开 | 与角色素材入口分散；导入已落库但导航失败时不能提示用户盲目重复导入 |

重要现状：内置图库是立绘，候选没有可直接开聊的示例角色预设。`needsWebBridge` 当前仅检查 Key 是否为空；不能把设置里“本地接口可不填 Key”当成已经验证的直连能力。所有推荐均不改这两个事实。

## 3. 方案取舍与推荐

| 方案 | 首次入口 | 优点 | 代价 | 判断 |
| --- | --- | --- | --- | --- |
| A：先填 DeepSeek Key，再开始 | 一个 Key 输入框 → 预选静态示例角色 → 开始对话 | 推荐用户直接使用 API，首轮不需复制粘贴，也不用调整模型参数 | 需提供明确申请入口；已有 Key 状态与读取异常要区分 | **推荐，按用户补充采用** |
| B：先选角色，首次发送才配 Key | 角色 → 输入消息 → 配置或网页版转接 | 无 Key 的用户先准备素材 | 仍把接口与转接选择留到第一轮，未体现优先申请 Key | 历史方案，本版不采用 |
| C：完整模型配置向导 | 服务商 / 模型 / 地址 / Key / 参数 → 素材 → 对话 | 可自定义连接方式 | 首次配置字段太多，不符合只填 DeepSeek Key 的要求 | 不采用；完整设置仅保留为已有独立入口 |

推荐 A。弹窗只完成一件事：保存 DeepSeek Key。申请入口直接指向候选已有的 DeepSeek 开放平台 Key 页面；不在 Dramatis 内代填外部注册或充值信息。保留低强调的“稍后配置”，使用户仍可整理素材或使用既有网页版转接；这是本设计对“非常推荐”的处理，不把无 Key 功能删除或改成永久封锁。同一次访问中主动跳过后不重复自动弹窗；下次打开仍未配置时再次提醒。

暂不做导览遮罩、七步教程、功能介绍轮播、强制注册 Dramatis 账户、偏好问卷或安装弹窗。空白世界仍可用于整理素材与世界管理；首次“开始对话”的快捷路径要求至少一个可回应角色。

```text
配置 DeepSeek API Key

API Key

[保存并继续]                       稍后配置
```

默认输入类型为密码，可有一个显示 / 隐藏图标；自动聚焦 Key 输入框。申请链接为 `https://platform.deepseek.com/api_keys`，在新标签页打开，回到 Dramatis 后保留当前弹窗和输入。不展示模型名、接口地址、服务商选择、配置名称、温度、上下文、用途、价格、保存方式或高级开关。也不额外要求世界、角色或身份字段。

弹窗底部只保留必要的数据范围和费用信息，不放 API 概念解释、优势介绍或“申请很简单”等劝说长文。上述本机明文句用于全新用户的既有默认保存方式；已有账户使用会话 / 加密模式时必须改为对应事实，且不在此弹窗改保存模式。高级设置不放在这个弹窗中。

## 4. 推荐完整路径与状态

### 4.1 默认主流程

```text
打开应用
  → 等待本机配置及 Key 读取完成
  ├─ 已有可用 Key：直接进入原对话或角色首屏
  ├─ 确认未配置 Key：DeepSeek Key 弹窗〔只输入 Key〕
  │    ├─ 保存并继续：保存确认 → 角色首屏 / 返回原对话
  │    └─ 稍后配置：进入角色首屏 / 原对话，保留网页版转接
  └─ 读取失败或密钥库未解锁：读取 / 解锁恢复入口，不当成未配置

首次空库完成上述步骤后
  → 预选一个示例角色
  → 开始对话（创建世界、首条对话、场景；保存成功后进入）
  → 输入第一句话 → 发送 → 生成 → 保存回复 → 继续聊天

主动稍后配置的无 Key 分支
  → 输入第一句话 → 准备转接
  → 复制提示词 → 打开 DeepSeek 网页版 → 用户粘贴并获得回复
  → 回到 Dramatis，粘贴回复 → 添加回复
  → 如有下一位角色，继续同一步骤
  → 更新记忆〔可选〕或跳过记忆 → 继续聊天
```

外部网页版是否登录、是否有可用额度由外部服务决定；不写“免费体验”“无需账户”或“立即收到回复”。接口和网页版两条路都需获得真实回复后才算完成首次体验。

### 4.3 手写与辅助起草分支

“新建角色”打开精简表单：名字〔必填〕、角色设定〔描述，建议填写〕。性格、昵称、立绘、作者、版本、标签放在“更多字段”，字段仍保留可编辑，沿用现有保存确认。角色可只填名字，空设定不应被无依据的规则拦截。

主按钮“保存并开始对话”，保存成功后使用此卡建世界 / 场景并进入输入框。如果卡已保存、建世界失败，提示“角色已保存，对话创建失败”，重试后半步；不再新建卡。按钮等待真实保存；当前自动保存编辑器的已保存数据不能在关闭时伪称全部撤销。

“辅助起草”保留在“新建角色”的次级入口和“世界管理”内。占位文本“描述角色或世界设定”，可展开一个具体例子“酒馆老板，话少，知道旧城的往事。”。有 Key 则生成草稿，无 Key 则使用既有 admin 转接：复制提示词 → 用户在网页版生成 → 粘回完整回复〔含 JSON〕 → 解析草稿 → 采纳。采纳后明确显示“加入场景并开始对话”〔卡〕、“加到当前世界”〔书〕，场景应用按原来源守卫执行；删除身份仍需确认。

辅助起草会调用模型，不设置为默认体验必经之路。草稿的整本覆盖、过期、撤回删除影响和费用信息保留；不把“生成完成”误当作已采纳。

### 4.4 DeepSeek 极简配置与原设置

首次自动弹窗和聊天中的“配置 DeepSeek Key”使用同一个极简界面，只有 API Key 一个输入框。用户不输入或选择其他配置；模型与接口地址使用候选现有 DeepSeek 默认配置，保存方式沿用当前账户设置。弹窗无“高级设置”“测试连接”或服务商切换入口。现有独立“设置 → 模型配置”仍供用户主动管理旧配置，不作为首次配置必经路径。

参数处理仅是设计约束：全新用户复用候选的 `DEFAULT_PROFILE`，当前地址 `https://api.deepseek.com`、模型 `deepseek-flash`、用途 `main`；这些值不显示为可编辑字段，不在此任务中更换模型。已有正常 DeepSeek 配置不因弹窗重置参数。已有其他服务商的可用 Key 直接使用，不能强制替换；若当前确认缺 Key 且用户选择保存 DeepSeek Key，应绑定独立的 DeepSeek 配置，保留原配置和凭据，绝不能把此 Key 写入其他服务商的配置。不要按模糊名称或“当前 active”猜测保存目标。

主按钮“保存并继续”。字段空值禁用；只做本地校验，不用付费请求验证。保存期间禁止重复提交，失败保留输入；`commitConfig` 后段失败可能已有本机写入，必须先核对哪个步骤已完成，不再新增一份配置或让用户从零重填。绑定账户与配置发生变化时不把旧草稿提交到新目标。保存及同一目标 Key 读取均确认后关闭弹窗，返回原页面；没有自动发送草稿的副作用。结果只报“Key 已保存”，不报“连接成功”。

本次首次弹窗不改变密钥保存策略。全新用户沿用当前本机明文保存默认，邻近显示“Key 明文保存在本机浏览器”；已有会话模式显示“Key 仅用于本次会话”。加密模式未解锁先走现有独立解锁入口；不要为减少字段悄悄改为明文，也不要在同一个极简弹窗增加口令或保存模式选择。详情仍可说明同步密文和网页控制者的读取能力，但默认弹窗不堆解释。

已有加密库解锁后，极简窗只更新 Key，复用当前已解锁的密钥存储及其既有就绪守卫，不再次要求口令。当前完整 `commitConfig` 在加密模式仍要求 `vaultPassphrase`，不能直接把它套到这个单字段窗；应使用既有仅更新 Key 的保存路径，等待其同步凭据处理完成并核对目标，参数与模式保持不变。若加密库尚未创建或不能解锁，返回独立恢复 / 完整设置入口，不悄悄创建明文库，也不在 Key 窗内增加密码字段。此处仅明确后续接线约束，不改加密策略。

真实接入由第一条用户主动发送的消息验证：DeepSeek 鉴权失败显示“Key 无效或不可用，请核对后重试”，重新打开同一 DeepSeek Key 弹窗；已有其他服务商配置失败则返回该服务商的既有配置入口，不强制转成 DeepSeek。DeepSeek 额度不足显示“DeepSeek 额度不足，请到开放平台查看”，不冒充保存失败；网络失败保留消息与已存 Key，允许重试，不要求申请新 Key。所有停止、失败及未知用量的费用提示沿用既有规则。保存 / 申请阶段不触发模型调用。

本地无鉴权接口目前提示与 `needsWebBridge` 判断不一致，仍作为既有高级配置问题记录；不承诺空 Key 本地直连，也不借此首次弹窗改接入规则。用户主动“稍后配置”后保留原网页版桥接路径。

### 4.5 返回、重开与移动端

- 有现成世界 / 对话且已有可用 Key 的用户直接恢复工作台，不强制再选示例，不自动新增演示世界。没有 Key 的已有用户同样先收到极简配置弹窗，但保存后返回原对话，不进入新用户角色选择。
- 自动提示在每次打开应用、切换账户或当前配置从有 Key 变为确认缺 Key 时判断；同一账户与配置在本次访问中主动“稍后配置”后，不因重新渲染、切换对话或打开素材库反复弹窗。下次打开仍缺 Key 时再提醒；输入旁始终可主动重新配置。读取失败、未读取及未解锁不算确认缺 Key。
- 有未完成桥接、保存操作或恢复码守卫时，先处理现有进度，Key 提示排队显示，不叠加弹窗、不自动放弃回合、不影响恢复码保存。极简窗的 Esc / 关闭按“稍后配置”处理；已有未保存输入仍通过现有放弃守卫确认。
- 每一步都能返回之前的选择；同一任务内保留输入和选人。现有聊天 / 预算草稿仅在内存中，本轮不承诺关页或重开仍保留；离开页面前有未保存内容时按现有守卫处理。
- 合法待接回复按现有账户、世界、对话、场景与进度恢复；旧或不匹配来源拒绝后给“回原账户 / 原对话”或“放弃并重新准备”，不降低来源核验。
- 手机首屏主操作在中心内容区，不要求先打开左栏。首轮聊天默认不展开两侧面板；状态短句、按钮和错误要靠近输入区，不能只靠 hover。
- 桌面保留 Enter 发送 / Shift+Enter 换行，粗指针设备 Enter 换行；快捷键放在输入帮助或 tooltip，不写进占位文本。图标的可访问名称保留。

## 8. 后续实施分组及设计验收

## 9. 已明确的取舍与未作出的承诺

推荐首先配置 DeepSeek Key，仅一个输入框。保存并确认可读取后，再用一个静态示例角色开始；其他模型配置字段不进入首次弹窗。角色设定及元数据逐步展开。此处“一名”是示例卡选择，不改全局最多回复人数的既有默认值，也不改默认对话模式。主动“稍后配置”时保留现有无 Key 路径，但不将其作为推荐默认。

本文不承诺真实模型输出、首轮耗时或费用，不把 API Key 保存成功解释为接口接入成功，不把内置立绘解释为已有角色预设。涉及删除相关记录、卡片编辑影响、世界书目标匹配、账户身份作用范围的文字以实际处理器为准，实施前针对相关调用点验收，不借文案补做底层裁定。

最终建议先评审第 3–4 节的主流程，再评审第 5–7 节文案；确定后再另行形成实施任务。历史 UI 优化报告保留，本文件独立新增。
