## 一、马上要做（P1 收尾：记忆质量）

### ✅ T1 动作分段能用了（换了一条路：让模型守它已经在守的约定）

- [x] 现状确认：真实模型 12 回合里只有约 2 条消息按 `#` 分隔动作
- [x] 逐个试过并全部失败：系统规则、正反例、每轮提醒、现场示范块（可丢弃）、
      把角色卡自带的风格示例归一化、连「动作用 `*星号*`」都放开——**模型就是不加标记**
- [x] 转折点：它有一点极稳定——**对白永远带「」引号**。于是把约定反过来：
      **引号内是对白，引号外是动作**。渲染层在「这条消息用过引号」时启用，没引号就保持原样；
      `#` 仍然支持且优先
- [x] 在**已有消息**上直接验证（不需要重新生成）：动作落到气泡外，对白留在气泡里
- **来源**：EVAL.md 第二轮的遵守率统计
- **验收**：小满/秦娘的回复在真机上呈现「斜体动作 + 气泡对白」交替 ✅
- **副产品**：规则文本一度把预算撑爆——例子必须放进**可丢弃**的格式块，
  不可丢弃的系统块只留一行规则

### ✅ T2 发言调度 v2：意图先行（T2a/T2b/T2c 三块全部交付）

**T2a 规则信号（已交付）**

- [x] 「说给上一个人听」：出现「你 / 您」且没有「你们 / 各位 / 大家」时，给上一位延续
      加成并免掉冷却；问全场时照旧轮换（真机复验：不带名字追问仍由同一个人接话）
- [x] 「开口就叫了他」：句首称呼单独识别（+60 且免冷却），一句里提到两个人也不会被抢走话头
- [x] **只做动作、一个字没说的那一轮不再算「发言」**，不吃冷却
      （判据是正文里有没有引号，而不是渲染规则怎么显示——渲染为了兼容会把无引号的行
      也当对白，那样纯动作的一轮会被误判成「说了话」）

**T2b 意图（零额外调用版，已交付一半）**

- [x] 解析与存储：模型若按格式写「意图：…」，这一行单独存进消息、正文里不留
      （留在正文就会进历史，被下一轮学成正文的一部分）
- [x] 界面显示：气泡上方一行「想做：…」，每次渲染重算、不缓存
- [x] 调度用上它：角色自己说过「我在旁边看着」时，下一轮让一让（可解释的加减分）
- [x] **推理流当盘算**：模型没声明、但返回了推理流时，取首句作为「盘算：…」
      ——那是它真实在想的事，只是不是我们要的格式。零额外调用
- [x] 真机测过遵守率：**0/4**。DeepSeek 对「意图：」这种标签指令与 `#` 一样不理
      （T1 的教训：不要要求它做它不肯做的事），所以主力走推理流那条路

**T2c 真正的「生成前意图」（已交付）**

- [x] 生成之前用便宜模型问一句「此刻想做什么」，据此决定插话 / 抢话 / 欲言又止 / 主动发起
      （四种 mode：`reply` / `cut_in` / `hold_back` / `initiate`，`director/intent-plan.ts`）
- [x] **钱从哪来**：把记忆抽取与情绪推演**合并成一次后台调用**
      （`memory/turn-analysis.ts`，两者本来吃同一批消息、同一批在场角色）。
      账从「1 生成 + 2 后台」变成「1 生成 + 1 意图 + 1 合并后台」，
      **每回合额外调用仍是 2 次**
- [x] **意图是建议不是命令**：名字对不上在场角色、`presence` 不是 `onstage`、
      `hold_back`——任何一条都丢弃并退回规则调度；调用或解析失败一律静默退回
- [x] 风险已按流程处理：抽取与推演的提示词都经过真模型验证，合并动了已验证的部分，
      已重跑一轮（EVAL 第六轮），抽取与推演照常落地
- [x] 意图落进消息（`intentSource: 'planned'`）与生成提示词，界面上用「他这一轮想：」标出；
      会话模式新增「意图先行」开关，关掉即退回纯规则调度（额外调用降到 1 次）
- **证据**：三轮真机——陈九「先不急着辩解，反问玩家在怀疑什么」、小满「不得不表态但不卖人」、
      陈九「上火想顶回去」，三处回复都照着自己的打算落笔；计数印证每回合多出的那一次
      确实被算进「额外调用」

- **验收**：连续追问同一人 5 次，4 次以上由同一人接话 ✅；三角色同场不抢话 ✅；
  意图在界面上可见 ✅（声明式在本模型上不成立、推理流只在推理模型上有——两条已记录原因）

## 四、优化项（真实使用中发现的具体问题）

### 🔜 T17 换场时选择「这次带谁去」

### ✅ T17 换场时选择「这次带谁去」 + T10 名单与存在状态对齐

**这两条一起做了**：它们是同一个问题——「谁在这一场里」。

- [x] 换场对话框里新增「这次带谁走」：列出此刻在场的人，默认全选，可逐个取消
- [x] 留下的自动转「在幕后」（`offscreen`），不再被调度、不再进 prompt 的在场名单
- [x] 旁白只记跟着走的人（原来是「秦娘、小满 与 陈九 进入了…」，现在只写实际同行的）
- [x] **内核定下规则：名单是权威，presence 跟着名单走**（`session/presence.ts`）。
      在名单里 → 幕后者转在场（沉默保持沉默、明确离场过的不复活）；
      不在名单里 → 在场/沉默者转幕后
- [x] 同步发生在三个入口：换场、切换对话、新建对话（否则又会出现
      「右栏说在场、这条线的名单里却没有他」的角色）
- **来源**：五十回合长跑（秦娘说要留下看店，却被换场一起带走，随后站在货栈门口发言）
- **验收**：真机验证通过——取消勾选陈九后换场，旁白只写「小满 进入了 河滩旧道」，
      陈九自动变「在场外」，秦娘保持在场外，场景名切到新场

### 🟡 T18 语音归属错位（检测 + 一键改归属已交付，误报率已压到可用）

- [x] **检测**：`render/attribution.ts`，纯规则、不调模型（单回合额外调用 ≤ 2 的约束不破）。
      判据收紧到一条硬信号：**同一个句子里既是第一人称、又用自己的名字称呼自己**
      ——「我看了看小满」（他就是小满）、「你跟陈九说」（他就是陈九）
- [x] **误报率**：第一版还加了「第一人称句子里出现别人的名字」，在真实长跑数据上
      报出 **21 条**警告（「我认得小满」这类正常台词大量中招）；收紧后是 **2 条**，
      且两条都是真错位。宁可漏也不要让用户学会无视警告
- [x] **一键改归属**：任何角色消息都能改（不只可疑的），选择框就在消息操作行里；
      改完会**重算这一轮的后台写入**（清队列记录 → 撤销记忆与情绪变化 → 重新排队），
      因为「谁说的」直接决定抽取出的视角记忆
- [x] 真机验证：长跑里两条错位都标了出来，一键改成正确说话人后警告消失、
      内容读起来也顺了（「我拿书角往柱子指了指」回到小满名下）；后台重算在跑
- [ ] **仍测不到的一类**：靠道具词才能看出的错位（「秦娘」那条其实写的是小满的书角）。
      加关键词规则会把正常台词也标成可疑，所以**故意不做**，由「任何消息都能改归属」兜住。
      单测里专门留了一条用例记录这个限制
- [ ] 更根本的解法仍然在模型侧：提示词已写明「不要替别人写」，但 8% 的错位是模型行为，
      靠规则只能事后发现

## 六、建议顺序

```
T1 格式遵守率  →  T2 意图先行调度  →  T4 五十回合长跑  →  T7 成本统计完整化
                      ↓                    ↓
              T10 语义统一（可并行）   T3 分层摘要 / T5 向量召回（由长跑结论决定）
```

理由：T1 与 T2 直接影响「读起来像不像真人在群里说话」，是当前最明显的体验缺口；
T4 是唯一能给 T3/T5 提供决策依据的动作，而它现在只差人工时间与调用预算；
T7 跟着 T4 一起做，成本数据是同一批调用里顺手就能记下来的。
