## 一、马上要做（P1 收尾：记忆质量）

### 🔜 T1 提高动作 `#` 约定的遵守率

- [ ] 现状：真实模型 12 回合里只有约 2 条消息完全按 `#` 分隔动作，其余把动作写成普通句子
- [ ] 尝试：把格式要求做成独立的、非降级的 system 区块（现在混在「基本规则」里）
- [ ] 尝试：给一个正反例（「对：`# 她放下杯子`」/「错：她放下杯子。」）——真实模型的教训是
      **规则太长会被忽略，例子更管用**
- [ ] 兜底：评估「没有 `#` 时按句式猜动作」是否值得——**倾向不做**，猜错比不猜更糟
- **来源**：EVAL.md 第二轮的遵守率统计
- **验收**：同一份 12 回合脚本重跑，遵守率 > 70%
- **成本**：1 次真实模型验证（约 40 次调用）

### 🔜 T2 P1-6 发言调度 v2：意图先行

- [ ] 生成对白前先产出「此刻想做什么」的意图（便宜模型或规则）
- [ ] 用意图决定「谁接话、以什么方式接」（插话 / 抢话 / 欲言又止 / 主动发起）
- [ ] **把「追问延续」作为信号**：玩家用「你还记得吗」追问刚说过话的人时，v1 会因冷却换人
      （真实使用中踩到），v2 应把「上一条是我的」当加分项
- **来源**：ROADMAP P1-6 + 端到端测试观察
- **验收**：连续追问同一人 5 次，4 次以上由同一人接话；三角色同场时不再出现抢话
- **依赖**：T1（意图先行会顺带缓解格式问题）

### T3 P1-5 分层摘要与压缩流水线 ⬜

- [ ] 轮 → 场景 → 章节三层摘要，触发条件为轮数或上下文占用阈值
- [ ] 被压出窗口的原文永不删除，随时可展开回想
- [ ] 遗忘机制：低重要度且长期未被回想的记忆降权，可合并为粗粒度印象
- **来源**：ROADMAP P1-5
- **依赖**：需要先有 50 回合长跑数据（见 T5）来判断压缩阈值

## 四、优化项（真实使用中发现的具体问题）

### 🔜 T10 presence 与「在不在这场戏里」的语义统一

- [ ] 现状：`presence` 是实例级（世界的），场景名单是场景级。两者不一致时会出现
      「presence 是在场、但不在名单里」的角色。已在内核用名单兜住（调度器不再让他上台），
      但界面上仍然会让人困惑：右栏显示「在场」，他却接不了话
- [ ] 方案候选：把 presence 改成对话级（每条对话各自记录谁能说话），或者界面上直接
      以名单为准显示「本场在场 / 不在本场」
- [ ] 先写一页设计决定，再动手——这是模型层的改动，代价与收益要摆出来
- **来源**：端到端测试 + 归档之后真机踩到

### T11 记忆面板的对话维度

- [ ] 记忆是世界的，但对话是多条的：面板现在混着显示，看不出「这条记忆是哪条线里的」
- [ ] 加按对话筛选；客观条目与视角条目的对照视图
- [ ] 「点回当时的对话」——记忆条目跳到它产生的原句
- **来源**：ROADMAP P1-4 的原始要求（时间线视图 + 出处）在改版后还没补全

### T12 归档的可发现性与撤销

- [ ] 归档后只出现在设置里，用户容易以为数据丢了 → 归档后给一次明显提示与入口
- [ ] 是否提供「取消归档」：现在刻意不提供（语义是「这条线没有发生过」），
      但至少要能导出归档对话的正文
- **来源**：LAYOUT 取舍第 3 条 + 真机使用

### T13 世界管理员的工具体验

- [ ] 草稿卡片显示更完整的预览（现在是标题 + 摘要），至少能看到开场白
- [ ] 采纳后提供「撤回」的短期窗口（采纳是写库，误点成本高）
- [ ] `upsert_world_book` 整本替换的语义要在界面上说清：建议显示「原有 N 条 → 现在 M 条」
- **来源**：端到端测试里管理员一次改了 3 条设定的实际体验

### T14 世界视图蓝图（顶栏预留位）🧊

- **触发条件**：至少有一个世界跑到 50 回合、角色超过 5 个——否则图上看不出东西
- [ ] 以节点网络显示角色、物品、事件之间的联系（顶栏已经为它留空）

## 六、建议顺序

```
T1 格式遵守率  →  T2 意图先行调度  →  T4 五十回合长跑  →  T7 成本统计完整化
                      ↓                    ↓
              T10 语义统一（可并行）   T3 分层摘要 / T5 向量召回（由长跑结论决定）
```

理由：T1 与 T2 直接影响「读起来像不像真人在群里说话」，是当前最明显的体验缺口；
T4 是唯一能给 T3/T5 提供决策依据的动作，而它现在只差人工时间与调用预算；
T7 跟着 T4 一起做，成本数据是同一批调用里顺手就能记下来的。
