# Dramatis 界面视觉优化方案书（待审批）

日期：2026-09-27  
状态：视觉方向 A 已获认可；图标与微动效范围补充待审阅，产品界面尚未修改

## 1. 项目目标与调研范围

Dramatis 的核心体验是进入一条世界线，阅读多角色对话，并像导演一样管理场景与阵容。本次优化要让阅读更沉浸、操作更清楚、整体更精致，同时保留现有功能及已确定的交互方式。

调研覆盖 `docs/` 的产品、布局、状态、任务、平台与评测文档，并检索了仓库中的 TypeScript、TSX、CSS 和工具代码。重点核对了 `apps/web/src/App.tsx`、约 2,835 行的 `styles.css`、主对话和副对话组件、角色栏、设置弹窗、外观偏好，以及桌面与手机端布局。文档以 `docs/LAYOUT.md` 的现行交互决定和 `docs/STATUS.md` 的最新状态为边界。

本方案是代码与文档审阅后的设计判断。尝试启动本地 Vite 预览时，现有 `node_modules` 内的 Vite 文件被环境以 `EPERM` 拒绝读取，因此本轮没有把实时截图或用户实测冒充为证据。执行前应补一组真实界面截图，校准细节。

## 2. 现状诊断

| 观察 | 依据 | 对观感的影响 |
| --- | --- | --- |
| 页面以相近的实底色、边框和圆角反复划分区域 | `styles.css` 的 `.topbar`、`.panel`、`.main-header`、`.chat-surface`、`.left-rail` | 内容与工具区的主次不够鲜明，桌面端容易呈现“多张盒子并排”的感觉 |
| 字级主要围绕 14px 正文与 12px 辅助文字 | `body`、`.hint`、`.tab`、角色标签等样式 | 长文阅读、标题定位、次要提示之间的层级不足；高密度设置页尤其明显 |
| 酒馆主题已有暖棕与金色基调，浅色/深色主题改为蓝色，但组件状态仍主要共享一套简单变量 | `:root`、`html[data-theme]`、`lib/appearance.ts` | 主题是换色，尚未形成跨主题一致的材质、层级与状态系统 |
| 角色立绘、头像资产丰富，聊天中的角色身份仍主要依赖头像与姓名 | `public/portraits/`、`MessageItem.tsx`、`CastRail.tsx` | 可以更好地用人物识别与节奏强化“多角色同场”，无需增加功能 |
| 控件样式分布在一份较长的 CSS 中，局部规则和手机端覆写较多 | `styles.css`、多个组件的 `className` | 视觉细节难以统一；贸然全局改 CSS 容易引起跨页面回归 |
| 共用 SVG 只有加号、场景、发送、停止、手机菜单 5 种，其他入口仍混用字符符号 | `components/Icons.tsx`、`TopBar.tsx`、`WorldTree.tsx` 等 | 不同平台字形和笔画不一致，图标状态也缺少连续反馈 |

已有亮点应继续保留：手机端对话铺满屏幕、顶栏覆盖、左右抽屉推开对话、输入草稿和流式消息不卸载；桌面端的世界/对话树、角色拖入场景；动作离开气泡、主副对话显示方式不同；三套主题与自定义聊天背景。

## 3. 设计方向选择

| 方向 | 视觉特征 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A. 叙事剧场（推荐）** | 深暖中性色、克制的黄铜强调、柔和层次、人物内容为主角 | 与“登场”“导演”“世界线”产品语义相符，延续当前酒馆主题与角色资产 | 需仔细控制暗色对比度，避免装饰感影响阅读 |
| B. 轻量阅读器 | 中性浅底、大留白、冷色少量强调 | 阅读门槛低，适合长时间使用 | 品牌辨识度弱，与现有酒馆基调距离较大 |
| C. 未来控制台 | 深色、冷色高亮、密集仪表盘 | 导演与系统能力显得强 | 容易压过剧情内容，也会放大设置复杂度 |

建议采用 A 作为默认酒馆主题的深化方向。浅色与深色主题保持可用，并沿用同一层级、间距、字级和组件状态规则；它们不需要复制暖金配色。

## 4. 推荐方案：叙事剧场

### 4.1 视觉原则

1. **对话先于工具。** 主阅读区拥有最平静的背景与最宽松的节奏；顶栏、边栏和运行时面板退居次级。
2. **角色先于装饰。** 头像、姓名、在场状态构成识别线索；避免大面积纹理、发光边框或无意义动效。
3. **少量高质量强调。** 金色只用于当前选择、关键动作和少数提示；危险操作保留独立色彩。
4. **长读舒适。** 正文字级、行高、每行宽度和段落间距优先于单屏塞入更多内容。
5. **三主题同构。** 布局与组件状态一致，色彩分别校准，不增加用户学习成本。

### 4.2 设计系统草案

以下是进入实现阶段的起始标尺，最终数值以桌面和手机截图审阅为准。

| 设计项 | 建议 |
| --- | --- |
| 字级 | 正文 15–16px；辅助 13–14px；区块标题 16–18px；世界/对话主标题 18–22px。保留高密度表格的例外，但不以 11–12px 承担重要信息。 |
| 阅读排版 | 正文行高约 1.65–1.8；消息正文可读宽度约 65–78 个汉字的视觉量级；动作/旁白与对白用排版区分，不只靠颜色。 |
| 间距 | 以 4/8/12/16/24/32px 为基础节奏，统一面板内边距、表单组距、消息纵距。 |
| 圆角 | 输入框和主要弹窗适度柔和；列表项、标签更克制。避免所有层级都使用相同圆角与完整边框。 |
| 层级 | 使用底色差、细分隔线与少量阴影建立 3 级表面；主聊天面尽量减少“套盒子”感。 |
| 状态 | hover、focus-visible、pressed、selected、disabled、error、success 形成完整规则；触屏上维持可识别的常驻状态。 |
| 动效 | 用于有状态变化的控件、抽屉、菜单和操作反馈；保持现有 240ms 抽屉节奏并尊重 `prefers-reduced-motion`。 |

颜色不建议在方案阶段直接锁死全部十六进制值。先建立语义令牌：画布、阅读面、工具面、悬停面、分隔、主字、辅字、强调、强调底、危险、成功、焦点环。再为酒馆/浅色/深色分别配值，并对带背景图的聊天面设置稳定的文字遮罩策略。

### 4.3 关键界面调整

**桌面主界面。** 保持现有骨架。降低顶栏和边栏的视觉重量，让世界/对话名称成为清楚的定位点。左栏的世界树强化“世界、对话、当前项”三级关系；当前项以底色、字重和细强调标识，避免只靠颜色。角色窄栏突出头像、在场状态和拖入提示，收起或窄窗口时不挤压对话宽度。

**主对话。** 让角色名、头像、对白、动作、系统旁白形成稳定的阅读节奏。角色对话保持气泡，动作继续在气泡外；玩家与角色的对齐和色块差异要足够清楚。流式输出、重抽/编辑菜单和“跳回原句”高亮仍可被快速发现，但不常驻打断阅读。

**副对话。** 保持“无气泡的 AI 工作流”语义。管理员说明、草稿预览、采纳/丢弃动作采用文档式层级和明确的操作区，不套用角色聊天皮肤。

**输入区。** 保持已有圆角输入盒、随内容增长、发送/停止与便捷指令。优化占位文案、焦点环、工具按钮间距和禁用状态。手机端继续保留“回车换行、点按钮发送”，底部安全区不能被遮挡。

**设置与运行时面板。** 将“配置项、解释文字、危险动作、即时状态”做出层级。高频项先见，技术说明可折叠；六大类与运行时页签保持当前入口和保存语义。长表单按小节分组，减少一整页同质卡片连续堆叠。

**空状态与反馈。** 新世界、空对话、没有在场角色、无记忆、导入后等情境给出简洁引导及下一步动作。错误、后台任务、存储无法保存等通知保留真实优先级，避免把警告弱化成装饰标签。

**手机端。** 完全保留 `LAYOUT.md` 已定的全屏对话、覆盖式顶栏、在场角色横滑条、主副切换与左右推开抽屉。优化触摸区、文字大小、弹窗分组和横屏/窄屏溢出；不恢复已删除的手机标题栏。

### 4.4 图标系统与微动效（新增）

图标不只是装饰，应帮助用户辨认操作、理解当前状态。沿用现有 `Icons.tsx` 的内联 SVG、16×16 坐标系、`currentColor` 和描边风格，建立完整图标规范：统一视觉尺寸、描边粗细、端点形状、图形重心和图标与文字的距离。以 SVG 为主，不引入整套外部图标库；已有头像与角色立绘仍承担人物识别。

**优先统一的入口：** 顶栏的桌面左栏开合、世界树的新建/删除/展开、副对话标识、消息操作菜单、设置分类、运行时页签与空状态中的关键动作。纯文本按钮继续保留文字；图标不能代替不清楚的功能名称。删除、归档、停止等高风险或含义易混的操作，仍配文字或可访问名称。

**加号交互样例：** 输入区“对话模式”按钮打开菜单时，加号顺时针旋转 45°，视觉上变为关闭符号；关闭时复位。建议使用图标外层的 `transform`，约 180–220ms 的缓出过渡，避免路径变形和布局跳动。按钮同步显示选中底色，并补 `aria-expanded` 与菜单关联；开、关状态都由现有 `modeMenuOpen` 驱动，不另建动画状态。若用户偏好减少动效，直接切换到终态，不播放旋转。

**微动效清单：**

| 场景 | 建议反馈 | 边界 |
| --- | --- | --- |
| 加号打开/关闭模式菜单 | 图标旋转 45°、底色变化；菜单轻微淡入与上移 | 菜单内容立即可操作，不因动画延迟焦点 |
| 左栏和右侧面板开合 | 保留现有 240ms 位移；图标状态与面板方向一致 | 不改变现有推开对话的 DOM 与交互 |
| 世界树展开/收起 | 小箭头旋转 90°，当前项状态同步 | 不让整棵树发生大幅运动 |
| 按钮提交、保存、同步 | 图标或按钮内部给一次短反馈；加载过程可用稳定的进度指示 | 避免无限旋转或重复闪烁干扰阅读 |
| 消息菜单与提示 | 120–180ms 的轻微显隐 | 不影响右键、长按、键盘操作与菜单定位 |

动画只表达状态或操作结果，不让每条聊天消息持续运动。默认以 `transform` 和 `opacity` 为主，避免尺寸抖动；为 `prefers-reduced-motion: reduce` 提供无动画的即时状态。触屏目标仍至少 44×44px；图标按钮须有 `aria-label`、键盘焦点和足够的主题对比度。

## 6. 验收标准

- **视觉一致性：** 三主题中的字级、间距、状态和组件层级一致；同一操作类型不出现相互矛盾的样式。
- **阅读：** 长消息、连续动作和多人发言能迅速辨别归属；自定义背景下文字仍清楚。
- **响应式：** 至少检查 390px 手机竖屏、手机横屏、约 768px 窄窗、约 1440px 桌面；无水平溢出和重要控件遮挡。
- **可用性：** 高频触控目标至少 44×44px；键盘焦点清楚；抽屉和弹窗遵守现有焦点/退出行为；减少动效偏好有效。
- **图标与动效：** 同类操作使用一致图形；加号、树节点与抽屉开合状态清楚；动画不造成布局跳动、焦点延迟或连续阅读干扰。
- **功能回归：** 世界/对话切换、主副切换、场景与角色操作、流式消息、输入草稿、消息菜单、设置保存和三主题切换正常。
- **工程质量：** `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build` 通过；视觉改动以截图核对，不用仅凭测试通过宣称美观。

## 7. 风险与边界

- 现有手机侧栏位移依赖特定 DOM 与 CSS 关系。调整外壳时必须保留 `.chat-surface` 的位移位置，不能把 `transform` 随意加到 `.workspace`，以免固定定位的右侧面板跑出屏幕。
- 单文件 CSS 覆写较多。先建立令牌和少量组件规则，再逐区迁移；每区改完都检查三个主题与两个主要断点。
- 字符符号换成 SVG 时，保留按钮语义与可访问名称；仅图标按钮不能依赖视觉形状表达唯一含义。微动效不能与现有消息菜单定位或手机抽屉位移叠加出错。
- 视觉优化不改数据模型、提示词、同步协议、消息分段语义或已定交互。若后续发现需要改变流程，应单独提出并审批。
- 不加入新的网页字体、图像依赖或大面积装饰图作为默认方案；现有角色素材已足够支撑身份表达。
