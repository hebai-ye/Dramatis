# Dramatis 全界面优化审查与分阶段实施方案

> 审查：2026-10-11；文档整理：2026-10-12（Asia/Shanghai）。状态：供评审，尚未实施。
>
> **目标：**让本地优先的角色扮演引擎在聊天、素材编辑、记忆诊断、账户同步和管理操作中采用一致的导航、信息层级和反馈规则，先解决会影响操作正确性的缺陷，再改善阅读、编辑和加载体验。
>
> **技术与架构：**pnpm monorepo、React、TypeScript、Vite、IndexedDB；服务器管理台为独立原生 JavaScript 页面。推荐保留现有聊天工作区、素材库工作区及账户/设置分离的结构，复用已经可靠的外壳和状态协调器，按可独立验收的批次推进。
>
> **实施约束：**本文件不是执行授权。实施者应在用户评审后按批次重新核对工作副本、编写窄范围计划并验证；可采用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`。本轮只新增本方案，未修改产品代码、依赖、用户库、既有历史记录，未提交、推送或部署。

## 1. 先读结论

推荐采用“渐进统一”的路线：先收口桥接归属、发送入口和失败保稿，再统一弹窗、窄屏编辑和异步反馈，最后调整视觉层级及加载。当前界面已有三套主题、账户/设置懒加载、素材离开保存协调、聊天保挂载和减少动效支持；这些是可继续使用的基础，不需要整体重做。

本轮最优先的两项新缺陷是：**副对话旧起草可以写入后来切换的世界**，以及**桥接等待期间 Enter 绕过禁用的发送按钮**。其后优先处理发送拒绝仍清空输入、通用弹窗键盘缺口、手机角色详情入口、650px 素材编辑拥挤和数值表单校验。它们与上一轮 UI01–UI10 已修复项不同，具体证据见 §5。

| 路线 | 收益 | 成本与风险 | 建议 |
| --- | --- | --- | --- |
| 渐进统一：可靠交互→布局/反馈→视觉/性能 | 每批能独立复核和回退；复用当前结构 | 短期仍有少量新旧表现并存 | **推荐** |
| 一次性重做应用外壳与全部页面 | 可快速形成统一视觉 | 同时牵动聊天挂载、草稿、同步及焦点，回归面大 | 本阶段不采用 |
| 只调整颜色、圆角和留白 | 修改小、易展示 | 不解决桥接归属、键盘、保存和窄屏操作障碍 | 可作为后续视觉批次，不能替代前两阶段 |

本方案的新编号 `D01–D17` 表示缺陷；`E01–E11` 表示体验改善或验证方向；不复用历史 UI01–UI10 或其他审计中同名 B 编号。P1：数据归属或关键工作流完整性；P2：功能可用性、信息准确性和无障碍；P3：低频改善或工具页。没有根据本轮证据新增 P0。

## 4. 贯穿全项目的设计与交互原则

### 4.1 用任务和对象组织信息

保持三层：**创作主区**（主/副聊天）、**当前世界工具**（场景、阵容、记忆、用量、Prompt）、**全局资料与设备**（素材库、账户、设置）。在实际处理世界数据的面板显示世界/对话范围，在处理模板时显示“模板”；同名世界/角色用稳定归属补充辨识，不用显示名推断身份。

推荐让每页首屏只有一个明确主要动作，次要操作放邻近区域，破坏性动作移到独立末端。默认显示用户完成任务需要的信息，统计/实现细节用可展开的“诊断”区承载。保留用户已裁定的手机顶栏位置、主副单按钮、侧栏推开聊天、无独立全屏按钮和隐藏本场场记安排；改变这些既有规格需另行评审。

### 4.2 交互基于范围和真实结果

所有异步结果绑定账户、世界、对话及操作代次；作用到具体对象的结果再绑定其ID/revision。发送、快捷键和指针采用同一可用性判定。表单保存须返回真实完成结果；失败保留输入；已提交但刷新失败显示“已保存，读取失败”；不确定提交保留核对编号，不能自动重试写入。

推荐共享轻量状态词汇：未更改、待保存、保存中、已保存、保存失败、仅本次会话有效、上次成功读取、结果待核对。不要把 loading 当空数据，也不要以颜色单独表示状态。此原则复用 UI03–UI08 已有模式，不要求每个字段都弹 toast。

### 4.3 统一外壳和焦点规则

账户/设置的 `DialogShell` 已有 portal、背景 inert、初始/返回焦点、Tab环绕、Esc与离开守卫。推荐让通用 `Modal` 复用其底层行为，保留各自标题/正文/页脚；素材工作区及非模态侧栏保持它们自己的导航语义，避免误加全局焦点陷阱。破坏性确认优先聚焦取消；确认关闭后返回触发按钮或逻辑邻项。

依据 [W3C 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)，模态交互需要内部键盘范围、Esc和合理回焦；仅加 `aria-modal` 而背景仍可操作不构成修复。验收包括读屏，不能只检查属性字符串。

### 4.4 按可用宽度组织布局

推荐组件依据工作区宽度收列，避免只有640px全局断点。素材详情可用宽度不足时切列表/详情；表单窄时单列，长ID/金额允许换行；表格可在容器内横滚并保持行/列对应，页面不横向滚动。弹窗短屏固定标题/关闭入口、正文独立滚动，考虑 visualViewport、软键盘及安全区。

验收基线采用 [WCAG Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) 的320 CSS像素场景，另验340/390/650/800/900/1280/1440及横屏。聊天、素材表单等无需二维布局的内容不依赖横滚；账本表格例外仍须让操作可达。

### 4.5 延续主题，建立可维护的视觉尺度

当前 `styles.css:1` 已有背景/面板/线条/文本/强调/危险/焦点等变量及三套主题。推荐先补语义 token（成功、警告、禁用、选中、输入背景、浮层）和间距/字号尺度，再逐个组件替换。基础文字保持当前15px，重要说明建议13–14px；10–11px仅用于非关键元数据且可放大。间距建议4/8/12/16/24px，圆角沿用现有10px为主；这是候选设计值，需三主题样本评审后冻结。

管理台可共享同名语义token与字号/状态约定，不要求引入React或完整组件库。正文/错误/已选/禁用均做实际对比度检查；普通文字4.5:1、大字3:1、控件与焦点3:1作为验收目标，不能凭深浅主题截图宣称合规。

重要触屏入口建议44×44px；这是本项目的体验目标，不等同WCAG最低值。 [W3C Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) 的AA最低值为24×24px并有间距等例外；细密角色条可保留视觉小图，但扩大透明点击区或给等价的大入口。

### 4.6 动效表达状态，不代替结果

保留现有160ms快速、220ms一般和240ms抽屉节奏；仅在导航/展开的空间关系有帮助时使用，错误/保存结果立即出现。不得用完成动画遮掩未落盘。系统减少动效时停止非必要位移/循环/滚动动画，保留静态进度文本和定位高亮；每次动作读取偏好，覆盖运行中偏好变化。UI10已修部分要纳入回归，而不是再次列为缺陷。

### 4.7 用量、权益和数据安全可解释

客户端自带Key的估算账单、逐币种预算和管理托管账本分别清楚标范围与来源。未知usage不能表达为免费；金额不同币种不合并；预算仅限制当前已裁定的后台调用。管理页面保留“预览→核对→完整句柄→备份保存”的顺序，显示操作号但不展示确认票据、Key或正文。权益、余额和预留解释可以更简洁，生产政策必须保持已裁定规则。

## 5. 新缺陷清单与推荐实施设计

每项验收都需保留本轮反例。下列文件修改是**建议范围**，不是本轮已经修改。

### D01 / P1：副对话起草缺少来源归属保护（S＋R）

**问题与影响：**`lib/admin.ts:122` 的桥接只保存prompt；`commitBridge:386`从当前session取world/conversation，`:415`执行草稿，`:436`把管理员输出追加到当前副对话。场景工具直接调用当前世界更新。R实测：在A准备2571字提示，创建B并进入副对话，旧桥接仍出现；收下合成 `set_scene` JSON后，B地点变为合成标记。用户可能把旧世界起草写入另一个世界，属于数据归属问题。

**推荐：**准备时记录账户/world/conversation/scene及生成所依据的数据版本；提示阶段显示来源名称；应用前核验来源和当前目标，迟到/切线结果不得改当前世界。切线后保留“回到来源继续/放弃”二选一，或只允许来源页收下。备选是切线立即清空桥接，实现更小，但用户会失去未完成转贴；需要明确告知和恢复路径。

**涉及/依赖：**`lib/admin.ts`、`SideChat.tsx`、`App.tsx`、`WebBridgePanel.tsx`；复用主分析现有归属保护思想。不得借此确定A08重贴记忆策略。

**验收：**A→B、同世界不同副对话、账户切换、等待解析期间切线、旧请求迟到分别拒绝跨目标写入；原来源可继续；失败保留粘贴文本；合法同目标工具仍成功。至少有受控hook/事务回归与两合成世界生产浏览器验收。

**兼容/回滚：**优先使用内存临时来源状态，无schema迁移；若持久化则新记录带版本，旧无来源记录明确拒绝/重新准备，不能自动绑定当前世界。回退会重新开放跨世界风险，不能作为常规兼容模式。

### D02 / P1：桥接等待时 Enter 绕过发送禁用（S＋R）

**证据：**`Composer.tsx:64`键盘仅检查组合输入/Shift/粗指针，按钮`:90`却检查bridgeOpen；`MainChat.tsx:552`、`SideChat.tsx:253`和下游发送路径没有同等桥接守卫。R副对话等待时按Enter，第二玩家消息被追加，旧提示2533→2571字。

**推荐/取舍：**统一 `canSubmit` 判定，并在业务发送入口再检查等待状态；保留显式放弃后再发送的既有流程。备选禁用整个textarea会阻止用户准备下一句，不推荐。不得只改键盘处理而留程序调用旁路。

**文件/依赖：**`Composer.tsx`、`MainChat.tsx`、`SideChat.tsx`、`useTurnRunner.ts`、`lib/admin.ts`；可与D01同阶段，分别验收。

**验收/兼容：**reply、analysis、admin三阶段的按钮/Enter/直接发送均一致；阻止时文本保留，无新消息和提示替换；Shift+Enter、IME确认仍正确。无迁移，回滚仅代码，但会恢复绕过风险。

### D03 / P2：发送前拒绝仍清空主输入（S＋R）

**证据/影响：**`MainChat.tsx:552`调用void onSend后无条件setInput空；runner在无角色、无效点名/点名数量不符时先return。R空角色场景发送合成文字，只出现左栏错误，输入清空，未新增玩家消息。左栏收起时错误还可能不在当前视野。

**推荐：**发送入口返回明确接受结果，采用 `Promise<{ status: 'accepted' | 'rejected' | 'uncertain'; reason?: string }>`；接收时点与整轮模型完成分开。自动模式以该玩家输入成功落盘为接受点；手动模式以带固定来源的pendingTurn成功准备、其恢复状态保存完成为接受点，此时玩家消息尚可等待收下回复后落盘。准备或恢复状态保存失败且能确认未提交时返回rejected；提交结果未知返回uncertain，保留输入并提示先核对，不自动再次发送。提交时捕获账户/对话ID、文本及草稿修订号，仅当返回accepted时这些仍对应同一份输入，才清该稿；晚返回不得清用户后来输入或新对话的稿。已确认提交但后续回读失败仍是accepted，另显示读取失败，不伪装成未发送。拒绝在输入区显示关联错误并保留选择/焦点。备选发送前镜像所有业务校验容易漂移，仅作即时提示，下游仍须判定。

**文件/依赖：**`MainChat.tsx`、`Composer.tsx`、`App.tsx`、`hooks/useTurnRunner.ts`，先完成D02的统一守卫。副输入也采用同样约定。

**验收/迁移：**无角色、无效@、归档、忙态、确定未提交的持久失败保稿；慢接受期间继续输入或切线，迟到接受不清新稿；手动准备失败不清稿，准备成功不等网页回复结束才回传接受；已提交后回读失败仍标已发送，提交未知先核对，网络失败不重复自动发送；窄屏左栏关闭仍可见错误。无库迁移，回滚仅发送结果/输入策略。

### D04 / P2：通用弹窗缺少完整模态键盘行为（S＋R）

**证据：**`Modal.tsx:26–43`没有初始/返回焦点、Esc、Tab环绕、inert或aria-modal。R新对话打开焦点仍在背景按钮，inert=0、aria-modal为空；开始上Esc不关闭，Tab离开dialog。影响新对话、场景和角色详情；账户/设置已有正确基础，不重做。

**验收/迁移：**三弹窗全部初始焦点、正反Tab、IME中的Esc、正常Esc、取消回焦、来源按钮消失时逻辑回焦、背景不可操作、短屏关闭可达；读屏可辨标题。无迁移；逐调用方可回退，但不能只留aria-modal属性。

### D07 / P2：跳原句请求未结束，持续阻止自动跟随（S）

**文件/验收：**`App.tsx`、`MainChat.tsx`、`StreamingBubble.tsx`；测试定位→阅读→回底→新chunk、目标不存在、切线、素材打开、减少动效动态变化。保留UI10；无schema迁移，回退局部滚动策略。

**文件/验收：**`App.tsx`、runner设置prompt处、`PromptInspector.tsx`；两世界/同名对话/多角色/失败准备/切线迟到；来源和实际数据匹配。仅内存元数据，无prompt正文持久化或迁移；回退展示可独立进行。

## 8. 加载与运行性能方案

### 8.1 当前量化事实

当前已有产物直接核对：入口`index-CTA_4dUz.js`500635B（构建展示500.63kB，历史gzip161.78kB）；HTML明确预载6个JS，入口＋预载合计**681023B（681.02kB）**；SW清单24份JS/CSS合计**847436B（847.44kB）**。这些是文件字节，不是本轮网络传输、首屏纯执行时间或总离线包大小；图标/立绘等未计入。不能只靠入口跌到500kB以下宣布首屏性能改善。

### 10.1 文件职责与接口建议

- `DialogShell/Modal/dialog-controller`负责关闭/焦点/守卫；业务表单返回其dirty/busy，避免每页再造一套Esc逻辑。
- `Composer`统一输入和键盘，主/副发送返回接受结果；runner/admin负责来源和业务可用性，UI禁用只负责表达。接受时点及清稿条件采用D03约定，不等待整轮模型结束，不清晚到的新输入。
- 草稿容器按账户/对话或世界ID定位，`library-editor`继续承担素材并发/flush，不能把其稳定机制拆散。
- 页面局部反馈承载操作对象、状态、最近成功时间；全局通知保留跨页面重要事件。保存/删除/导入等真实Promise不能再次void吞结果。
- 懒加载边界只包内容，外壳/导航立即可用。新模块分离沿用现有lazy-module错误恢复，不新增另一种动态导入重试协议。
- 管理页保留独立原生实现，共享token/文案/状态约定即可；列表、详情、提交仍有各自请求代次，不互相覆盖。
