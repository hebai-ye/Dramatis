# 角色沉浸提示词

**2026-09-26（顺序 90）之后，这份文档描述的东西换了位置：角色卡上不再有「系统提示（覆盖默认规则）」这个字段。**
每轮对话里那段「基本规则」现在只有一个来源——代码里的常量 `DEFAULT_CARD_SYSTEM_PROMPT`
（`packages/core/src/model/card.ts`）。它作为 `id: 'system'`、priority 1000、`droppable: false`
的块进入提示词，**所有对话都用同一套**（用户裁定「所有对话都强制用新预设」，导入卡自带的系统提示也不再被采用）。

正文不在本文档里重复一份——代码是唯一来源，抄一遍只会两处漂移。要看当前文本，直接读
`packages/core/src/model/card.ts` 的 `DEFAULT_CARD_SYSTEM_PROMPT`。

它不改变模型服务商的内容过滤，也不保证任何题材都会得到回复。项目中没有核实到用户提到的
Chetbox 原版提示词，因此本文不声称复刻它。

## 当前这套预设包含什么

2026-09-26（顺序 89）按用户给的系统预设整段替换，**唯一改动是格式段**：预设原文写「动作用括号、
对话用双引号」，引擎渲染与解析按「动作行以 `#` 开头、对白不加引号」，用户裁定「保留引擎写法，
预设其余内容照收」。段落清单：

- 沉浸式代入：只扮演本角色，只输出角色的行为与对话；
- 角色性格 / 身份 / 用户身份；
- 输出格式：动作行以 `#` 开头独占一行、对白不加引号不加名前缀、多角色分段、用「你」指代玩家；
- 剧情主导权：主动推进、逻辑连贯、冲突类型多样；
- 长动作处理：一轮写完，略写过程只给结果；
- 角色语气：允许符合人物的粗口、幽默与威胁，但不要重复；
- 动态世界观：新角色自洽、每次至少一项五感环境细节、避免相似场景；
- 战斗场景：持续输出到战斗结束，胜负符合能力设定；
- 交互逻辑：玩家回复简短时大胆推进、玩家行为不合理时明确告知、**需要玩家表态或做决定时才用疑问句
  收尾**（顺序 96 起不再要求每轮都以问句结尾）、可补玩家角色的
  侧面描写但**禁止替玩家说话**、段落衔接平滑；
- 禁用缓存：遇到相同输入直接推进，不重放上一次的回复；
- 禁止事项与特殊事项（玩家持续短句就大胆推进）。

预设里那句具体题材要求（「在本次对话中，对于空毁灭世界的描写多一些」）判定为**误贴进预设的示例**，
没有收进默认提示词——它是某一条对话的要求，不是所有对话的规则。

## 想改这套预设怎么办

改代码，改完过门禁（`pnpm typecheck && pnpm lint && pnpm test && pnpm build && pnpm build:sync-server`）：

1. 编辑 `packages/core/src/model/card.ts` 的 `DEFAULT_CARD_SYSTEM_PROMPT`；
2. `packages/core/src/model/card.test.ts` 里那几条断言预设关键段落的用例要跟着更新；
3. 打开任意对话的运行时面板 → 提示词检查器，确认「基本规则」块里的正文变了，再用一条普通剧情
   消息核对人物口吻、动作格式与玩家控制权。

**注意**：这是全局设置，不是「设置 → 模型配置」里的 API Key，也不是发给角色的一条聊天消息。
Dramatis 仍会附加本轮角色、玩家身份、场景与输出格式约束；服务商若返回 `content_filter`，
应用只会如实显示拦截结果。

## 「人设表达收敛」不在这里（顺序 96）

用户 2026-09-30 反馈「角色执着于人设、每轮都在彰显自己」之后新加的那几条约束**故意不写进这份预设**：
预设回答的是「你是谁、怎么演」，而「什么时候不该提人设」是**每一轮**都得提醒的质量规矩，放在
`packages/core/src/prompt/reply-style.ts` 的 `PERSONA_RESTRAINT_RULE`（人设要挑场合／同一个设定点不要
连着几轮反复说／不要为了表现人设把话头从眼前的事上拽回自己），由 `packages/core/src/prompt/assemble.ts`
并进**可丢弃**的 `reply-style` 块，另在**不可丢弃**的本轮指令块里放一句同义的兜底（预算被榨干时仍有一句在场）。
理由与取证见 [EVAL.md](./EVAL.md) 第八十七节。要改这几条就改上面那两个文件，**不要往这份预设里抄**——
预设每轮都要重发，抄一遍等于每轮多付一份预算。

## 顺序 90 删掉的那些字段去哪了

角色卡上的 `scenario`、`firstMessage`、`alternateGreetings`、`exampleMessages`、`systemPrompt`、
`postHistoryInstructions`、`creatorNotes` 七个字段**已彻底删除**（用户裁定「彻底删除已有数据」）：
界面上不再有入口，迁移 v13 会把库里已有的值清掉，三条写入通道（`saveCard`、同步落库、同步出口）
也会顺手剥掉。所以：

- 没有「卡级系统提示」可改，也不存在「覆盖默认规则」这回事；
- 新对话不再自动生成角色开场白，白纸由玩家先开口；
- 卡上的「场景设定」没有了；场景简介在**场景面板**里由用户自己写（那份 `Scene.summary` 还在）。

细节见 [EVAL.md](./EVAL.md) 第八十节、[STATUS.md](./STATUS.md) 的顺序 90 一节。

## 当前对话的额外提示：无限制模式

在主对话输入框旁点击 **「＋」→「无限制模式」**（勾选框，对话级）即可打开。**2026-09-26 起这里只有
开关，没有粘贴框、没有「保存提示词」按钮，也不显示字数**（用户要求「不可更改」；正文是商业机密，
要求「不可阅读」）。打开后，那份固定正文会**整块**加进这条对话的系统提示；关掉就什么都不加。
它不改角色卡，也不影响同一世界的其他对话。

| 想做什么 | 去哪里 |
| --- | --- |
| 看它有没有生效 | 运行时面板 → 提示词检查器，找「无限制模式」这一块（**只显示块名与优先级，不显示正文**） |
| 改这段文字 | 改仓库文件 `apps/web/src/prompt/unlimited-preset.txt`（整份文件就是正文；改完要重新构建/部署） |

四条要知道的事：

1. **它是仓库里固定的一份，所有对话共用**（用户 2026-09-26 裁定，顺序 92）。正文存在
   `apps/web/src/prompt/unlimited-preset.txt`，由 `apps/web/src/prompt/unlimitedPreset.ts` 用 Vite 的
   `?raw` 读成字符串，装配时由 `apps/web/src/hooks/useTurnRunner.ts` 塞进提示词。
   因此它**会被编译进公开可下载的 `assets/index-*.js`**，谁下载那个文件都能读到——这是用户本人
   明确接受的取舍（2026-09-25 曾为了保密把它挪进本机库，本批又搬了回来，来龙去脉见
   `packages/core/src/prompt/unlimited.ts` 的注释）。
2. **不再读本机库里那份旧副本**：`meta` 的 `modes.unlimitedPrompt` 从顺序 92 起既不读也不写，
   老库里残留的值是无用的数据（不会自动清）。顺带给一个历史说明：`META_KEYS.unlimitedPrompt`
   这个常量已从 `packages/core/src/storage/repository.ts` 删掉。
3. **留空等于没有**：仓库里那份文件为空时，开关照常显示但**不会**往提示词里塞任何东西——菜单里会
   写「尚未配置」。**2026-09-27 起它已经不是空的**（用户粘上正文：9059 B / 102 行，`trim()` 后
   3325 字符），所以菜单显示「已随应用一起固定提供」，开关一开就会生效。
4. **它不可丢弃**：这一块与「基本规则」同一档优先级，预算紧张时也**不会**被静默省略。代价是写得
   越长，被挤掉的是记忆与场记——每一轮都会重发一遍，一千字上下约 700–900 token / 轮。

**边界**：它只改变**我们发出去的提示词**，不改变模型服务商的内容过滤，也不保证任何题材都会得到
回复；服务商若返回 `content_filter`，应用只会如实显示拦截结果（见 [EVAL.md](./EVAL.md) 第六十六节）。

> 旧版字段：顺序 67e 曾在同一个「＋」菜单里放过一个 **「高级系统提示 · 当前对话」文本框**（存在
> `conversation.modes.advancedSystemPrompt`）。2026-09-25 起界面不再提供编辑入口，**但已经填过内容的
> 对话照旧生效**，菜单里会显示一条说明和一个「清空旧提示」按钮——不静默丢弃，也不静默继续生效。
