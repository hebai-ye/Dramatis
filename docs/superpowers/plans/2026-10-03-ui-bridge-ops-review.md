### A01 — 只复审：extractable 方案 A 的一页影响面

**事实。** `keys.ts:195–198,247–262` 默认解包不可导出，可显式开启；web `sync.ts:190–210` 在密码与恢复码登录两条路径均开启。主密钥放在 `sessionRef.current`（239、391、475），没有用户开关；换密在 615–628 直接用现有主密钥与会话凭证，不要求再输入旧密码或恢复码。断开在 511–520 清 ref，但 JS/浏览器内存不能据此承诺立即物理擦除。`keys.test.ts:230–287` 覆盖默认不可导出，以及显式可导出后换密、旧凭证失效、恢复码仍能解旧数据。`sync.ts:593`“先重新解主密钥”的注释已与实现不符，列入只读发现，交部分一处理。

**判断（威胁模型分析，未执行攻击验证）。** 方案A可作为可信设备上便利会话的有条件取舍接受；不能称为“会话期始终不可导出”或“换密有二次认证”。它保留不换主密钥的换密语义和恢复码兼容，不需要重新加密全部记录。风险增量是恶意同源代码一旦取得密钥引用（例如截获后续WebCrypto调用）便可导出长期可用主密钥；被接管的活跃会话也无需再次证明秘密就能发起换密。不可导出仍无法阻止活跃恶意代码使用密钥解密，因此替代方案是缩小风险，不能宣传为抗任意XSS。单靠CSP也不能替代密钥生命周期设计。

**影响面。** 密码/恢复码登录、自动重连、新空间创建、换密、账户切换/断开、已解锁其它设备和历史密文副本。换密更换鉴权与封装，不撤销已导出的主密钥，也不能让旧封装加旧秘密的历史副本失去解密能力；“旧密码失效”必须限定为当前鉴权及新封装。会话密码/API Key 保存模式与主密钥 extractable 是不同维度，不能混用开关说明。

| 选项 | 行为与代价 | 建议 |
| --- | --- | --- |
| A 保留现状 | 整个同步会话可导出；换密无需再次证明秘密；最少交互 | 若接受上述威胁模型，可作为当前方案，明确记录风险 |
| B 换密时重新认证 | 正常会话不可导出；换密时用旧密码或恢复码临时解包可导出主密钥，包装后释放引用 | 推荐的后续安全默认；增加输入步骤与一次派生，不在本组实现 |
| C 用户选择便利模式 | 默认 B，用户显式选择会话可重新包装；增开关、文案、迁移和测试矩阵 | 仅在用户确实需要长期便利开关时考虑 |

**本组文件:** 仅后续复审说明文档；不改 crypto、sync 实现与测试。**验收清单:** 密码/恢复码两种登录、新建/自动重连、换密、断开/换账户；确认运行期 extractable 属性和二次认证行为；既有测试只证明密码轮换语义，不证明前端生命周期安全。**回滚:** 本轮无密钥语义改动；未来 B/C 必须由部分一制定兼容与会话迁移。本项待选择 A/B/C，不把选择等同于授权本组越界实施。

## 4. 风险、回滚与交付定义

- UI/CSS/Modal：每项局部可回退，保留界面状态与数据；focus、滚动和软键盘必须实测，不能以SSR渲染成功替代。
- 世界书/scene/session：代码回退不撤已落库数据。采纳前保留before与封存；冲突拒绝、目标固定、条件提交必须有测试。跨标签原子性缺口交部分一，不用事后恢复掩盖。
- bridge：保证所有失败释放queue并取消仍在跑的操作；超时不自动重发收费/网页请求。不可识别站点回到手工流程。
- desktop：固定源和端口继续保留；provenance是可丢弃构建元数据；缺记录重建，不杀无法识别的既有服务。
- SW：失败/半途离线保留可用缓存；缓存清理不可由代码回退恢复，上一版模块与可靠恢复路径要实测。
- 运维/备份：真实裁剪和数据库替换不可逆，先隔离演练，实际上线另授权；Report-Only回退不等于验证过强制策略。
- 文档：保留历史事实，仅C02做指定字符串替换；本轮报告不写成已实施日志。每项完成必须同时有实现diff、对应验收证据、明确未验边界，再更新本组台账。
