## 实现行为

导航在 fetch event dispatch 内同步注册一个 `waitUntil`，其 promise 接续导航网络结果。仅成功 basic 同源响应且有 `clientId` / `resultingClientId` 时触发后台刷新。原导航网络 Response 原样返回；HTTP 错误也原样返回，网络失败回落 active、previous、v5 的 index。刷新不 reload 页面。同 worker 共用 refresh promise；成功后节流 30 秒，失败不重置成功时间，后续导航可重试。

`navigator.locks.request('dramatis-shell-publish-v1', { mode: 'exclusive' })` 包住读取当前 pointer、重新 no-store 获取 index / shell manifest / app manifest、静态下载与验证、上一代模块迁入、图片迁移和 pointer 发布。锁外捕获的旧导航 HTML 不传入 staging。新 install 与旧 worker 导航共用同一 origin 的锁名；不使用 steal。

新外壳写入唯一 `dramatis-shell-generation-v1-*`，先验证 HTML 引用的同源 JS/CSS 全部在本次 module manifest，再下载清单所有模块及 HTML/manifest 的白名单静态资源，验证成功状态、basic 同源类型和 HTML/JS/CSS/图片 MIME。`shell-previous.json` 和必要上一代所有模块完成缓存后，最后仅一次 `dramatis-shell-control-v1` 的 active pointer put 发布。清单不变仍重新获取 HTML、manifest 与稳定图标；保留此前 previous module list，所以 install / activate 连跑不会丢上一代 lazy。

Cache API 多步操作没有事务。本实现的隔离来自发布前 pointer 不引用 staging，发布点是单条 pointer put；不能把 generation 的多个 put 说成跨 cache 原子提交。下载、缓存、上一代迁入、图片迁移或 pointer 写失败时已有 shell 不被修改或删除，可能留下孤立 generation，下一次成功发布后再清理。仅删除本应用不再引用的 generation，保留 active、previous、v5、独立图片缓存以及其它应用缓存；发布后的清理失败不会撤回 active。

`/portraits/` 与 `/brand/` 使用独立 `dramatis-images-v1`。发布前将 v5 / 已引用 generation 中已有图片迁入；迁移配额失败不发布外壳。每次图片请求先捕获旧缓存响应，再 no-store 后台更新，只有成功 basic 同源 image 响应才能替换；离线、错误、HTML、opaque、写入配额失败保留旧图。图片 miss 的网络响应可正常返回。其它静态运行时 miss 写独立 `dramatis-static-runtime-v1`，不修改已发布 generation。所有 shell/图片静态读取继续 `ignoreVary: true`。

无 Web Locks 的兼容策略是保守保留旧 v5 / active pointer，不执行 staging 或发布。已有离线外壳仍可兜底；首次安装且无任何旧缓存时不能建立新的离线外壳。这是明确的兼容限制，不使用无锁旁路迁就 mock。真实 ServiceWorker Web Locks 可用性仍需 D01 核实。

## 已准备的行为夹具（未运行）

VM 生命周期夹具使用按名称隔离的 CacheStorage；每个 put 即时写入对应 Map，match 返回 clone，支持 Vary，故不存在假跨 cache 事务。两个独立 VM worker 共享 CacheStorage 与串行 Web Locks；fetch 在暂停前捕获 Response，以表达已在途旧 A 响应。事件 mock 断言 waitUntil 必须在 dispatch 中同步注册。内存 mock 只建模 API 行为，不代表浏览器实现。

- 同 worker 字节的 A → B 导航后离线 B，当前及前代 lazy、稳定图标可读；module list 不变时 HTML/图标变化可更新；install / activate 连跑保留前代 lazy，staging fetch 均 no-store。
- v5 index 离线 fallback、前代模块及 portraits / brand 迁移；迁移配额失败保持 v5 shell / 图片。
- index、module list、app manifest、模块、稳定静态资源下载失败；generation / 前代模块 / 前代清单 / pointer put 失败；generation open、prior read、image open / 枚举、发布前 control open 失败保留 A，并可重试。
- 混合部署 HTML/清单、模块返回 HTML、坏 manifest、非法模块路径、缺失上一代 lazy 拒绝发布。
- 清理失败仍可读新 active，外部 cache 和图片不被删除；中途 staging 与 pointer put 前暂停时旧 A 仍可离线访问，模拟中断失败后新 worker 重试并清除孤立 generation。
- 稳定图 no-store 更新；离线、HTTP 错误、非图片、真实 opaque mock、图片 put 配额失败保旧，后续请求可更新。
- 同时受控导航只一次刷新，成功刷新节流；HTTP 错误、离线、无 client identity、opaque、外源响应不刷新。
- 两 worker 的旧 A staging 暂停 / 新 B install 等锁，锁覆盖 fresh fetch 到 publish；锁外旧 A 导航先捕获、B install 已发布再放行旧响应，最终 pointer 仍为 B。
- 无 Web Locks 的 v5 fallback、已发布 generation 保留、首次无壳无法离线；非 GET、跨域模型、sync、api、未知路径完全 pass。
- 原策略测试最后两例继续正向检查前代 lazy 在 A → B 两次刷新后保留，B 模块 put 失败时 A pointer / HTML / lazy 及缓存删除记录不变。

“中断”用例是暂停后 API 拒绝的可观察隔离夹具，不能声称已测试浏览器进程崩溃、CacheStorage 落盘或真实 worker 终止。D01 应补真实 Chromium 生命周期 / offline / 双 worker 交错 / locks 可用性。
