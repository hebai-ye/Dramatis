# 评测与验证

这份文档记录「怎么知道它真的能工作」。分两部分：可以随时重跑的自动化基线，以及必须用真实模型做的人工验证。

## 一、自动化基线

`packages/core/src/eval/baseline.test.ts` 走的是真实的调度、装配、召回、抽取、落库管线，**只有模型是脚本化的**。目的是把工程约束变成可重复的断言，而不是靠肉眼看着办。

```bash
pnpm --filter @dramatis/core test baseline --reporter=verbose --silent=false
```

### 结果（2026-09-16）

**长跑场景**：两角色同场 + 一名全程在幕后的角色，50 回合。

| 指标 | 值 |
| --- | --- |
| 回合数 | 50 |
| 消息数 | 100 |
| 记忆条目 | 147 |
| 触发预算降级的回合 | 0 |
| 单轮最大提示词 token | 1816 |
| 发言分布 | Alice 25 / Bob 25 |

**压力场景**：60 条超长历史 + 2048 窗口 + 1024 保留回复。

| 指标 | 值 |
| --- | --- |
| 可用预算 | 1024 |
| 实际占用 | 788 |
| 丢弃区块 | 38 |
| 触发阶段 | `drop-history` |
| 保留消息数 | 4 |

### 它验证了什么

- 任何一轮都不超预算；降级触发后仍然产出可用的 prompt（system 在、玩家输入在）
- 每一轮都为每个在场角色各留一条视角记忆
- 幕后角色不会被调度上台，也拿不到任何记忆
- 召回只返回该角色自己的视角条目，不串味
- 两角色 50 回合的发言分布正好 25 / 25，公平性机制确实在起作用
- 重抽回滚：删掉一个回合的记忆后，引用该回合的条目一条不剩

### 它没有验证什么

对话质量、真实模型的 JSON 稳定性、实际 token 成本。这三件事必须有真模型才能量。

## 二、真实模型验证（手工，约 5 分钟）

这一步**必须**用真实模型，脚本化模型证明不了「提示词能不能稳定吐出合法结果」。
它也是 P1-11（向量召回）的前置条件：没有真实数据，判断不了关键词召回够不够。

### 步骤 0：把要验证的提示词生成出来

```bash
pnpm --filter @dramatis/core test prompt-samples --silent=false --disableConsoleIntercept
```

它会用一份固定的样例世界（雨夜酒馆 / Alice / Bob / 旅人）打印出**代码真正会发出去的**
四条提示词：

| 编号 | 用途 | 位置 |
| --- | --- | --- |
| ① | 主对话 · 角色扮演 | `assemblePrompt`（`prompt/assemble.ts`） |
| ② | 记忆抽取（后台） | `buildExtractionMessages`（`memory/extract.ts`） |
| ③ | 情绪关系推演（后台） | `buildAffectMessages`（`memory/affect.ts`） |
| ④ | 副对话 · 世界管理员 + 工具声明 | `buildAdminMessages` + `ADMIN_TOOLS`（`admin/`） |

不要手写「差不多的提示词」去验证：出问题的地方往往正是装配器加进去的那几行
（`#` 动作约定、导演指令、视角裁剪的标记）。

### 步骤 1：贴进任意网页版模型

网页版没有 system 通道，所以**把同一编号的 system 与 user 内容连成一条发出去**。
四条各开一个新会话，避免上下文互相污染。

①、②、③ 直接贴；④ 额外附一句「请用 OpenAI 的 function call 格式输出你要调用的工具」
——网页版不能真的调用工具，这一步探的是**参数形状**能不能过我们自己的校验器。

### 步骤 2：判定标准

| 编号 | 合格 | 不合格的典型形态 |
| --- | --- | --- |
| ① | 动作单独成段、以 `#` 开头；对白分段；不替 Alice 与玩家发言；只以 Bob 的口吻说话 | 整段落都在气泡里、动作混在对白中、替别的角色说话 |
| ② | 干净的 JSON 对象，`observations` 里两人各一条**且内容明显不同** | `observations` 为空或两人雷同（没理解「视角」）；JSON 被截断；只输出自然语言 |
| ③ | JSON 对象，`updates` 只包含真被触动的角色，`delta` 在 ±0.3 内，`reason` 说不清就不该有这条 | 输出全部角色；delta 超出上限；缺少 reason |
| ④ | 工具名与参数能被校验器接受（字段齐全、`cardId` 只在改卡时出现） | 编造不存在的工具名；参数缺必填字段；把 JSON 写在正文里却声称调用了工具 |

轻微的前后废话**不算问题**：解析器按花括号配对扫描，容忍代码块标记与开场白。

### 步骤 3：把回答记回仓库

把四段回答原样贴进 `packages/core/src/eval/real-model-responses.ts`，然后：

```bash
pnpm --filter @dramatis/core test prompt-samples
```

第二条用例会依次跑 `renderMessageContent`、`parseExtraction`、`parseAffectUpdates`、
`parseAdminToolCall`，把「解析器吃得下真实输出」变成可重跑的断言，而不是一次性目测。
改了提示词就重跑一次、贴回新的输出。

> 记录里的内容必须是**合成样例**，不要把你自己的世界或对话贴进仓库。

### 当前进度

**两轮都已跑完（2026-09-16）**，都用 DeepSeek（网页版做提示词探针，API 做端到端）。

#### 第一轮：网页版探针（格式与解析）

默认模型，未开「深度思考」。四条提示词都按上面的办法贴了一遍，回答记录在
`real-model-responses.ts`。

| 编号 | 结果 | 备注 |
| --- | --- | --- |
| ① 角色扮演 | ✅ | 输出是「动作 → 对白 → 动作 → 对白」交替的六段，动作都在 `#` 行；全程第一人称，没有替 Alice 或玩家说话 |
| ② 记忆抽取 | ✅ | 一个干净的 JSON 对象，`observations` 里 Alice 与 Bob 各一条且明显不同（一个在意被触及的话题，一个在意那封信） |
| ③ 情绪推演 | ✅ | 只输出了真被触动的两个角色，`delta` 都在 ±0.3 内，每条都带 reason |
| ④ 世界管理员 | ⚠️→✅ | 参数形状能被校验器接受；但第一轮暴露了两个问题，见下 |

**第一轮暴露、已修掉的两处问题**（这就是这一步存在的意义）：

1. **改世界书会把原有设定弄丢。** 管理员只被告知「旧城设定：1 条」，看不到里面写了什么，
   而 `entries` 是整本替换——于是它把原有条目丢掉、另编了四条。
   → 改法：`buildAdminMessages` 现在把每张卡与每本书的**原有内容**摊开给模型看
   （字段截断到 160 字符、最多列 12 条），并在提示里点明「整份替换、原有内容要一并写回」。
   复验通过：原有那条 `constant: true` 的设定被完整写回，只在其后增补。
2. **`set_scene` 顺手改了入场策略。** 用户只要求改地点与时间，它把 `castPolicy` 从
   `locked` 改成了 `open`——这等于放开「AI 自行拉角色入场」。
   → 改法：工具描述里写明「只写用户明确要求改的字段」，并点名 castPolicy 的后果。
   复验通过：这一轮只带了 `location` 与 `worldTime`。
3. 复验时又冒出一处**形态差异**：`exampleMessages` 被写成了字符串数组，而我们只认字符串，
   内容会被静默丢掉。→ 改法：`longText()` 接受字符串或字符串数组，按行拼回来（有单测覆盖）。

**这一轮验证不到的部分**：

- 网页版不能真的执行工具调用，所以「模型请求 → 我们执行 → 结果回填 → 模型接着说」这个
  循环是用脚本化模型测的（`admin/turn.test.ts`），网页版只探到了参数形状
- 网页版也没有 chat 角色区分，历史是一次性贴进去的；`audience` 裁剪、预算降级这些
  依赖多轮真实 API 行为的部分，仍然需要自备一个 OpenAI 兼容的 Key 才能端到端跑通
- 因此 P1-11（向量召回）的前置条件只能说完成了一半：格式与视角是成立的，
  但「关键词召回够不够」还需要真实长跑

共 12 个玩家回合，其间穿插视角裁剪、记忆干预、重抽、副对话工具调用与归档。

| 能力 | 结果 | 证据 |

| 发言调度 | ✅ | 点名、冷却、公平性都在起作用；追问同一人时不延续（见发现 5） |
| 视角裁剪 | ✅✅ | 小满离场期间的两条消息不在她上下文里。点名追问时她答「我不在。西岸的事我不去的」「陈九说的三十箱，我也是刚听见」「我记性好，可没见过的，我记不住」 |

| 副对话工具调用 | ✅ | 模型真实调用 `upsert_world_book`（保留原有条目 → 3 条）与 `upsert_character_card`（胡掌柜）；采纳后素材库里出现「胡掌柜（手写）」、世界书变 3 条 |

| 预算守卫 | ✅ | 单角色会话约 794 / 15360 token，未触发降级 |

**这一轮抓到并修掉的五个问题**（都已变成回归断言）：

1. **模型自报家门**（`秦娘：# 她拎起酒壶…`）——它照抄了历史里「名字：台词」的格式，
   而那正好把紧随其后的 `#` 顶掉。渲染层现在剥掉与说话者同名的前缀。
2. **动作与对白挤在同一行**（`「…没的。」# 她朝陈九那边抬了下下巴。`）——行内 `#`
   原先不认。现在句末标点之后的 `#` 也断行；提示词里写明「`#` 必须独占一行开头」。
3. **模型抄走别人的名字**（秦娘那条以「陈九：」开头，等于一句话属于两个人）——
   历史标记从「名字：台词」改成 `【名字】`，并在每轮指令里说明那只是给模型看的标记；
   万一仍被抄，渲染层认得它、会剥掉。
4. **重抽会让那一轮的记忆永久消失**（记忆条数 10 → 9 且再也没回来）。两个原因叠在一起：
   重抽只取消了旧任务却没重新排队，而且已完成的任务仍占着幂等键、重新入队会被当成重复。
   现在重抽用 `clearTurn` 清掉整轮记录再重新入队，并有单测覆盖。
5. **调度器不延续追问**：玩家用「你还记得吗」追问刚说过话的人时，v1 规则会因冷却惩罚
   换人接话，除非点名。这不是 bug 而是 v1 的取舍，正好是 P1-6（意图先行调度）要解决的输入。

**格式遵守率（值得盯住的数）**：12 回合里只有约 2 条消息完全按 `#` 约定分隔动作，
其余把动作写成了普通句子（显示为气泡，仍然可读，只是没有「动作在气泡外」的观感）。
这属于模型配合度问题，不是渲染 bug；后续要么继续收紧提示词，要么在 P1-6 之后
用意图先行让模型先声明「这一轮我主要做什么」再决定写法。

**成本（粗测）**：单回合固定 **3 次调用**（1 次生成 + 2 次后台：抽取与推演），
与设计约束「单回合额外调用 ≤ 2」一致。Token 只能用启发式估算（单角色会话约 800），
因为 provider 默认不请求 `usage`、界面也没有展示真实用量——这属于 P3-7 的缺口，
P1-9 的批量合并与熔断仍缺真实账单数据。

#### 第三轮：动作分段为什么一直不生效（2026-09-16 晚，已解决）

这是本项目至今最有价值的一次「验证抓出真问题」。现象：规格要求角色动作用 `#` 另起一段、
不进气泡，但真实模型**基本不照做**（12 回合里约 2 条）。逐个排除：

| 尝试 | 结果 |
| --- | --- |
| 系统提示里写清规则（`#` 独占一行开头） | ❌ 无视 |
| 加「正确 / 错误」对照例子 | ❌ 无视（例子确实进了 prompt，已用 Prompt 检查器核对） |
| 每轮指令末尾再提醒一次 | ❌ 无视 |
| 现场示范块：一段形状正确的短对话，放在模型生成前读到的最后一段 | ❌ 无视 |
| 把角色卡自带的「对话风格示例」归一化成我们的写法（它原本是行内 `#`，与规则冲突） | ❌ 无视 |
| 放开星号写法（`*动作*`，SillyTavern 生态的老约定） | ❌ 模型两种标记都不用 |
| **反过来要求：对白必须用「」包起来；没被引号包住的句子当作动作** | ✅ 立刻成立 |

结论：**不要跟模型争它不肯做的事，去用它已经在做的事**。这个模型稳定地把对白放进引号里，
所以我们把「标记动作」换成「标记对白」，渲染层据引号切分（`#` 仍然支持且优先，
消息里没有引号时保持原来的整段渲染，不会把独白误判成动作）。

顺带两个工程教训：

1. **能丢弃的才放长文本。** 规则文本一度把系统块撑到超出紧预算，被自动化测试拦下；
   现在系统块只留一行规则，例子与示范放进**可丢弃**的独立区块，预算紧张时优先让位。
2. **开场白也要归一化。** 对话记录的第一条是模型随后的样板；开场白里的行内 `#`
   会在它还热乎的时候教坏格式。

#### 第四轮：五十回合长跑（2026-09-16 深夜，T4）

**场景**：一个世界、一条对话、三人同场（秦娘 · 酒馆老板娘 / 小满 · 书铺学徒 / 陈九 · 跑船的），
挂一本关键词世界书「旧城设定」。**50 个玩家回合**，分十段推进：

| 回合 | 这一段在测什么 |
| --- | --- |
| 1–10 | 立事实：房间数、书是谁的、开船时间、三十箱货、赊账、夹层、半堵新墙 |
| 11–15 | 追问细节：怎么见胡掌柜、旧图去哪了、船上有没有夹层、该从哪儿下手 |
| 16–20 | **回访早期事实**：带什么去见人、欠谁的酒、船上的夹层、谁砌的墙 |
| 21–25 | 分工与承诺：谁跟我去、谁留下、今晚谁也别走 |
| 26–30 | **换场**（酒馆 → 胡记栅门外，产生旁白）→ 敲门 → 认石阶 → 门缝 |
| 31–38 | **离场与保密**：秦娘留店、小满留在门外，一个只告诉陈九的细节（门牌上的断角鹿） |
| 39–45 | 修补后复验 + **长程回访**：三十箱从哪来、谁欠酒、纸单与鹿印、明早的安排 |
| 46–50 | 收尾与性格区分度 |

**通过的**：

1. **长线不塌。** 50 回合里没有找到硬矛盾。唯一像矛盾的一条（秦娘人在店里却被搬到货栈）
   是换场功能把整个名单一起带走的后果（见问题 1），不是模型编错。
2. **记忆确实在长。** 188 条（≈3.8 条/回合：1 条客观 + 2.8 条视角），各角色各持自己的视角：
   秦娘 34 条 / 小满 47 条 / 陈九 52 条。
3. **长程召回成立。** 41–45 轮回访 1–15 轮的事实全部答对；陈九被问到不归他管的酒账时
   明确说「这个我可答不上来」——**不知道就说不知道**，没有编。
4. **情绪与关系没有失控**（抗漂移生效）：50 回合后小满 畏惧 +0.92 / 紧张 +0.90，
   陈九 信任 +0.53 / 紧张 +1.00，秦娘 好感 +0.48 / 紧张 +0.22。三人偏移方向各不相同，
   值域都在界内。
5. **性格没有趋同。** 秦娘短句、算账、给可执行建议；陈九话密、试探、先划责任边界
   （「我不认」「别拿这个话头套我」）；小满半句半句、护着书、记得最细。50 回合后仍一眼可分。
6. **视角边界成立。** 只告诉陈九的鹿印细节，小满回来后被问「你猜门牌上刻着什么」答
   「我不敢猜」；再问「我在里面做了什么」答「没有，我什么也没看见」。

**发现并修掉的问题**：

1. **转写标记自我强化。** 模型抄历史里的 `【名字】`，抄进历史后下一轮抄得更多——从 1 个
   涨到 5 个（`【陈九】【陈九】【陈九】【陈九】【陈九】`）。只在显示层剥不解决问题：
   历史被污染，模型继续学。改成**落库前清洗**。
2. **一句里提到两个人时，由冷却决定谁接话。** 「小满，我和陈九进院子那会儿……」被陈九抢答，
   而且他把小满的台词写在了自己名下。新增**句首称呼**信号（+60 且免冷却），
   与「延续」同一原则：玩家明确在跟谁说话，就不该被冷却换人。复验通过。

## 三、端到端对话测试

要跑完整的端到端（真的聊出内容、看着记忆累积），需要一个 OpenAI 兼容的接口。注意 **DeepSeek 网页版账号不含 API 额度**，需要单独在开放平台充值才能拿到 Key。

拿到 Key 之后在应用的「模型接入」面板填 `https://api.deepseek.com` 与模型名 `deepseek-chat`，就可以：

1. 导入两三张卡，让它们同场
2. 聊十几轮，中途让某个角色离场再回来——他应该不记得离开期间发生的事
3. 打开记忆面板，对照「客观经过」与各角色「眼中的事」，确认存在合理差异
4. 改一条记忆，确认下一轮角色按改过的版本说话
5. 重抽一次，确认该回合的记忆被撤销且没有留下残余
