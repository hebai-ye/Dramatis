# Dramatis · 登场

> 多角色扮演酒馆 —— 导演你的角色阵容，让每个角色记住属于自己的故事。

**TL;DR (English)** — Dramatis is an open-source multi-character AI roleplay tavern for Web, Android and desktop. Direct the cast, lock the scene, and let every character keep their own memory and personality. SillyTavern-compatible character cards and world books. Local-first with optional cloud sync. Bring your own API key.

`sillytavern-compatible` · `ai-roleplay` · `character-card` · `worldbook` · `local-first` · `byok` · `pwa` · `tauri` · `capacitor`

## 项目状态

**P0 全部完成，P1 记忆闭环已交付（批次 1–3）** —— 兼容层、本地持久化、多角色同场、发言调度、视角化记忆与记忆面板都可以运行，并带有测试。进度见 [docs/ROADMAP.md](docs/ROADMAP.md)。

已经能用的：

- 导入 SillyTavern 角色卡：PNG 的 `chara` / `ccv3` 数据块，以及 V1 / V2 / V3 的 JSON。未识别字段原样保留并提示，不静默丢弃
- 导入世界书（`world_info` JSON）：关键词触发、次级键选择逻辑、概率、排序权重
- 本地持久化：世界、场景、消息、角色状态都存在 IndexedDB 里，刷新与重启不丢
- 多个世界并存，可随时切换与删除；删除世界会保留导入过的角色卡
- 多套模型服务配置，密钥与配置分开存放，密钥永不进入可同步的数据
- **多角色同场**：一个场景里可以有多个角色，各自拥有独立的在场状态与视角
- **发言调度**：谁接话由可解释的规则决定（点名、冷却、公平性、外向权重），并显示每个角色的得分与理由
- **按视角裁剪上下文**：角色看不到自己不在场时发生的事，且不消耗额外模型调用
- **重抽与编辑**：重抽会先撤销该回合的记忆写入，避免角色同时记住两个矛盾的版本
- **视角化记忆**：后台异步抽取，同一次事件在不同角色眼里是不同的记忆，允许互相矛盾
- **记忆面板**：能看清每个角色分别记得什么，可编辑、置顶、删除、调整重要度
- 流式输出，兼容一切 OpenAI 协议的接口，自带 Key
- 入场策略（锁定 / 仅限召唤 / 条件触发 / 自由入场）会作为导演指令写进 prompt
- 预算守卫：超长时按固定顺序降级，并保证一定产出可用的 prompt
- 界面里的 Prompt 检查器会显示每次装配的区块与降级情况

还没有的：记忆抽取与召回、情绪与关系演化、账号与同步、移动端与桌面原生壳。

## 桌面入口（推荐用来试用）

Windows 上双击 `start-dramatis.cmd` 即可。或者从命令行：

```bash
pnpm desktop        # 开发模式，改代码即时生效
pnpm desktop:prod   # 先构建再启动，更接近真实运行
```

它做三件事：起本地服务 → 等它真的能连上 → 用 Edge 或 Chrome 的**应用窗口模式**打开。没有地址栏、没有标签页，任务栏里是一个独立窗口。

**地址固定在 `http://127.0.0.1:5273`，别改。** 浏览器按「源」隔离数据，换个端口就等于换一个空数据库，你会以为数据丢了。启动器因此用了 `--strictPort`：端口被占用时宁可启动失败，也不静默换端口。

这只是 P2-2（PWA）之前的最低成本桌面体验，**不是** P2-9 的 Tauri 壳。等到需要常驻后台任务或系统级密钥存储时，再上真正的壳。

如果你对设计有意见或想法，欢迎直接开 Issue 讨论，这个阶段正是改设计最便宜的时候。

## 快速开始

需要 Node 20+。**桌面入口不需要 pnpm** —— 它直接调用 Node 与 Vite。

如果要从命令行跑开发服务器，本项目用 pnpm 管理依赖：

```bash
pnpm install
pnpm dev        # 启动 Web 端，默认 http://localhost:5173
pnpm typecheck
pnpm test
```

没装 pnpm 也能装依赖：`npx --yes pnpm install`。

打开页面后，在左侧填接口地址、API Key 与模型名。支持 DeepSeek、OpenAI、Kimi、阿里百炼、智谱，以及 Ollama、LM Studio 这类本地服务；只填域名时会自动补 `/v1`。然后导入一张角色卡，就可以开始对话。

## 这是什么

Dramatis（中文名 **登场**）是一个开源的多角色扮演酒馆前端。名字取自 *dramatis personae*（剧中人物表），也对应它最核心的动作：**让角色登场**。

它做的不是"和多个 AI 角色分别聊天"，而是让你像导演一样掌控一个持续运转的场景——谁在场、谁沉默、谁在幕后，以及每个人各自记得什么。

**与 SillyTavern 的关系**：兼容它的生态（角色卡、世界书、预设、聊天记录都可以直接导入），但不是它的分支，也不是来取代它的。Dramatis 做的是它结构上做不到的那部分。

## 核心设计

### 导演系统：谁在场，由你决定

场景有独立的入场策略，运行时一句话就能切换：

| 策略 | 行为 |
| --- | --- |
| `open` | 满足触发条件的角色可自行入场 |
| `locked` | 冻结在场名单，AI 不得引入任何新角色 |
| `invite_only` | 只有你显式召唤才入场 |
| `triggered` | 满足条件才入场（目标被触发、世界书命中） |

角色同时有独立的存在模式：`onstage`（在场可发言）、`muted`（在场但沉默）、`offscreen`（在幕后，不参与对话但记忆仍在积累）、`absent`（离场）。

`offscreen` 是关键。角色不该被冻结——你离开三天再回来，他这三天也该有生活。

### 发言调度：不把"谁说话"交给模型

调度器独立于生成模型，输入包括：玩家是否点名、关键词与世界书命中、与各角色当前目标的相关度、召回记忆的相似度、角色的外向权重、刚说过话的冷却惩罚、久未发言的公平性补偿。

调度用便宜模型或纯规则，生成才用正式模型。角色还会先输出一句"此刻想干什么"的意图，再据此生成对白——插话、抢话、欲言又止才会像人。

### 记忆系统：分层、按视角、有损压缩

```
工作记忆  最近 N 轮原文（唯一的精确层）
场景记忆  当前场景的滚动摘要
情节记忆  结构化事件：时间 / 地点 / 在场者 / 发生了什么 / 对关系的影响
语义记忆  客观事实（你的身份、喜好、世界设定）
关系情绪  角色→你、角色→角色的慢变量数值
人物内核  从卡里提炼的、当前场景激活的性格切片
```

三个和常见做法不同的地方：

- **记忆按视角存储。** 同一件事，Alice 记的和 Bob 记的不该一样——他注意到了什么、误解了什么、在意什么。这是"多个角色"和"一个角色的多个分身"之间的分界线。
- **召回是混合的。** 向量相似度 + 关键词 + 标签过滤 + 时效衰减 + 重要性打分，按每个角色的记忆预算裁剪，并允许模型主动 `search_memory` 深挖。
- **压缩有损，原文永不删除。** 轮 → 场景 → 章节三层摘要，被压出窗口的原文仍在本地库里，随时可以展开回想。

### 不会卡死：硬预算守卫

拼装 prompt 前做 token 预算核算，超出就按优先级降级：丢最旧的原文 → 丢低分召回 → 压缩关系描述。**永远不因为超长而报错**，宁可信息少也要出得来话。

### 人格动态：慢变量 + 快变量

角色卡的 personality 是静态文本，Dramatis 把它拆成可计算的两层：

- **慢变量**：5~8 个可打分特质轴（外向、攻击、共情、戏谑、谨慎……），基本恒定。
- **快变量**：情绪与关系数值，每轮更新、会衰减。

每轮生成后由状态更新器推演变化，生成时注入的是"他此刻处于什么状态、对你是什么态度"，而不是每次重述整份人格。另有**抗漂移机制**，每隔 N 轮用角色卡内核重新锚定，避免聊久了所有人都变成同一个温柔知心 AI。

## 架构

TypeScript monorepo，平台无关的核心逻辑抽成 `core`：

```
packages/core       数据模型 / 兼容层 / Prompt 装配 / 模型接入
apps/web            React + Vite（Windows 与 Android 共用同一套 UI）
services/sync       账号与云同步（P2）
```

Android 与 Windows 桌面都优先走 PWA：一套代码，不需要独立的构建链路。只有当 PWA 出现解决不了的缺口时，才考虑 Tauri 桌面壳或 Capacitor 安卓壳，触发条件见 [docs/ROADMAP.md](docs/ROADMAP.md) 的 P2-9 / P2-10。不考虑 iOS。

- **本地优先**：本地 SQLite 随时可用，云端同步负责多端一致与数据安全。
- **自带 API Key**：密钥只存在设备本地，不参与同步。
- **端到端加密**：开启同步时，用同步密码派生密钥加密后再上传，服务端不碰明文。

详细设计见 [docs/DESIGN.md](docs/DESIGN.md)。
