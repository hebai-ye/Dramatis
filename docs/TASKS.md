#### 每一项怎么做（改哪里 / 怎么改 / 怎么验）

**57 被印象取代的原文退出常规召回，保留「提到才想起」**（P0，S）

- 改哪里：`core/memory/recall.ts`、`apps/web/src/App.tsx` 的召回段（约 700–723 行）、`PromptInspector`。
- 怎么改：
  1. `recallMemories` 增加选项 `superseded: 'exclude' | 'on-keyword'`，默认 `exclude`：`supersededBy` 非空的条目不进主池。
  2. 新增纯函数 `recallSupersededOnMention(events, query, limit = 2)`：只对被取代的原文打分，**只有** `reasons` 里含 `keyword`（或 `pinned`）的才返回，按分数取前 `limit` 条——这就是「玩家明确提到才想起」。
  3. 玩家在问过去（`asksAboutPast`）且召回结果里有印象时，顺着 `supersedes` 把来源原文再展开最多 2 条（复用 27e 的 `resolveMemorySources`）。
  4. App 里把主池换成「未被取代」，附加池走 2 / 3；附加条目的 `score` 压到低于印象，让预算守卫先丢它们。
  5. Prompt 检查器的记忆小节标出「从印象取回 N 条」。
- 怎么验：单测三条——默认不出现被取代原文；关键词命中时出现且 ≤2 且排在印象之后；问过去时印象带来源。假模型 60 轮演练（触发一次合并后）读 IndexedDB 对账：召回池条数 = 未取代 + 印象；提到关键词那一轮，Prompt 检查器里出现原文。EVAL 记一节。
- 风险：印象的关键词靠启发式，可能漏；漏了只是「想不起来」，不会想错。
- **✅ 做完（2026-09-23）**，与计划的偏差：① 选项名是 `superseded: 'exclude' | 'include'`，「提到才想起」不是
  `recallMemories` 的一个模式，而是统一入口 `recallForPrompt()` 的第二条通路（`mentionText` **必填**，只能是玩家这一句）；
  ② 补充项除了分数压低，**预算里还留一块不超过 1/4、只按实际装得下的量**的位置——演练里最近六轮的地名把近事
  全算成命中、填满预算，不留位置补充项永远进不来；③ 检查器区块悬停显示 id，演练按 id 对账。
  单测 +11，真机 15/15，见 EVAL 第四十六节。

**58 提示词按「场记覆盖」收起远处原文**（P0，M）

- 改哪里：`core/prompt/history.ts`、`core/prompt/assemble.ts`（历史块与场景块）、`core/model/conversation.ts`（一个可选开关）、App 的装配入参、设置或对话模式菜单。
- 怎么改（质量优先的规则，**不是**固定 N）：把当前对话的原文分三段——
  1. **未被任何场记覆盖的**：全带（场记每 8 轮 / 2400 token 才滚一次，所以最近这一段本来就在）；
  2. **已被覆盖、但在近窗内的**：全带。近窗默认 **40 条**，只是「就算场记已覆盖也保留原文」的下限，可调；
  3. **已被覆盖、且在近窗之外的**：不带原文，由 `scene.recap`、章节、记忆代表；玩家提到关键词或问过去时，用 57 的同一套触发从这一段取回 ≤3 条原文（新函数 `expandHistoryOnMention`）。
  - 顺带补一个现在就有的漏洞：章节要攒够 3 场才滚，所以**已结束但还没进章节的前几场**，它们的场记在原文滚出窗口后没有任何载体。新增「前几场场记」块（当前对话里 `endedAt` 非空、且未被章节收录的场景的 `recap`），优先级同章节块。
  - `historyPolicy: { mode: 'full' | 'recap-aware'; nearWindow: number }`，默认 `recap-aware / 40`；在对话模式菜单里给一个「历史：完整 / 场记覆盖后收起」的开关（对话级，落 `ConversationModes`，老数据缺省即新默认，不需要迁移）。
- 怎么验：假模型 300 轮长跑（MEMORY.md 第七节的脚本）：提示词曲线**封顶**且不再线性涨，预期落在场记周期 + 近窗 ≈ 5–6 千字；场记 / 章节 / 记忆块都在；真模型 50 轮定向问答（EVAL 第十节那种）**长程召回不低于 T4 的全中**；关键词取回的原文在 Prompt 检查器可见。把 MEMORY.md 第八节的成本估算按新曲线修订。
- 风险：场记质量决定远处细节能否保住——它本来就是「只压已发生的、保留人名数字承诺」，且原文永不删、提到就取回，所以最坏情况是多花一次取回，不是丢。
- **✅ 做完（2026-09-23）**，先量后做：假模型 300 轮，改前提示词线性涨到 21,947 字（历史 606 条），改后从第 40 轮起
  封顶 3.3–3.75 千字（历史 40 条），探针「铜钥匙呢？」从 568 条收起原文里取回第 5 轮那句。与计划的偏差：
  ① 「问过去」没有具体所指时不从收起段取回（取哪三条没依据；场记 / 章节 / 印象来源已在回答），只认关键词；
  ② 取回的原文集中成一节「提到的旧对话原文」而不是插回记录；③ 顺带修掉「已结束场景的尾巴永远进不了场记」
  （worker 对已结束场景不再按门槛判）；④ `historyNearWindow` 可调但没做界面，开关只有「场记覆盖后收起远处原文」。
  **真模型 50 轮定向问答未跑**（要用户的 Key）。见 EVAL 第四十七节。

#### 问题二的答案：你的账户数据到底在哪、怎么定期上服务器、能不能切账户

**现在的事实**（读代码 + 线上实测，不猜）：

| 数据 | 存在哪 | 谁能读 |
| --- | --- | --- |
| 世界 / 对话 / 消息 / 记忆 / 关系 | 这台设备的 **IndexedDB**（`dramatis` 库） | 只有这台设备 |
| 同步副本 | **你自己的服务器**（`/var/lib/dramatis-sync/sync.db`） | 服务端只能看到密文：`sealed`（AES-256-GCM）、`updated_at`、`space_handle`；**看不到内容** |
| 解开它的钥匙 | 由同步密码 + 恢复码派生（本机解开封装的"主密钥"） | 服务端也没有明文钥匙（只存两份加密封装） |
| API Key / 模型配置 | **只在本机**（浏览器 localStorage / 内存），不进同步、不进封存 | 不上服务器 |

**「定期存到服务器」现在的状态**：① 每轮对话结束后自动推一次（已在）；② 这次新增
**5 分钟心跳**（页面开着且可见时才会跑）——两条共用同一个节流窗口，不会双倍流量。

**「切账户换数据」现在做不到**，这是真缺口，原因很具体：本机只有**一个**数据库，
所有世界都堆在里面；换同步空间只换「推到哪」，本地数据不分家——换个账户同步，
两边的东西会合并到同一份本地数据里。两种做法：

1. **一个账户一个库**（推荐）：本地库名带上空间句柄（`dramatis:<spaceHandle>`），
   切账户 = 切库，天然隔离、不用动数据模型；代价是要把现有那份数据迁到「未指定账户」的库里，
   并在界面上明确「切了以后看不到另一个账户的世界」。
2. **给实体加空间字段**，查询时按空间过滤：改动铺得广（每处查询都要带条件），
   好处是同一个页面可以同时显示多个账户的数据——这一版不需要。

顺序 37 就按第 1 种做，验收标准是：A 账户看到 3 个世界、切到 B 看到 0 个、切回 A 还是 3 个，
且切换过程中不丢任何一条数据。

#### A. 「链接 DeepSeek 网页版」的原意是**不用复制粘贴**（总表顺序 7）

现在交付的网页版桥接是**手动转接**：复制提示词 → 贴进网页版 → 把回复粘回来。
用户要的是全自动。三条可能的路摆在这儿，**代价差一个数量级，需要拍板**：

| 路线 | 怎么做 | 代价与风险 | 我的建议 |
| --- | --- | --- | --- |
| **A1 官方 API Key**（现状 + 极简引导） | 用户在 deepseek.com 建一个 Key 填进来 | 要充值；但这是**唯一稳定、合规、不会封号**的路。体验上能补的：把「注册 → 建 Key → 填回来」写成三步图文，Key 错/额度尽给明确报错 | ✅ **推荐**，并入顺序 8 |
| **A2 本地助手**（可选，只装在自己电脑上） | 一个小工具跑在本机：用它打开**你自己已登录**的 DeepSeek 网页，自动填提示词、取回复；应用连 `http://127.0.0.1:<端口>` | 真的不用复制粘贴。但：依赖网页 DOM（改版就坏）、登录态会过期、**属于自动化访问，与 DeepSeek 使用条款冲突**（有被限流/封号的风险）、只在桌面、要装 Node、手机用不了 | ⚠️ 可以做，但必须**默认关闭 + 明确告知风险 + 只在你自己的机器上** |
| **A3 服务端代理 / 共享账号** | 服务器替所有人调模型 | **不做**：服务器会拿到所有人的 Key（或账号 cookie）、成本无上限、被刷爆、合规风险集中在部署者身上；与「BYOK、不做模型代理」的定位直接冲突 | ❌ 不做 |

**为什么不能「后端自动连网页版」**：DeepSeek 网页版没有对外接口。所谓「自动」只有两条路——
逆向它的内部接口（要拿用户的登录凭证去冒充网页，随时失效且违反条款），或者在服务器上跑浏览器
自动化（同上，而且把风险从用户身上挪到部署者身上）。所以这两条**不作为默认能力**；
要「零复制粘贴」，A2 是唯一在**用户自己机器上**成立的形态。

#### B. 「我填的 API Key 存哪、谁能看见」（总表顺序 8 + 10）

**实测**（本机生产构建，走真实 UI 填一个假 Key，保存方式选「保存在本机浏览器」）：

| 位置 | 实际内容 |
| --- | --- |
| `localStorage['dramatis.keys.v1']` | `{"provider:<uuid>":"sk-…"}` —— **明文** |
| IndexedDB `providerProfiles` | 只有 `baseUrl` / `model` / `keyRef`，**没有 apiKey 字段**（设计上就不存） |
| 切回「仅本次会话」 | 明文那份被清掉（localStorage 变成 `{}`），Key 只活在内存 |

**谁能看到它**（这就是「多少个地方能看见」的准确答案）：

| 谁 | 能看到 | 说明 |
| --- | --- | --- |
| 你自己的浏览器 | ✅ | 明文（device 档）或内存（session 档）；同源脚本都读得到，所以别在这个域上装来路不明的脚本/扩展 |
| 模型服务商（DeepSeek） | ✅ | 请求头 `Authorization: Bearer` 直接发到它的 443，浏览器直连，不经过我们的服务器 |
| 我们的同步服务端 | ❌ | 库里能查到的列只有 `space_handle / collection / id / server_rev / updated_at / deleted_at / sealed`，**没有任何 Key 字段** |
| 同步上传的内容 | ❌ | `providerProfiles` **不在同步白名单**（十类实体里没有它） |
| 封存导出文件 | ❌ | 导出是固定清单（世界/对话/场景/角色/消息/记忆/章节/世界书/身份/账单），**不含模型配置与 Key** |
| Service Worker 缓存 | ❌ | 模型请求（跨域 POST）一概不拦不缓存；缓存里只有同源 GET 的外壳 |
| 账单流水 | ❌ | 只记模型名、token、单价，不记凭证 |
| **给你发网页的那个人** | ⚠️ **能** | 唯一的信任边界：**能改这个网页的人就能读你填进去的 Key**。自己部署=自己；把网址给朋友用，等于把「读 Key 的能力」给了部署者。这就是「各自带自己的 Key、服务器不存 Key」的理由 |

**服务器上对外开着哪些口**（实测 `ss -tlnp`）：

| 端口 | 谁在听 | 对谁可见 |
| --- | --- | --- |
| **8443** | nginx（网页 + `/sync` 反代） | **公网**——我们唯一对外提供内容的端口 |
| 80 | nginx 的 default 站点 | 公网看到的是**腾讯云的备案拦截页**（不是我们的东西）；服务器本机访问看到 nginx 默认页。建议顺手关掉 default 站点（顺序 18，优先级不高） |
| 8787 | 同步服务（Node） | **仅 127.0.0.1**，公网连不到 ✅ |
| 443 | Tailscale | 只在 tailnet 内；你已决定放弃 Tailscale，可以考虑卸载（它还在跑，占 ~50MB 内存） |
