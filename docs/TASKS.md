## 一、马上要做（P1 收尾：记忆质量）

### ✅ T1 动作分段能用了（换了一条路：让模型守它已经在守的约定）

- [x] 现状确认：真实模型 12 回合里只有约 2 条消息按 `#` 分隔动作
- [x] 逐个试过并全部失败：系统规则、正反例、每轮提醒、现场示范块（可丢弃）、
      把角色卡自带的风格示例归一化、连「动作用 `*星号*`」都放开——**模型就是不加标记**
- [x] 转折点：它有一点极稳定——**对白永远带「」引号**。于是把约定反过来：
      **引号内是对白，引号外是动作**。渲染层在「这条消息用过引号」时启用，没引号就保持原样；
      `#` 仍然支持且优先
- [x] 在**已有消息**上直接验证（不需要重新生成）：动作落到气泡外，对白留在气泡里
- **来源**：EVAL.md 第二轮的遵守率统计
- **验收**：小满/秦娘的回复在真机上呈现「斜体动作 + 气泡对白」交替 ✅
- **副产品**：规则文本一度把预算撑爆——例子必须放进**可丢弃**的格式块，
  不可丢弃的系统块只留一行规则

### ✅ T2 发言调度 v2：意图先行（T2a/T2b/T2c 三块全部交付）

**T2a 规则信号（已交付）**

- [x] 「说给上一个人听」：出现「你 / 您」且没有「你们 / 各位 / 大家」时，给上一位延续
      加成并免掉冷却；问全场时照旧轮换（真机复验：不带名字追问仍由同一个人接话）
- [x] 「开口就叫了他」：句首称呼单独识别（+60 且免冷却），一句里提到两个人也不会被抢走话头
- [x] **只做动作、一个字没说的那一轮不再算「发言」**，不吃冷却
      （判据是正文里有没有引号，而不是渲染规则怎么显示——渲染为了兼容会把无引号的行
      也当对白，那样纯动作的一轮会被误判成「说了话」）

**T2b 意图（零额外调用版，已交付一半）**

- [x] 解析与存储：模型若按格式写「意图：…」，这一行单独存进消息、正文里不留
      （留在正文就会进历史，被下一轮学成正文的一部分）
- [x] 界面显示：气泡上方一行「想做：…」，每次渲染重算、不缓存
- [x] 调度用上它：角色自己说过「我在旁边看着」时，下一轮让一让（可解释的加减分）
- [x] **推理流当盘算**：模型没声明、但返回了推理流时，取首句作为「盘算：…」
      ——那是它真实在想的事，只是不是我们要的格式。零额外调用
- [x] 真机测过遵守率：**0/4**。DeepSeek 对「意图：」这种标签指令与 `#` 一样不理
      （T1 的教训：不要要求它做它不肯做的事），所以主力走推理流那条路

**T2c 真正的「生成前意图」（已交付）**

- [x] 生成之前用便宜模型问一句「此刻想做什么」，据此决定插话 / 抢话 / 欲言又止 / 主动发起
      （四种 mode：`reply` / `cut_in` / `hold_back` / `initiate`，`director/intent-plan.ts`）
- [x] **钱从哪来**：把记忆抽取与情绪推演**合并成一次后台调用**
      （`memory/turn-analysis.ts`，两者本来吃同一批消息、同一批在场角色）。
      账从「1 生成 + 2 后台」变成「1 生成 + 1 意图 + 1 合并后台」，
      **每回合额外调用仍是 2 次**
- [x] **意图是建议不是命令**：名字对不上在场角色、`presence` 不是 `onstage`、
      `hold_back`——任何一条都丢弃并退回规则调度；调用或解析失败一律静默退回
- [x] 风险已按流程处理：抽取与推演的提示词都经过真模型验证，合并动了已验证的部分，
      已重跑一轮（EVAL 第六轮），抽取与推演照常落地
- [x] 意图落进消息（`intentSource: 'planned'`）与生成提示词，界面上用「他这一轮想：」标出；
      会话模式新增「意图先行」开关，关掉即退回纯规则调度（额外调用降到 1 次）
- **证据**：三轮真机——陈九「先不急着辩解，反问玩家在怀疑什么」、小满「不得不表态但不卖人」、
      陈九「上火想顶回去」，三处回复都照着自己的打算落笔；计数印证每回合多出的那一次
      确实被算进「额外调用」

- **验收**：连续追问同一人 5 次，4 次以上由同一人接话 ✅；三角色同场不抢话 ✅；
  意图在界面上可见 ✅（声明式在本模型上不成立、推理流只在推理模型上有——两条已记录原因）

### ✅ T3 P1-5 分层摘要与压缩流水线

- [x] 轮 → **场景场记** → **章节回顾**三层：一场攒够 8 轮或 2400 token 就压一次；
      攒够 3 场有场记的戏就滚成一章（`memory/summary.ts`）
- [x] 触发与解析都是**纯函数**（`shouldSummarizeScene` / `pendingSummary` / `parseSummary`），
      可测、可解释；解析宽容——模型不写 JSON、只写了一段散文也照样收下
- [x] 被压出窗口的原文**永不删除**：摘要只读原文，游标（`scene.recapUpToSeq`）保证
      同一段话不会被统计两遍
- [x] 后台任务 `scene.summarize` / `chapter.summarize`：**判断只在后台做一处**，
      界面只在每轮结算后说一声「来看一眼」；攒不够的那一趟是空跑，不发调用、不记账
- [x] 场记进提示词的场景块（「本场已经发生：…」），章节进独立的「前情提要」块
      （只带最近三章，更早的压成一句「还有 N 章」）
- [x] 界面：场景面板只读显示本场场记与覆盖进度；记忆页列出章节与要点
- [ ] **遗忘机制只做了一半**：召回侧的时效衰减早就有（P1-3），但「低重要度记忆
      合并成粗粒度印象」没做——低分记忆现在只是被排序压下去、被预算挤出去，不会真的模糊
- **来源**：ROADMAP P1-5
- **依赖**：需要先有 50 回合长跑数据（T4）来判断压缩阈值 —— 已具备
- **验证**：EVAL 第七轮（真机 3 轮）——触发成立、摘要保住了硬信息、场记进了提示词、
  攒不够不发调用；顺带修掉「触发判断放在界面侧导致重复调用」

- [x] 顺带修掉两个问题：转写标记自我强化（改为落库前清洗）、一句提两人时冷却决定谁答

### ✅ T21 P1-11 召回评测（结论：暂不做向量）

- [x] 出题—对答案的评测harness：`memory/recall-eval.ts` + `eval/recall-scenario.ts`
      （合成题库 14 条记忆 / 9 道题，含 2 道负向题测视角隔离），进仓库、可复跑
- [x] 真实数据探针：开发页 `apps/web/tools/recall-probe.html` 读本机库里的**真实记忆**，
      用同一套内核实现跑探针
- [x] 真实数据结论（214 条记忆 / 3 个角色）：命题命中 6/6、排名 #1–#2、进预算 100%、
      **串味 0**；没有出现「换了说法就想不起来」的漏召回
- [x] 因此按 ROADMAP 的约定**暂不做向量检索**，并把触发条件写死：
      真实数据上出现漏召回（命题排名 > 3 或进不了预算）才引入
- **来源**：ROADMAP P1-11
- **证据**：EVAL 第五节

### ✅ T22 记忆预算的兜底上限（评测指出的真问题——但和我们最初猜的不一样）

- [x] **先量**：假设是「同一线索反复出现，重复条目把预算占掉」，于是做了近似去重
      （bigram Jaccard），再到真实数据上扫阈值——**任何阈值下数字都一模一样**
      （噪音 5.0、token 778 纹丝不动），一条近重复都没删掉
- [x] **再量一层**：同一题里选中条目之间的**最高相似度平均只有 0.03**，
      而「只靠重要度/时效进来」的条目平均有 5.0 条 → **噪音不是重复，是无关**
- [x] **对症下药**：`limitFallbackItems` —— 有命中的那一轮最多再带两条无关条目；
      一条命中都没有（闲聊、开场白）时保持原样；置顶不算兜底
- [x] 接进线上召回路径（`App.tsx`），评测 harness 也默认按线上口径跑
- [x] 收益（真实数据）：进预算的**相关条目 4.0 → 5.1 条**，命中率与串味率不变
      （86% / 0），平均 token 778 → 769
- [x] 近似去重**没有接进线上**：它在当前数据上一条都没删，留着当探针页的测量工具
      ——「先量了、发现用不上」也是结论
- **来源**：EVAL 第五节（T21 评测 + T22 实测）
- **证据**：EVAL 第五节的阈值表与兜底表

      没填就只报 token、不编价格；只覆盖一部分时标出「N/M 次有单价」
- [x] 世界与本对话两级总计（「这一局大概花多少」），并在运行时面板新增「用量」页
- [x] 副对话的用量也记（管理员一次回合可能跑好几轮工具调用，按轮累加）；

### 🔜 T17 换场时选择「这次带谁去」

### ✅ T17 换场时选择「这次带谁去」 + T10 名单与存在状态对齐

**这两条一起做了**：它们是同一个问题——「谁在这一场里」。

- [x] 换场对话框里新增「这次带谁走」：列出此刻在场的人，默认全选，可逐个取消
- [x] 留下的自动转「在幕后」（`offscreen`），不再被调度、不再进 prompt 的在场名单
- [x] 旁白只记跟着走的人（原来是「秦娘、小满 与 陈九 进入了…」，现在只写实际同行的）
- [x] **内核定下规则：名单是权威，presence 跟着名单走**（`session/presence.ts`）。
      在名单里 → 幕后者转在场（沉默保持沉默、明确离场过的不复活）；
      不在名单里 → 在场/沉默者转幕后
- [x] 同步发生在三个入口：换场、切换对话、新建对话（否则又会出现
      「右栏说在场、这条线的名单里却没有他」的角色）
- **来源**：五十回合长跑（秦娘说要留下看店，却被换场一起带走，随后站在货栈门口发言）
- **验收**：真机验证通过——取消勾选陈九后换场，旁白只写「小满 进入了 河滩旧道」，
      陈九自动变「在场外」，秦娘保持在场外，场景名切到新场

### ✅ T23 滚动归属：对话区自己滚，页面不滚（用户提出）

- [x] 定位：窄视口下 `.app` 的高度等于内容高度（实测 24561px），页面在滚、对话区没在滚
- [x] 病因是改版前的遗留规则 `@media (max-width: 900px) { .app { height: auto } }`
      （`.app` 早已从 grid 改成 flex 外壳，这条没跟着改）
- [x] 外壳固定：`html/body/#root` 撑满 + `body { overflow: hidden }` +
      `.app { height: 100dvh }`（带 `100vh` 回退）
- [x] 窄窗口只把左栏从 300px 收到 240px——试过上下堆叠，对话区只剩 91px 高，不划算
- [x] 顺带核对副对话、运行时抽屉、场景弹层：页面都不滚，各自内部滚
- **来源**：用户在使用中提出
- **验证**：EVAL 第四节——四档视口（1400×900 / 1280×520 / 860×640 / 700×600）
  页面均不滚、对话区均自滚、输入框都在

### ✅ T20 角色的动作主语用名字，不用「我」（用户提出）

- [x] **显示层**改写（`render/segments.ts` 的 `thirdPersonAction`）：动作段里的第一人称换成
      说话人的名字。存的还是模型原本写的东西——记忆抽取与语音归属检测读的仍是原文
- [x] 只改动作段：引号里的「我」一个字不动（那是他在说话）
- [x] 三种不动的「我」：**我们**（复数）、**自我**（构词）、**你我**（对举）
- [x] 同一句里第二次当主语时省略，而不是重念名字；换句子则重新给出名字
- [x] 玩家的动作保持第一人称（你说「我把碗放下」没问题，角色不行）；
      流式气泡与落盘后的渲染用同一套规则，否则生成完的一瞬间名字会跳一下
- **来源**：用户在使用中提出
- **验证**：EVAL 第四节——在那条五十回合长跑会话上直接看已有消息，
  最近 8 段动作里含「我」的有 0 段

### ✅ T19 调用熔断（P1-9 的最后一块）

- [x] 本局预算挂在世界上（`room.budget`）：额外调用次数上限 + 花费上限（需先填单价）
- [x] 到上限只停**生成之外**的调用：意图判断、一轮分析、分层摘要；**角色回复照常生成**
- [x] 熔断检查在**每一趟后台任务开始前**用最新账单重算，而不是信界面渲染时的状态

## 六、建议顺序

```
T1 格式遵守率  →  T2 意图先行调度  →  T4 五十回合长跑  →  T7 成本统计完整化
                      ↓                    ↓
              T10 语义统一（可并行）   T3 分层摘要 / T5 向量召回（由长跑结论决定）
```

理由：T1 与 T2 直接影响「读起来像不像真人在群里说话」，是当前最明显的体验缺口；
T4 是唯一能给 T3/T5 提供决策依据的动作，而它现在只差人工时间与调用预算；
T7 跟着 T4 一起做，成本数据是同一批调用里顺手就能记下来的。
