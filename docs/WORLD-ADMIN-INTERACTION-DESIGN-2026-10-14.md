## 3. 三个方案与推荐

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| 推荐：Codex 风格过程行＋回复＋结果卡 | 每次请求为一个稳定轮次；回复之前用一条轻量状态展示思考/工具，点击展开详情；结果单独标保存与决定状态 | 默认简洁，展开仍能检查连续工具与部分成功；需要补真实生命周期事件 |
| 紧凑状态行 | 保持一条状态，完成后显示现有 artifacts；只改善文案和预览 | 改动最小，可作第一批；不能覆盖执行过程及完整失败记录，不满足最终目标 |
| 独立任务侧栏 | 副对话旁再开常驻工具任务列表、详情及结果区 | 桌面适合大量并发任务，但当前工具串行，手机需来回切换；重复世界/对象/状态信息，不采用 |

推荐的核心是“一轮一条过程入口，展开看过程，结果直接可用”。过程行随真实阶段更新：等待回复→思考中→正在起草「秦娘」→保存中→已完成。用户打开详情后，短进展、供应商实际返回的思考内容、工具动作按事件顺序追加；正文与结果仍在详情之外。计数只表达已收到的动作和结果，不把最多三次模型请求当成三个工具步骤，也不预估还会调用几个工具。

### 4.1 桌面与窄屏共同结构

```text
旧城 / 世界管理                         来源详情
世界管理员

我    起草酒馆老板，补一份旧城世界书，把地点改成露台。

管理员
  ▸ 正在起草世界书「旧城」 · 18 秒             详情

  [展开后]
  │ 思考内容（供应商实际返回时才出现）
  │ 已生成秦娘草稿，等待保存。
  │ ▸ ✓ 起草角色卡「秦娘」                  待保存
  │ ▸ … 起草世界书「旧城」                  执行中
  │ ▸ · 设置场景「露台」                    等待执行
  │   [单个工具再展开：目标、传入字段、返回结果]

  回复（流式追加，与过程详情分开）
  结果（保存前可只读预览，不可采纳）
  角色卡  秦娘                          草稿待保存
  设定摘要                            查看草稿

                         回到最新 ↓（仅脱离跟随时出现）
下一句输入                                      停止生成
```

默认过程行只有左侧原生展开箭头、当前阶段、实测经过时间和“详情”；使用次级文字、无大卡片外框。阶段变化原位替换，不增加多条状态，不以多色 badge 或固定任务仪表盘吸引注意。展开区使用轻量竖线和紧凑行；长思考分块追加，工具行显示动作、对象及状态，点击工具行才看技术详情。底部输入的停止按钮仍是停止生成的入口。

完成态过程标题为“已完成 · 3 个动作 · 24 秒”（仅有真实动作数/总耗时才显示），默认收起；若用户已主动展开则保持展开，允许点击收起。正文后的结果摘要写“2 份草稿已保存 · 1 处场景已生效”。失败/部分完成标题必须写“部分完成”或“结果待核对”，不使用正常“已完成”；关键错误和待核对说明仍在收起行旁可见。结果卡留在可见层，不藏进过程详情。无工具的普通回答可以有等待/思考过程行，只有有据的内容才在详情出现，无空动作列表。

层级顺序：来源（世界/副对话）→ 可展开过程行（思考与工具在同一详情内）→ 回复 → 结果摘要/结果卡。模型正文仍是回复，不能为了模仿风格把累计正文整体改称“思考”。详情的短进展只能来自明确的业务事件或未来明确提供的用户可见进展字段；不额外调用模型生成进度解说。展开工具才显示目标位置、传入字段、工具名、调用 ID、返回说明及原始错误。不展示密钥、Authorization、完整模型请求或整个源快照。字段值使用纯文本，未知工具名和模型内容不作为 HTML 执行。

建议组件边界：AdminTurnBlock（轮次及来源）、AdminProcessDisclosure（过程行及一级展开）、AdminProcessTimeline（真实顺序的思考/业务事件/工具）、AdminActionRow（单工具二级展开）、AdminArtifactCard（实体预览与操作）、AdminDraftPreview（完整只读预览）、AdminBridgeStep（等待贴回）。这些名称是实现建议，当前代码尚无这些组件。保留 admin 独立订阅，避免每个正文分块重画 App 和全历史。

### 4.2 来源与目标

轮次来源绑定 db/账户/世界/副对话/本轮代次，显示名称，详情显示 ID 和准备时间（仅新事件实测时间可用）。同名世界/对话用短 ID 区分；账户可显示已有本机容器名称，不暴露账户秘密。

素材结果卡写“保存位置：当前账户素材库”。场景卡写“旧城 / 开场 / 当前场景”，名称和 ID 来自实际执行选中的目标。开始前目标尚未被代码解析时只显示世界和“设置场景”，获得真实目标后再补齐；不从最近打开的主对话猜目标。

新增目标摘要应从现有选取分支返回只读元数据，不能另写一套选择算法。场景 artifact 当前 targetId 为 null，历史没有记录当时具体主对话/场景目标；旧历史只能写“已生效于当时的主对话”，不提供猜测出来的跳转。当前现场能取得真实目标的结果才显示“查看场景”。

### 4.3 动作折叠

一级过程默认收起；展开后单工具默认只显示“动作＋对象＋状态”，参数和返回值二级收起。过程内事件按真实序号追加，不把工具独立搬成常驻卡片列表。长记录初次展开定位到当前动作，同时保留查看早期事件的滚动入口；用户上滚后不再自动拉回。失败或未使用字段以摘要出现在对应动作和过程标题附近；详细错误可继续展开。

一级和各工具的展开状态由用户控制，正文分块、工具切换和保存交接都不重置。停止/异常后亦保持当前展开状态；只有从未被用户展开的正常完成过程保持默认收起。回复区域稳定追加，不因工具行展开在正文中间插入卡片。已停轮次不把剩余未知步骤计为失败。

## 5. 可观测状态与转换

状态采用三个独立维度：轮次 phase、单动作 outcome、保存 evidence。busy 仅作为互斥依据，不能兼任成功证明。任何“已保存/已生效”都来自实际写入完成或重读确认；正文中的承诺不改变状态。

### 5.1 轮次状态

| 状态 | 唯一合法触发依据 | 显示文案 | 可用动作 |
| --- | --- | --- | --- |
| saving-input | 开始 await 用户消息写入 | 保存消息… | 可继续编辑下一句；禁重复发送；此阶段无 API 停止 |
| preparing | 用户消息写入确认，正在加载/构建真实请求或桥接提示词 | 准备请求… / 准备提示词… | 保留下一句输入；若任务不可取消则不放停止 |
| waiting-model | provider 请求已经开始，尚无正文或推理事件 | 等待回复 · 8 秒 | API 请求可“停止生成” |
| receiving-reasoning | **未来新增** reasoning 活动回调实际到达 | 思考中 · 8 秒 | 点击同一过程行展开详情；API 可停止 |
| writing | onDelta 实际收到正文 | 正在回复 | 正文流式追加；API 可停止 |
| executing | **未来新增**执行前事件，且来源核对通过、execute 已进入 | 正在起草角色卡「秦娘」 | 可请求停止后续生成；不承诺撤销已开始写入 |
| waiting-next-model | 工具结果已回填，实际开始下一次 provider 请求 | 等待后续回复 | 已完成工具继续可查看；可停止 API |
| saving-output | done 后实际进入管理员消息写入 | 保存回复与草稿… | 不开放采纳；禁止重发；写入不可取消 |
| saved | 管理员消息已保存；所有显示保存成功的实体有依据 | 回复已保存 / 2 份草稿已保存 · 1 处场景已生效 | 预览、采纳/丢弃或查看实体 |
| stopped | abort 得到确认，且后续执行已停 | 已停止；已完成的结果保留 | 查看已有结果；新请求按核对规则开放 |
| failed-known | 获得能证实未写入的错误，或工具参数被拒 | 未完成：原因 | 修正输入；只对已确认未执行的请求开放重试 |
| partial | 本轮有确定已完成结果，另有失败/停止/未执行项 | 已完成 2 项，1 项未执行 / 已停止，1 处场景已生效 | 按项查看和处理；不“全部重试” |
| uncertain | 写入可能发生但没有确认，或多段写入中断 | 保存结果待核对 | 只读核对、复制内容；禁止再次提交原操作 |
| saved-read-failed | commit 已返回成功，之后 reload/refresh 失败 | 内容已保存，显示未更新 | 重新读取；不重跑工具 |
| saved-accounting-failed | 内容保存成功后 ledger 失败 | 内容已保存，用量记录未完成 | 查看内容；不重新生成，不猜费用 |

主路径：输入保存 → 准备 → 等待回复 ↔ 正文/真实推理 → 已知工具顺序执行 → 等待后续回复 → 输出保存 → 已保存。停止或异常可在任一支持阶段分叉；最终结论按各实体真实结果汇总，不由最后一次 API 是否成功决定。

桥接主路径：输入保存 → 准备提示词 → 等待贴回 → 校验来源/解析 → 同事务应用有效项与保存消息 → 已保存 → 刷新界面。手动等待不经过 waiting-model/receiving-reasoning/writing。

### 5.2 单工具生命周期与最小新增事件

当前仅 `tool` 结束事件可用。第一批据它显示“调用已结束”，失败必须读取 execution.ok；不可绘制开始/执行中或伪造开始时间。下一批才增加以下可选观测回调，保留现有 text/tool/done 的兼容消费方式：

| 新观测 | 放置位置 | 能证明什么 |
| --- | --- | --- |
| model-request-started | 每次 collect/provider 请求之前 | 正在等待本次模型请求；标真实请求轮数而非工具总数 |
| provider-activity / reasoning-delta | collect 消费实际 reasoning 时 | 确有推理活动/非空推理内容；无内容不建思考区域 |
| tools-received | completion 返回完整 toolCalls 后 | 当前这批已知队列的数量和顺序；不代表工具已执行 |
| tool-validation-result | parseAdminToolCall 返回后 | 参数有效/被拒；拒绝时“未执行”，无需假装执行中 |
| tool-execution-started | 来源/abort 核对通过，进入 execute 之前 | 动作真的开始；携带可得的对象、目标和本地开始时间 |
| tool-execution-ended | execute 返回/抛错，现有 tool 事件处 | execute 返回、失败或待核对；返回字符串本身不足以证明业务成功 |
| output-save-started / confirmed | appendMessages 开始/返回 | 管理员消息与草稿的保存状态；confirmed 可关联实际 messageId |
| effect-confirmed | saveScene 返回、桥接事务返回、采纳/撤回写入后重读 | 场景/素材是否实际保存以及目标；不得在事务内部写入返回就发布桥接成功 |

工具列表状态：已收到→校验→等待执行→执行中→结果。校验拒绝直接到“未执行”；生成 draft 到“草稿已生成，待保存”；saveScene 确认到“场景已生效”；失败涉及多段保存则“待核对”。队列里已知且未开始的动作在停止确认后可标“未执行”；未知的未来模型动作不建空项。

每个事件带 scope/runKey/单调序号，tool 带 callId 和所属模型请求序号；同轮连续调用按收到的顺序显示，不并发重排。同工具同对象再次调用显示为独立项，本轮不启用生产去重。runKey 是本地展示隔离键，不是服务端幂等票据。当前用户消息与管理员消息各自创建 turnId，不能假设二者共享 turnId；新展示关联必须在实际创建时明确记录。

toolName 人话映射：upsert_character_card→起草角色卡，upsert_world_book→起草世界书，upsert_persona→起草身份，delete_persona→起草身份删除方案，set_scene→设置场景。起草阶段的删除身份绝不能显示“身份已删除”。未知工具写“未执行：不支持的工具”，名称留详情。

### 5.3 思考区域：按实际能力降级

当前版本：没有思考区域；请求已发出且未收到正文时显示“等待回复”。不要固定写“正在思考”，不要生成一段替代推理，也不让模型多调用一次来解释进度。

如果后续接通真实 reasoning-delta：首次非空内容后过程行显示“思考中”，点击同一行查看实际内容。思考与工具处在同一个过程详情中，不另做一个独立的思考面板；随后工具开始，行标题原位更新为工具动作，之前已收到的思考留在展开记录里。区域标“本次生成可查看”，只呈现供应商返回的内容，不当作已执行动作或保存依据。结束后停止追加，下一次模型请求按请求边界形成下一段；没有推理字段的模型没有思考块，过程详情仍可展示真实工具活动。此设计不承诺供应商一定返回，也不将模型声明的计划当作工具队列。

推理首批只驻内存，不进 Message、素材库、同步和封存，切离所属范围后销毁；刷新不伪造历史推理。“思考中”仅在收到真实 reasoning 活动且无正在执行工具时使用，等待期间标题仍为“等待回复”。过程详情桌面建议最多约 360px、窄屏不超过当前可见区域的一半，长内容独立滚动；其内部流式更新不推动外层整页自动滚到底。少量内容自然展开不设空白高度；减少动效时不逐字闪烁。该尺寸为本提案的设计值，不是 Codex 产品规格。

### 5.4 耗时

已发请求或实际开始工具后显示本地经过秒数，状态切换保留各自开始时间。超过 12 秒无新的可观测事件补“暂未收到新内容”；超过 45 秒提示“可以继续等待，或停止生成”。不是服务器心跳证明，也不是超时/断线判定，不显示百分比、ETA 或预计 token 数。真实 timeout 到来才显示失败。

手动桥接等待不限时、不转圈、不自动失败：“等待你贴回回复”。本地助手若只暴露 /ask 的 Promise，只能写“等待本地助手返回”，不能写“网页版正在思考/已发送”。

## 6. 结果卡与草稿操作

### 6.1 具体布局和文案

| 类型 | 默认可见 | 展开预览 | 主动作与结果 |
| --- | --- | --- | --- |
| 角色卡 | `角色卡 · 秦娘`，新建/修改，设定首段，`草稿已保存 · 待采纳`，账户素材库位置 | 完整设定及实际存在的卡片字段；不恢复已删除的开场白字段 | `查看草稿`、`采纳`、次级`丢弃`；成功`已采纳 · 已保存到素材库`、`查看素材` |
| 世界书 | 名称、新建/替换、条目数量，前 2 条标题和短内容 | 全部条目、关键词和实际字段；已有 ID 的整份覆盖提示 | `查看草稿`、`采纳`、`丢弃`；“将整本替换素材库中的「旧城」，不会追加条目” |
| 身份创建/修改 | 名称、设定摘要，`身份草稿 · 待采纳` | 完整身份设定；明确当前操作是新建还是修改 | `采纳`；不表示已切换为当前玩家身份 |
| 删除身份 | 名称、`删除方案 · 待确认`，`确认后删除素材库中的身份；此处不能撤回` | 被删除对象的现有可读信息 | 危险动作`确认删除身份`；成功`身份已删除`，无撤回入口 |
| 场景已应用 | 名称、实际世界/主对话目标、地点/时间/设定中实际修改的字段，`已生效 · 已保存` | 实际 patch；只有执行前真实捕获过旧值才做前后对照 | `查看场景`（目标有据时）；没有采纳/撤回按钮 |
| 场景缺主对话 | `未应用：这个世界还没有主对话`；仍展示原建议 | 原场景建议 | `新建主对话`、`复制设置要求`、`丢弃`；新建后由用户发新请求，不自动重放旧场景 |

预览只读，用现有 DialogShell；桌面约 720px 宽且不越屏，窄屏全宽可滚动。标题固定标对象、来源和状态，按钮区始终可达；Esc 关闭，回焦到原预览按钮。打开预览不中断生成，也不自动切换世界；若对象来源已不匹配，操作区禁用并显示原因。差异视图只用于真实旧值已保存的字段；不能拿当前素材与旧草稿假称“生成时的改动”。

待保存的内存 draft 可以只读预览或复制，但采纳/丢弃禁用，写“草稿尚未保存”。只有 appendMessages 返回并且 artifact 可在对应消息重读到后，进入可决定态。场景成功与对应消息是否记录分别显示，避免把场景成功误报为记录成功。

### 6.2 单卡状态转换

待决定→采纳中→已采纳；待决定→丢弃中→已丢弃；已采纳→撤回中→待决定。单卡操作期间锁该轮同一份结果的互斥写操作；沿用生成 busy/归档时禁写契约。其他结果仍可查看，输入仍可写。

每次操作等待实际 Promise，先更新“采纳中…”等本地状态，只有写入及状态核对成功才改变最终 badge。异常保留预览和原状态；不确定先核对 artifact 状态和目标实体，不能在 catch 后直接开放“再采纳”。刷新失败则“已采纳，列表未更新”，按钮为“重新读取”。没有明确提交结果时不把可重复点击等同于 Repository 的幂等保证。

版本冲突：`素材已在起草后修改，这份草稿不能直接采纳。` 显示`查看草稿`、`丢弃`、`复制重新起草要求`，禁采纳；详细版本时间在展开项。不自动发新生成请求，不强制覆盖。discarded 只改状态保留记录，文案为“已丢弃”，可展开内容；本轮不增加“恢复丢弃草稿”能力。

### 6.3 撤回必须与真实语义一致

卡/书撤回前显示具体确认：`撤回会删除素材库中的「秦娘」，包括采纳后对它的修改；草稿会回到待采纳。` 主按钮“删除素材并撤回采纳”。即使这份草稿原来修改的是已有卡/书，当前实现也不会恢复旧版，界面不得写“恢复原版本”。

身份修改有 previousPayload 时：`撤回会恢复采纳前的身份内容，并覆盖之后的修改。` 新建身份：`撤回会删除这份身份，草稿回到待采纳。` 按实际 previousPayload 分支。删除身份及 applied 场景不提供此入口。确认弹窗使用实际对象 ID，不按名称匹配；预览已过期则先只读核对。

若未来要改变撤回为版本安全恢复，属于另一个数据语义任务，不能夹带在本轮 UI 实施中。

## 7. 手动网页版桥接

桥接作为当前轮次的一段放进对话阅读区，替换现有占据大量固定底部空间的完整表单；底部仅保留“等待贴回”的紧凑入口及可编辑的下一句草稿。下一句发送禁用并有可见理由，不靠 hover title 说明。用户查看历史时仍可一键回到贴回步骤。

```text
等待贴回回复                    旧城 / 世界管理
1  复制提示词        [复制]  [打开 DeepSeek 网页版]
   复制成功：已复制；失败：复制失败，可展开后手动复制
   ▸ 查看提示词（2571 字）
2  贴回回复
   [整段回复粘贴框，包含工具 JSON]
   [应用回复]                      [放弃这次起草]
   应用回复会直接设置场景；角色卡、世界书和身份仍需采纳。
```

“已复制”只由 clipboard write 成功触发；打开链接只能证明链接点击，不能把第 2 步标为“网页版已完成”。回焦自动填空框可沿用，但需要小标签“已从剪贴板填入，请核对”，绝不自动应用；用户原文不被覆盖。粘贴换来源/阶段的隔离继续按 sourceKey；原来源的未提交粘贴可仅驻对应 scope 内存，重开不承诺恢复。sessionStorage 恢复的是桥接提示词/来源，当前不是粘贴全文持久保存。

点击应用后：先禁同一来源的应用/助手/放弃按钮，冻结本次 raw；标签“校验来源…”→“应用并保存…”。当前 commitAdminSource 把解析、校验、事务合在 Promise 中，第一批只能统一写“应用回复…”；下一批真实回调才能拆阶段。事务期间无“停止”按钮；普通 Composer 不沿用 API 停止形态。没有前置执行预览就不把按钮命名为“预览”；本轮不新增“先解析出可编辑草稿再第二次执行”的流程。

成功提示按 artifacts 和解析 notes 汇总：`2 份草稿已保存 · 场景已生效`，或`1 项已保存，2 项未执行`。有效项同事务提交，未知工具/无效参数未执行；没有工具但有正文可以是合法普通回复，显示“回复已保存，未修改素材或场景”。格式畸形在现有解析器可能成为纯正文，不设计成“一定会抛解析错误”；只能依据实际 parse 结果反馈。

来源过期：`准备提示词后，来源内容已变化。这份回复未应用。` 保留粘贴内容可复制，禁再次应用旧来源；可回原来源核对，或明确放弃再准备。账户切换后隐藏其他账户的正文、prompt 和剪贴板内容，只在所属账户显示恢复入口。缺有效 binding 的旧进度只能放弃重建，不补造来源。

放弃只关闭未应用的桥接，不删除已经保存的用户消息，也不撤销已完成结果；有粘贴内容时用 DialogShell 明确“放弃未应用回复”，提供取消。空粘贴可以直接放弃，不增加确认。返回历史/关闭预览不是放弃。

本地助手沿用可用性探测规则，保持为次级入口。将助手提交与手动应用置于同一个来源锁；返回文本先填入供核对，复用明确的“应用回复”，取消现有自动 onAdmin 的迟到应用。等待时可以选择“改用手动贴回”，这仅使当前助手回调失效，不宣称远端网页停止。/ask 没有取消确认接口，不能承诺撤销已发送网页请求；结果不明时不自动再次调用助手，先去网页核对。助手异常不清手动文本，长期等待显示本地 elapsed，不猜测页面状态。

## 8. 停止、重试与结果待核对

“停止生成”只用于活跃 API 模型生成阶段。点击立即写“正在停止…”，禁重复点击；收到 abort/执行边界确认后写“已停止”。已进入写入的动作可能完成，使用“停止后续生成，已完成改动保留”的邻近说明。停止不丢弃已经保存的草稿，也不回滚场景。写用户消息、保存输出、桥接事务、采纳/撤回事务或多段写入时，不提供无效的取消按钮。

重试分为：重新读取、重新保存未提交的内存回复、重新生成一个新请求。不能把它们都叫“重试”。当前系统没有通用 operation 票据、跨刷新幂等请求或可靠的每轮持久执行记录，因此默认不提供“重试这一轮”或“全部重试”。

| 情况 | 下一步 |
| --- | --- |
| 输入确定未保存 | 保留原输入，可“重新发送” |
| 输入保存结果未知 | “查看消息记录”；先按实际 messageId 重读，确认不存在且无执行才可重发；未能确认时继续禁原操作 |
| 输入已保存、API 在工具前失败且确认无副作用 | 可发新请求；若提供“重新请求回复”，必须复用已有用户消息，不重复 append 输入，且该能力在实施前单独完成接线 |
| 参数校验失败 | “修改要求”；失败动作显示具体字段；只有用户新请求才重新尝试 |
| API 场景已保存、后续模型失败/停止 | 保留场景已生效结果；新请求只处理未完成项，无全部重放 |
| 草稿仍在内存，输出保存明确失败且未写入 | “复制草稿”；有保存接口并复核来源/消息不存在后才可“重新保存回复”，不再调用模型/工具 |
| 保存可能成功、或采纳只完成实体保存未更新消息 | “核对保存结果”；重读对应 message/artifact/目标实体，不能直接采纳或重新生成 |
| 桥接事务成功、刷新失败 | “重新读取”；不再把同一粘贴提交到 commitAdminSource |
| 本地助手结果未知 | “查看网页版回复”；不自动再发送网页请求 |
| 用量记录失败 | 内容维持已保存；本轮不新增费用推算或自动重复 ledger 记录 |

“核对”只读取已绑定账户/世界和实际已知 ID；名称相同不能证明已执行。核对不得发新模型请求或再执行工具。无法确认某一项时保留“待核对”，不能靠查不到当前 UI 卡片断言没保存。桥接历史源指纹失效可防再应用旧源，但它不是对所有 API/采纳路径的幂等承诺。

## 9. 滚动、手机、键盘与减少动效

跟随以用户意图为准：发送可到最新，贴底时文本、工具项、结果卡、保存交接增长均跟随；用户向上查看历史、选中文字或打开预览后，阅读锁保持。显示“有新内容 · 回到最新”，只展示是否新增而不逐 token 计数。用户按该按钮或确实滚到底才恢复；工具折叠、错误展开、状态终结不主动夺走滚动位置。展开历史动作保留标题在视口中的位置；不因新卡片重新滚至底部。

延续 handoffId：同一条管理员消息进列表后，在同次提交替换流式正文，不闪空或重复。错误/停止不先清空半截正文；本轮至少保留在所属 scope 内存中可复制，标“未保存”。持久化未完成正文涉及新的数据语义，另行批准，不在首批偷偷写入 Message。

窄屏按副对话容器宽度布局，建议 <600px 堆叠卡头/来源/按钮，320px 必须无水平溢出。动作目标允许换行，ID/JSON 在详情内断行，不缩小正文。点击区域至少 44px；按钮不用 hover 才能看见。预览和桥接粘贴可独立滚动，避免聊天、固定桥接大表单和普通输入产生三重滚动；手机桥接粘贴时下一句输入收为“下一句草稿”入口，保留内存文字，完成后展开。

软键盘出现时保证粘贴框/采纳确认的主动作可达，尊重安全区，不以固定 vh 强压正文。桌面 Enter 发送、Shift+Enter 换行、IME Enter 不提交、粗指针 Enter 换行沿用既有规则。预览的 Enter 不发送聊天；Tab 顺序为正文操作→动作详情→结果操作→输入；折叠用原生 button/summary 和 aria-expanded，触发后焦点不跳。Esc 仅关闭最上层预览/确认，不停止生成、不丢弃草稿。

状态使用图标＋短文字，不仅依靠颜色；错误靠近所属轮次/工具/卡片。阶段变更以 aria-live=polite 播报一次，失败用 role=alert；不逐 token、逐秒或逐个等待点播报。完整预览不塞进 live 区域。prefers-reduced-motion 时取消滚动动画、呼吸/闪烁和逐字动画，仍按收到的分块更新正文；状态不会因此少显示。

## 10. 历史、恢复与可交付能力边界

当前持久事实是 Message.content、artifacts 及各实体；没有完整工具 trace、模型请求时间线、推理或失败动作列表。首批不从正文或 artifact summary 倒推历史工具调用，也不把旧 artifact 当成真实 callId。

第二批生命周期记录仅驻本次打开的 scope 内存：同账户/世界/对话内切历史可查看，换账户立即不可见；刷新后展示持久正文与结果卡，无法恢复的动作过程直接不显示。工具动作详情标“本次打开期间的记录”，不承诺跨设备或重开可用。这样可先完成过程反馈且不迁移数据库/同步/封存。

如评审要求刷新后还要保留失败动作和顺序，单列第三批数据设计：仅持久化动作摘要、目标 ID、明确结果及记录完整性，不保存 raw reasoning/参数/完整响应。需分别评审旧消息兼容、同步合并、封存导入、删除和源绑定；不能把 proposed trace 当成已存在接口。本轮不授权此持久扩展实施。

来源切换时终止旧 API 后续执行、取消旧 UI 发布；已保存结果仍归原范围。迟到失败也按 scope 过滤，不能在 B 世界显示 A 的 error。已知源切换守卫继续保留，不把 UI 的名字/标签当作执行授权。源变化后新请求不消费旧 stream 或旧草稿操作。
