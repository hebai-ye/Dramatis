# 评测与验证

这份文档记录「怎么知道它真的能工作」。分两部分：可以随时重跑的自动化基线，以及必须用真实模型做的人工验证。

## 一、自动化基线

`packages/core/src/eval/baseline.test.ts` 走的是真实的调度、装配、召回、抽取、落库管线，**只有模型是脚本化的**。目的是把工程约束变成可重复的断言，而不是靠肉眼看着办。

```bash
pnpm --filter @dramatis/core test baseline --reporter=verbose --silent=false
```

### 结果（2026-09-16）

**长跑场景**：两角色同场 + 一名全程在幕后的角色，50 回合。

| 指标 | 值 |
| --- | --- |
| 回合数 | 50 |
| 消息数 | 100 |
| 记忆条目 | 147 |
| 触发预算降级的回合 | 0 |
| 单轮最大提示词 token | 1816 |
| 发言分布 | Alice 25 / Bob 25 |

**压力场景**：60 条超长历史 + 2048 窗口 + 1024 保留回复。

| 指标 | 值 |
| --- | --- |
| 可用预算 | 1024 |
| 实际占用 | 788 |
| 丢弃区块 | 38 |
| 触发阶段 | `drop-history` |
| 保留消息数 | 4 |

### 它验证了什么

- 任何一轮都不超预算；降级触发后仍然产出可用的 prompt（system 在、玩家输入在）
- 每一轮都为每个在场角色各留一条视角记忆
- 幕后角色不会被调度上台，也拿不到任何记忆
- 召回只返回该角色自己的视角条目，不串味
- 两角色 50 回合的发言分布正好 25 / 25，公平性机制确实在起作用
- 重抽回滚：删掉一个回合的记忆后，引用该回合的条目一条不剩

### 它没有验证什么

对话质量、真实模型的 JSON 稳定性、实际 token 成本。这三件事必须有真模型才能量。

## 二、真实模型验证（手工，约 2 分钟）

我无法在当前环境里完成这一步：浏览器自动化不可用、没有 API Key、也没有本地模型。所以需要你来做一次。

### 步骤 1：把下面两段喂给 DeepSeek

第一段作为系统提示（网页版没有系统提示的话，把两段连成一条发出去也一样）。

```text
你是一个叙事记录员。阅读刚发生的一段对话，然后只输出一个 JSON 对象。
不要写解释，不要写代码块标记，除了那个 JSON 对象什么都不要输出。
```

```text
地点：旧城东侧的酒馆
时间：第三日 · 黄昏
玩家扮演：旅人
在场角色：Alice、Bob

对话：
旅人：听说北边那支商队失踪了，你们知道些什么？
Alice：……我不太想聊这个。
Bob：她上个月还托那支商队捎过一封信。

字段要求：
- summary：客观描述发生了什么，一到三句，不要写角色的内心。
- importance：0 到 1。改变了关系、暴露了秘密、推进了情节的，给高分；寒暄与日常给低分。
- location：只有对话里明确发生了地点变化时才填，否则留空字符串。
- observations：为每个在场角色各写一条，描述他在这个视角下注意到了什么、
  误解了什么、在意什么。同一件事在不同角色眼里应当有差异，允许互相矛盾。
  没有明显反应的角色可以省略。speaker 必须用上面给出的角色名。

输出格式：
{"summary":"客观经过，一到三句","importance":0.6,"location":"","observations":[{"speaker":"角色名","perception":"他的印象"}]}
```

### 步骤 2：判断输出

合格的输出是一个干净的 JSON 对象，字段齐全，`observations` 里两人各一条**且内容明显不同**——比如 Alice 留意的是对方的回避，Bob 留意的是那封信。

不合格的典型形态：

- `observations` 为空，或者两个角色的 perception 内容雷同（说明没理解「视角」的意思，需要加强提示词）
- JSON 被截断（输出长度不够，需要提示模型不要啰嗦）
- 只输出了一段自然语言描述（解析器会报「没有找到 JSON 对象」）

轻微的前后废话**不算问题**：解析器按花括号配对扫描，容忍代码块标记与开场白。

### 步骤 3：把输出贴回来

把模型输出原样发给我，我用 `parseExtraction` 实际跑一遍，确认能否解析；不能解析就针对性调提示词。

## 三、端到端对话测试

要跑完整的端到端（真的聊出内容、看着记忆累积），需要一个 OpenAI 兼容的接口。注意 **DeepSeek 网页版账号不含 API 额度**，需要单独在开放平台充值才能拿到 Key。

拿到 Key 之后在应用的「模型接入」面板填 `https://api.deepseek.com` 与模型名 `deepseek-chat`，就可以：

1. 导入两三张卡，让它们同场
2. 聊十几轮，中途让某个角色离场再回来——他应该不记得离开期间发生的事
3. 打开记忆面板，对照「客观经过」与各角色「眼中的事」，确认存在合理差异
4. 改一条记忆，确认下一轮角色按改过的版本说话
5. 重抽一次，确认该回合的记忆被撤销且没有留下残余
