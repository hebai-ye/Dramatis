# 界面与交互规格

> 来自手绘草图与逐区域填写，记录「界面长什么样、怎么动」。实现以此为准；与当前实现有偏差的地方见文末差异表。

## 骨架

```
┌────────────────────────────────────────────────────────────┐
│ [折叠]  顶栏（预留：未来的世界视图）                        │
├──────────────┬─────────────────────────────────────────────┤
│ 新建对话      │ 世界名 · 对话名 · 在场角色      [主/副对话] │
│              ├──────────────────────────────┬──────────────┤
│ 世界与对话列表│                              │              │
│ （可滚动）    │  对话流                      │  角色栏      │
│              │                              │  （可拖入）  │
│              │  ┌────────────────────────┐  │              │
│ 设置          │  │ 输入                + │  │              │
└──────────────┴──└────────────────────────┘──┴──────────────┘
```

## 各区域职责

### 顶栏

- **左上角**：折叠左栏
- **其余部分**：目前未设定功能。**预留**给未来的「世界视图」——以节点网络蓝图显示角色、物品、事件之间的联系

### 左栏 · 顶部

四个按钮：

1. **新对话**
2. **查看已有世界书**（导入 / 删除世界书）
3. **查看已有角色卡**（导入 / 删除角色卡）
4. **创建** —— 走副对话，由 AI 帮忙起草，用户决定去留

也就是说素材管理（导入、删除、手动微调）留在左栏顶部，**从零创建走副对话**。

### 左栏 · 中间（可滚动）

- 层级是 **世界 = 项目**，一个世界下可以开**多个对话**
- 支持**归档对话**：把情绪、关系、记忆**回滚到该对话开始之前**——相当于这条时间线没有发生过，但对话本身被保留
- 归档后的对话不在主列表里，改从**设置**中打开

### 左栏 · 底部

设置，用于配置 API 等；**已归档的对话也从这里打开**。

### 主区 · 标题栏

显示当前世界名与对话名；显示当前场景内的角色，实时刷新。

### 主区标题栏 · 右上控件

切换**主对话 / 副对话**状态。

### 主区 · 内容

**主对话状态**（角色扮演）：

- 类似 QQ 群聊：圆形头像、名字、对话内容
- 对话内容用正常聊天气泡
- **角色动作用 `#` 新开一段，且不在气泡内**
- 一段话里掺杂动作时切分成多段：对话 → 动作 → 对话
- 长对话可以拆成多个短气泡，以显出真人感

**副对话状态**（世界管理）：

- 界面上是「世界管理员与用户」的对话
- 内容是正常的 AI 工作流：创建角色、创建设定
- **不用气泡**
- 管理员产出的角色卡、世界卡由用户决定去留
- **需要真实调用工具**
- 此时 AI 不是任何角色

### 输入区

- 开启新对话时：投入**世界卡**与零或以上角色卡
- 「世界卡」就是世界书，不是另一种资产
- 底部一排按钮，其中：
  - **加号**：设置当前对话模式
  - **场景**：输入 / 切换当前场景
- 切换场景后，产生一条**旁白式动作**：没有对话气泡、也不属于任何角色，形如「××× 与 ××× 进入了 ×××」。它记录的是「谁跟谁去了哪里」，而不是谁说的话
- 对话模式包括：
  - 是否所有角色必须在主角发言后才能发言
  - **静默模式**：主角长时间对话期间，其他角色只能做动作；关闭后其他角色开始说话

### 右缘窄栏

- 显示各角色
- 把角色从这里**拖进对话**，角色进入当前场景
- 在这里打开角色，显示角色详细信息

**这一栏是真实存在的**，不是草稿纸格线。

## 与当前实现的差异

**已全部落地**（2026-09-16）。改版前是「设定侧边栏 ｜ 对话 ｜ 运行时面板」三栏，
且房间既是世界又只有一条对话线。

| 需要的能力 | 落地情况 |
| --- | --- |
| 顶栏左上角折叠按钮 | 顶栏收窄，只剩折叠按钮，其余留给世界视图 |
| 世界 → 多个对话 | `Conversation` 实体；Room（世界）持 `activeConversationId`，场景与消息归属对话；schema v3 迁移给旧数据补出「主线」 |
| 归档对话与影响索引 | `repository.archiveConversation`：按对话开始时的状态快照还原情绪与关系，按 `conversationId` 整批撤销记忆，对话本体保留 |
| 主对话 / 副对话 | `Conversation.kind`；两条独立记录，消息各带 `conversationId` |
| 副对话的真实工具调用 | `admin/tools.ts` 三个工具 + `admin/turn.ts` 的「请求 → 执行 → 回填 → 再说话」循环；provider 支持 `tools` / `tool_calls` |
| 动作 `#` 分段渲染 | `render/segments.ts`：`#` 另起一段且不进气泡，长对白按句切气泡 |
| 会话级模式（静默等） | `Conversation.modes`，并落成 prompt 里的指令 |
| 右栏角色拖入 | 角色栏拖拽入场（`text/dramatis-instance`），点击开角色详情 |
| 世界卡 | 确认为世界书本身，新对话时与世界书一起投入 |
| 左栏三段结构 | 四按钮 / 世界与对话列表 / 设置，三段齐备 |
| 世界视图蓝图 | 仍是未来：顶栏除了折叠按钮什么都没放 |

## 待确认

全部已定，无遗留问题：

1. **世界卡＝世界书**，不是独立资产
2. **归档**＝把情绪、关系、记忆回滚到该对话开始之前；对话本身保留，从设置中打开
3. **素材管理**在左栏顶部的两个按钮里，**从零创建**走副对话
4. **副对话的工具集**先只做三件：起草/修改角色卡、起草/修改世界书、设置当前场景
5. **主对话与副对话是两条独立记录**，各有各的历史；副对话的形态更接近 AI 工作流
6. **切换场景**产生一条无气泡、无角色归属的旁白式动作，形如「××× 与 ××× 进入了 ×××」

## 实现时的取舍

规格里没写到、但实现时必须定的几件事，记在这里免得以后靠猜：

1. **草稿先挂在消息上，采纳才进素材库。** 管理员调用工具时会真的产出内容，
   但在用户点「采纳」之前，角色卡与世界书只以 `AdminArtifact` 的形式挂在
   那条消息里。丢弃只是改状态，不删记录。
2. **`set_scene` 落到主对话上。** 副对话自己没有场景线（管理员不参与剧情），
   所以这个工具作用于这个世界最近的一条主对话；主对话还没有场景时会顺手开一个。
3. **归档不可撤销。** 归档就是「这条线没有发生过」，没有「取消归档」按钮——
   要重来就开一条新对话。被归档的对话可以在设置里回顾与删除。
4. **拖角色入场不写旁白。** 规格里只有「切换场景」会产生旁白；把角色拉进来
   只是一次在场状态变更，保持安静。
5. **长对话拆气泡只按句子边界切**，单句本身超长时不再细切——宁可留一个长气泡，
   也不要把一句完整的话切碎。
6. **对话模式通过 prompt 指令生效，不改调度结果。** 静默模式若直接让调度器
   不选人，角色就会彻底失声（用户发一句话什么回应都没有）；现在它是一条
   「只能说动作」的指令，接话的人还是照常选出来。
7. **左栏顶部多了一个「导入素材」按钮。** 规格写的是四个按钮（新对话 / 世界书 /
   角色卡 / 创建），而素材管理的「导入」需要一个入口——它既不属于世界书面板
   也不属于角色卡面板（同一个文件两种都可能）。所以单独放一个按钮，按文件
   结构自动分辨，不违背「素材管理留在顶部」这条。
8. **动作分段以「引号」为准，`#` 是等价写法。** 规格要求动作用 `#` 另起一段，
   实现也照做了；但真实模型（DeepSeek）在规则、正反例、现场示范、卡内示例全部到位
   的情况下仍然不给动作加标记，只在一点上稳定——**对白永远带「」引号**。
   所以渲染改成：消息里出现过引号时，引号内算对白、引号外算动作；`#` 仍然支持且优先。
   两种写法渲染结果一致，规格里要的「动作不在气泡内」因此才真正成立。
9. **名单是权威，角色的存在状态跟着名单走。** 规格里右栏是「把角色拖进对话，角色进入
   当前场景」，也就是以**当前场景的名单**为准；而实例上另有一个「它在这个世界的状态」
   （在场 / 沉默 / 幕后 / 离场）。两者脱节时会出现自相矛盾的局面（右栏说在场、名单里
   却没有他；换场把留在店里的人也一起带走）。现在定了规则：**在名单里就算在场，
   不在名单里就转幕后**；沉默保持沉默、用户明确标过「已离场」的不被名单复活。
   换场对话框因此多了「这次带谁走」，默认带走此刻在场上的人。
10. **对话模式多了一个「意图先行」开关（缺省开）。** 规格里的模式菜单只有「玩家先开口」
    与「静默」两项，实现时加了第三个：生成前先用便宜模型问一次「这一轮谁开口、他想做什么」。
    它让角色照着自己的打算落笔（T2c 的三轮真机证据），代价是每回合多一次调用——
    所以做成开关而不是写死：想省调用的 BYOK 用户关掉它，就退回纯规则调度
     （额外调用从 2 次降到 1 次），其余体验不变。
11. **运行时面板多了「用量」一页，设置里多了「单价」两个输入框。** 规格里的运行时面板
    只有场景、记忆、Prompt 三块，但「这一局花了多少」既不属于任何一块：场景讲现在在哪、
    记忆讲记得什么、Prompt 讲这轮发了什么。所以给它单独一页（世界 / 本对话两级总计，
    按用途、按角色、按模型三张分组账）。单价放在「模型接入」里跟着草稿式保存按钮一起落库
    ——它是这条配置的属性，不是一份全局设置；两家模型不同价时也能各自记各自的账。
12. **场景面板多了一段只读的「本场场记」，记忆页多了一段「前情提要」。** 规格里
    「场景设定」是人写的简介（来自角色卡的 scenario），场记是后台自动整理的
    「这一场到目前为止发生了什么」——两者混在一起会互相覆盖，所以分开存、分开放：
    设定留在可编辑的输入框里，场记只读显示，并标出「覆盖到第几条消息、什么时候整理的」。
    章节回顾放在记忆页顶部，因为它就是粗粒度的情节记忆。
13. **角色的动作主语用名字，不用「我」。** 规格只写了「动作不进气泡」，没说主语是谁；
    真实模型默认写成第一人称（「我把斗笠往上一抬」），读起来像角色在自己念旁白。
    所以显示时把动作段里的第一人称换成说话人的名字——引号里的「我」不动（那是他在说话），
    玩家自己的动作也保持第一人称。改写只发生在显示层，存的仍是模型原本写的内容：
    记忆抽取与语音归属检测读的是原文，不会因为这条渲染规则丢掉证据。
14. **「用量」页多了本局上限（熔断）。** 到上限只停**生成之外**的调用
    （意图判断、一轮分析、分层摘要），角色回复照常——聊到一半突然说不出话，
    比多花几分钱糟糕得多。上限按世界存，放在用量页而不是设置里：它是这一局的账，
    和旁边的数字是同一件事。
15. **整个应用是固定外壳，滚动只发生在内层面板里**（修一个遗留 bug）。规格里没写这一条，
    但它是「像聊天软件」的前提：滚动位置属于对话区，不属于页面——页面跟着滚，顶栏、
    输入框、两侧面板就会一起跑掉。实测原因是窄窗口下的一条遗留规则
    （`.app { height: auto }`，改版前 `.app` 还是 grid 时留下的）：宽度 < 900px 时外壳
    跟着内容长高，五十回合的长跑把 `.app` 撑到了 24561px。现在 `html/body/#root` 撑满、
    `body { overflow: hidden }`、外壳用 `100dvh`（带 `100vh` 回退），窄窗口只把左栏
    从 300px 收到 240px——两栏仍然并排：曾经试过上下堆叠，结果对话区只剩 91px 高。
16. **设置里多了一段「封存（导出 / 导入）」。** 规格把「归档的对话从设置里打开」放在这里，
    而封存与它同类——都是「我的数据在哪、怎么带走」。导出按钮在世界打开时才可用
    （没有世界就没什么可导），导入永远是新建一条世界线并自动打开。
17. **手机上左栏是抽屉，右缘角色栏让位。** 规格画的是桌面三栏；640px 以下没有并排的
    空间（左栏 240px + 角色栏 104px 之后，对话只剩一条缝），所以左栏默认收起、
    点顶栏的 `≪` 打开成抽屉盖在对话上，右缘角色栏在这一档隐藏——此刻在场的是谁，
    标题栏里已经写着。桌面行为一个字没改。
18. **设置里多了一段「本机存储」。** 数据存在浏览器里，而浏览器默认可以清掉它，
    所以把「存储后端 / 有没有拿到持久化 / 已用与配额」摆出来，并给一个
    「申请持久化存储」按钮；拿不到时如实说明怎么才拿得到（装到桌面或加收藏，
    也就是 PWA 那条路）。
19. **记忆面板有**两个**筛选维度，外加一个对照视图（T11）。** 规格里记忆页只说了
    「按角色筛」，但记忆是世界的、对话是多条的：三条线的记忆平铺在一起，用户看不出
    「这条是哪条线里的」（真机上打开主线时面板里躺着 72 条，其中 30 条来自另一条对话）。
    所以做成**对话 × 视角**两个下拉，互不干扰；默认停在当前打开的对话（「我这条线里
    发生了什么」是最常问的），切到「全部对话」时每条记忆带归属标签。
    另加一个「对照」视图：按轮把「客观经过 + 各角色眼中的说法」摆进一张卡——
    「同一件事各人记成什么样」是多角色最值得看的东西，平铺着看会被几十条隔开。
    多出来的一件事是**「跳到原句」**：记忆条目按 `sourceTurnIds` 找回那一轮，切回它所在的
    对话并把那句话高亮出来。规格没写，但「能点回出处」是记忆面板该有的底气。
20. **归档的提示条带一个按钮，归档的对话能导出正文（T12）。** 归档之后对话就不在主列表里了，
    规格说「从设置里打开」——照着做了，但用户下一刻还是得自己找，于是提示条上给了
    「去看这条对话」。另外规格没提「怎么把归档的对话带走」，而「只在应用里能看」的回顾很脆弱，
    所以设置里每条归档对话都能「导出正文」：Markdown，抬头写明世界 / 归档时间 / 条数，
    正文按场景分段。**「取消归档」仍然不做**（语义是「这条线没有发生过」），
    但界面上把理由写出来，并指向导出——「不能撤销」与「能带走」是两件事。
21. **没有 API Key 时走「网页版桥接」，而不是报错。** 规格里没有这一条，它来自真实使用：
    第一次打开网址的人手里没有 Key，而应用在发送时直接拦一句「还没有填 API Key」——
    要先注册、充值、建 Key 才能看看这东西好不好玩，这道门槛挡掉的正是最该留下的人。
    现在的形态是：发送按钮变成「**生成提示词**」，点下去弹出桥接面板（三步：复制提示词 →
    打开 DeepSeek 网页版 → 把回复贴回来），第二步可选地再收一次「这一轮的记忆与情绪」。
    **三条设计约束**：① 贴出去的就是应用本来会发出去的那段提示词（不是另写一份「网页版简化版」）；
    ② 粘回来的回复走与自动生成相同的落盘路径（意图解析、转写清理、气泡分段都一致）；
    ③ 第二步可以跳过，跳过只是「这一轮没被记住」，不会把对话卡住。
    代价写在这里：每轮多两次复制粘贴；刷新页面会丢掉「贴到哪一步」的进度（玩家消息还在）；
    副对话（世界管理员）这条路径暂时还没有桥接。
22. **窄屏上运行时面板是覆盖层，不是第三列。** 规格画的是桌面三栏；640px 以下，
    左栏已经改成抽屉，但运行时面板**当时漏了**——它仍然是 flex 行里的一项（宽 340px），
    于是会话区被挤到 30px、输入框 29px，手机上半个应用不能用（侧边浏览器真机复测测出来的）。
    现在照左栏那套做：`position: fixed` 从右侧盖上来、整屏遮罩（点哪儿都关）、
    面板顶部一个「收起面板」出口。**桌面一个字没改**：那一列仍然常驻。
    同一处还顺手补齐了规格没写但手机必需的三件事：`viewport-fit=cover` +
    `env(safe-area-inset-*)`（否则 iOS 的横条会盖住最后一行）、桥接面板在窄屏竖排、
    导入素材后自动收起左抽屉。
23. **副对话也能在没有 Key 时起草素材（管理员桥接）。** 规格里副对话是「需要真实调用工具」的
    AI 工作流；网页版没有工具接口，所以换成「**让网页版把工具调用写成 JSON 块**」：
    提示词把三个工具的声明渲染成文本并要求它按 `{"tool":…,"arguments":{…}}` 输出，
    应用再解析回 `ChatToolCall`——**校验与执行仍然只有一份**（`parseAdminToolCall` +
    同一个 `executeDraft`），参数缺失、id 不存在这些判断不会因为走了网页版就松掉。
    另外两条取舍：**一次贴回**（API 那条路最多跑三轮「调用 → 回填 → 再说」，让用户贴三次
    不能接受，所以要求它一次写多个块）；**认不出的块不静默吞**（在消息里如实说「它提到了一件
    这里没有的事」）。
24. **设置从「左栏的一段」改成弹窗，分六个大类。** 规格把设置画在左栏底部（打开后占左栏那一段），
    用起来的问题是要在「看设置」和「看世界列表」之间来回切；而设置本身有六个大类，挤一列要滚很久。
    现在是弹窗 + 左侧分类（模型配置 / 个性化 / 身份 / 同步 / 数据 / 已归档），左栏回归
    「只放世界与素材」。手机上是整屏弹窗 + 横向滚的分类条（分栏放不下）。
    **入口不止一个**：归档后那条提示的「去看这条对话」会把弹窗直接开在「已归档」这一类。
25. **多了一套「个性化」，色调与对话区背景都归它管。** 规格只写了「界面长什么样」，
    没写用户能不能改；现在三件事可改：**色调**（酒馆 / 浅色白+蓝 / 深色黑+蓝）、
    **对话区背景**（自己的图，≤2.5MB，存本机）、**心理活动是否默认展开**（默认收起）。
    两条实现约束：色调只换 CSS 变量（组件里不许写死颜色——这一批顺手把 18 处写死的酒馆金
    换成了跟着 `--accent` 走的 `color-mix`）；背景挂在**不滚动**的那一层
    （`.chat-surface::before`），滚动只发生在 `.chat-body` 里，所以「滑动时背景固定、
    只有对话在动」；没用 `background-attachment: fixed`（移动端忽略且掉帧）。
26. **心理活动默认收起。** 规格没提；用户要求「把角色的心理意图隐藏，点击后可查看」。
    气泡上方只留一行「他这一轮想做什么（点开看）」，措辞按来源分（计划 / 盘算 / 自己写的）。
27. **等待期要说话。** 规格没写；用户反馈「思考一段时间后整段抛出」。SSE 本来就在流，
    问题出在等待里界面没有任何反馈（生成前还有一次调度调用、推理模型先流一大段推理流）。
    现在从第一毫秒就有阶段占位（正在判断谁开口 / 正在写）+ 呼吸点，并实时显示推理流的**尾巴**
    （最后一行、截 120 字）——给「它在动」的观感，又不把整段思考摊开（读全了容易被剧透）。
28. **一条消息上的操作平时不显示（悬停 / 右键 / 长按）。** 规格没写「操作按钮常驻还是悬停」，
    实现原本是常驻在最后一段气泡下面（重抽/编辑/删除 + 一行 Token 用量）。用户 2026-09-21 反馈
    两件事：**手机上那排按钮顶出了气泡**（`.bubble-actions` 里横排三颗且不换行，气泡只有
    78% 宽），**桌面上常驻的用量那行与编辑/删除太碍眼**。现在照 Codex 那套：
    - 桌面（`hover: hover`）：平时 `opacity: 0`，鼠标移到**这一行**才露出重抽/编辑/删除，
      旁边一行小字提示「右键看更多」；右键（`contextmenu`）出完整菜单，菜单里除了这三样
      还有 **Token 用量**与**改归属**（多角色时才有）。
    - 手机（`hover: none`）：`.row-actions` 整块 `display: none`——这是「按钮出框」的根治；
      长按 450ms（`touchstart` 计时，`touchmove/end` 取消）出同一个菜单，菜单项 `min-height: 44px`。
    - 触发面是**整行**（`.message-row:hover`）而不是气泡：鼠标从气泡滑向按钮的路上要过几像素
      间隙，用气泡做基准会闪一下。长按之后浏览器还会补发一次 click，用 `swallowNextClick`
      吃掉，否则刚打开的菜单会被「点任意处关闭」立刻收走。
29. **菜单挂在 `body` 上（portal），位置跟着点击/长按的点走。** 第一版把菜单绝对定位在
    `.message-column` 里，测试量出来的坐标完全正确，但**人在屏幕上看不见**：对话区是
    `.chat-body { overflow-y: auto }`，最下面那条消息的菜单整个落在裁剪区外。现在菜单
    `position: fixed` + `createPortal(…, document.body)`，`left/top` 由点击处给，
    挂载后量一次实际尺寸把它推回可视区（边距 8px；`max-width/height` 兜底）。
    这一条同时是**回归时发现的**，不是设计出来的（记录见 EVAL 第二十四节）。
30. **输入区是「一个盒子」，不是「大输入框 + 一排带边框的小按钮」（顺序 41）。** 规格里
    只写了输入区有哪些控件（加号、场景、发送），没写它们长什么样。用户 2026-09-21 要求
    「照 Codex 的样子」。现在的形态：
    - 一个圆角盒子（`--panel-soft` + 1px `--line`，半径 14px）把输入框与下面那排控件装在一起；
      **焦点态由盒子表示**（`:focus-within` 换成 `--accent-soft` 边 + 一圈 16% 的强调色光晕），
      所以 `textarea` 自己不画边框——盒子里再套一个方框就回到了改之前的两层框。
    - 输入框**跟着字数长高**，最多 200px（高过就自己滚）。高度交给浏览器量
      （`scrollHeight`），不自己算行数：换行、中英文混排、手机软键盘都会影响实际高度。
    - 旁边那排控件不再用全局 `.ghost`（带边框的胶囊），换成 `.composer-chip`：**无边框**，
      只有悬停时一层 8% 的文字色底。窄屏上这一排**不许换行**（换行会让发送键掉到下一行的
      左边），「场景：某某」与地点文字各自省略。
    - 主操作是**圆圈里一个向上的箭头**（`.composer-action`，32px；手机上 40px）；
      跑起来时同一个位置换成描边圆圈 + 方块（停止），**尺寸与位置都不动**——「发送 → 停止」
      「停止 → 发送」不该让那一排跳一下。
    - 没配 API Key 时这颗键不是「发送」而是「生成提示词」，所以它展开成带文字的胶囊
      （`aria-label` 也跟着改）；配了 Key 才是纯箭头圆钮。
    - 图标是内联 SVG（`components/Icons.tsx`），不引图标库，吃 `currentColor`——
      三套色调切换不用另写规则。
31. **副对话的输入区与主对话共用同一套。** 规格里副对话是「管理员工作流」，没单独画
    输入区；两处形态不一致会显得像两个应用，所以 `SideChat` 也用 `.composer-box`，
    只是左边少了「模式 / 场景」两个控件、换成这条对话的标题。
