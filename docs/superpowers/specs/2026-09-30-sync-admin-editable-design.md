# 顺序 100：正式管理台与显示名／存储配额编辑

用户已批准正式接入服务器，并选择“显示名＋存储配额”。不添加 VIP、删除、恢复或内容读取能力。沿用 A 的独立回环管理服务、SSH 隧道与随机 token。

## 数据与同步约束

- `account_profiles.display_name` 只允许修改已由用户认领、世代匹配的运营名称，不能管理员代认领账户 ID。
- 新增 `space_policies(space_handle, space_epoch, max_bytes, revision)`；`max_bytes` 可为 null（继承全局默认），或 0 到 1 TiB 的整数。包括未认领空间也可配置容量；界面按完整句柄识别。
- 单空间策略读取在同步 `BEGIN IMMEDIATE` 写入事务内，与计量／写入原子。现有全局字节配置作为默认；记录数、请求体、限流护栏继续执行。降低至已有用量以下保留数据，仅允许不增加总字节的后续批次。
- 空间随机 epoch 变化后旧策略失效，不误施于重建空间。

## 修改流程

1. 用户编辑名称／容量，提交预览；服务端校验白名单字段、空间世代、当前资料与策略。
2. 返回内存中的随机确认票据、明确的修改前后值；票据 2 分钟过期，最多 128 份。
3. 二次确认要求输入完整空间句柄。没有正确票据与句柄时，不备份、不写库。
4. 对真实源库做 `VACUUM INTO` 到独立备份目录、唯一文件名；验证快照 `quick_check` 后才成为 `.bak`，不得覆盖源库／已有备份。备份不通过网页下载。
5. 持久追加操作意图审计，然后拿数据库写锁重新检查预览版本；并发变更拒绝过时确认。
6. 在一个事务中更新运营名称和容量策略，并记录结果。token、凭证、封装、sealed、正文与名称值不进入审计；只记操作 ID、目标句柄、备份文件名、数值额度、结果。

## 管理界面与认证

保留总览／搜索／分页／详情，详情新增编辑与确认区。未认领空间不开放名称编辑。容量可自定义或恢复默认；展示有效上限、已用量和超额状态，避免把 GB 当作 RAM。API 仅新增认证后的 POST 预览／提交；完整回环 Origin 强制用于写请求，GET 继续原边界。读连接仍为只读，写操作单独连接。

写功能仅在 `DRAMATIS_ADMIN_WRITE=1` 且有效备份目录配置时启用。审计／备份失败拒绝操作；服务异常不能冒充未提交成功。恢复和删除没有入口。并发搜索／详情结果使用请求版本，避免旧响应覆盖新状态。

## 正式接入与回滚

先检查正式 WinSW／Node／schema／备份与现行部署产物；先备份、在唯一暂存目录校验新文件，再改目录名切换，保存旧程序。同步服务更新仅用于资料认领与配额执行；网页如需更新，基于实际生产版本仅加入资料同意／认领接线，不上线无关提示词／界面改动。独立管理服务不加入 Caddy／公网反代。Windows secrets 与备份目录用 NTFS ACL。

本机经原管理 SSH 反向隧道转发管理端口；正式 token 在受保护环境文件中生成，真实地址／身份／秘密仅留忽略的 LOCAL-NOTES。生产验收只读；编辑／越权／备份失败／并发／超额写用隔离库验证，不修改真实用户容量来做测试。

回滚停管理写服务、换回保留的同步／网页程序。新增资料／策略表保留，旧程序忽略；回滚旧同步程序时容量策略将不再执行，必须明确记录。库恢复另行人工停写／独立路径校验，不能覆盖运行中 WAL 库。
