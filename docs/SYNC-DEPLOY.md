# 部署方案答卷（P2-6 第四步·下）

> 面向的问题：**你有一台自己的服务器，想把同步后端放上去；项目是公开仓库，
> 但你的服务器地址与个人设置不能进仓库。** 这份文档把「放哪、怎么放、
> 什么会公开、我需要你提供什么」一次讲清，供你决定。
>
> 相关：[SYNC.md](./SYNC.md)（协议与选型）、[../tools/sync-server/README.md](../tools/sync-server/README.md)（操作手册）。
> 最后更新：2026-09-20。

## 一、目标与硬约束

| # | 约束 | 出处 |
| --- | --- | --- |
| 1 | 本地库是唯一真相源，服务器挂了也不影响使用 | SYNC §2 |
| 2 | 服务器**不接触明文**，也不接触同步密码 | SYNC §2 / §3.3 |
| 3 | **公开仓库里不出现你的服务器地址、域名、id、密码、证书** | 你这次提的要求 |
| 4 | 换后端不改客户端、不改加解密 | SYNC §3.2（协议先行） |
| 5 | 手机能用 → 应用必须是安全上下文（https 或 localhost） | 浏览器对 WebCrypto 的限制 |

## 二、信息分层：什么会公开，什么留在哪

这是这份答卷的核心。三类信息严格分开：

| 层 | 内容 | 存放位置 | 会不会进 GitHub |
| --- | --- | --- | --- |
| **公开层** | 协议、内核代码、服务端实现、部署脚本、文档模板（全部用占位符） | 仓库 | ✅ 会，且**应该**会 |
| **本机层** | 你的服务器地址、用户 id、同步密码、恢复码、应用里的世界线数据 | ① 应用设置里（浏览器 IndexedDB）② 你本机的 `.env` / 命令历史 | ❌ 不会（`.gitignore` 已挡住 `.env` / `*.db` / `backups/` / `dist/`） |
| **服务器层** | SQLite 里的密文、两份凭证哈希、两份钥匙封装、systemd 环境变量 | 你的服务器（`/var/lib/dramatis-sync`、`/etc/systemd/system/…`） | ❌ 不会（根本不在仓库里） |

**几个容易漏的地方，先说清**：

1. **服务器地址一旦 commit 就洗不掉**（Git 历史永久保留），所以地址只写在
   你本机的 `.env` 与应用设置里，文档里一律写 `你的域名` / `<你的服务端地址>`。
2. **`git status` 是最后一道门**：部署期间每次提交前用它确认没有 `.env`、`.db`、
   日志、证书被带进去。
3. **截图与录屏**同样会泄露地址——要发到仓库里的截图先把地址栏遮掉。
4. **同步密码永远不会离开你的设备**，所以「密码泄露」只可能发生在你自己那边：
   别写进仓库、别贴进 issue。

## 三、部署形态三选一

> 前提：应用页面必须是安全上下文，否则端到端加密用的 WebCrypto 不存在。

| 形态 | 服务端对外方式 | 应用页面 | 手机能用 | 要域名/备案 | 外网可达 |
| --- | --- | --- | --- | --- | --- |
| **A. Tailscale（推荐先试）** | 服务监听 `127.0.0.1`，由 Tailscale 暴露给 tailnet | 桌面用 `http://127.0.0.1:5273`（安全上下文 ✓）<br>手机用 tailnet 里的 https 地址 | ✅ | ❌ 不需要 | ❌ 只有你自己的设备 |
| **B. 域名 + HTTPS** | Caddy 反代 + Let's Encrypt | 可以就用 `https://你的域名` 直接打开应用 | ✅ | 国内服务器**需要 ICP 备案** | ✅ 公网可访问（凭证不对仍是 401） |
| **C. 只在本机验证** | 不对外，服务与页面都在这台电脑上 | `http://127.0.0.1:5273` | ❌ | ❌ | ❌ |

**我的建议**：先用 **A** 把「手机 ↔ 电脑同一条世界线」跑通（今天就能做，零成本、
零暴露），等你确认体验没问题、也确实想要一个独立网址，再决定要不要为 **B** 走备案。

## 五、我需要你提供的信息

**必填（4 项）**：

1. **服务器的 SSH 入口**：`ssh 用户名@地址 -p 端口`（或者告诉我「我自己敲命令，你只给步骤」）。
2. **系统**：`Ubuntu 22.04 / Debian 12 / 其他`（决定包管理与防火墙命令）。
3. **Node 版本**：在服务器上跑 `node -v`（需要 ≥ 22.5；没有的话我给你装法）。
4. **你打算怎么访问**：选 A（Tailscale）/ B（域名 + HTTPS）/ 先只在本机验证。

**选填（帮你少踩坑）**：

5. 你是否愿意让**我直接通过 SSH 操作**这台服务器？
   - 愿意：我在这台电脑上跑 `ssh`（用你本机已有的密钥），每一步做了什么都会告诉你；
   - 不愿意：我把命令一条条列出来，你粘贴执行，把输出贴回来（同样能做完）。
6. 手机是 Android 还是 iOS（决定 PWA 装法与 Tailscale 客户端步骤）。
7. 有没有现成域名、是否愿意备案（只影响选 B 时的工作量）。
8. 备份想放哪：服务器另一个目录 / 定期拉回你电脑 / 都做。

## 七、验收标准（部署完成的定义）

1. `systemctl status dramatis-sync` 是 running，重启机器后自动起来；
2. 手机与电脑各同步一次后，**两端看到同一条世界线**（消息条数与顺序一致）；
3. 在服务器上 `sqlite3 … "SELECT space_handle, COUNT(*) …"` 能看到记录，
   但**看不到任何明文**（内容全是密文）；
4. 断网时应用照常可用（本地优先），恢复网络后能补同步；
5. `journalctl` 里没有凭证、没有对话内容；
6. 备份文件生成，恢复演练通过；
7. 仓库里 `rg -n "你的域名|你的IP|<你的 id>"` 搜不到真实值。

## 八、回滚与退出

| 场景 | 怎么做 |
| --- | --- |
| 只是不想同步了 | 应用设置里清掉服务端地址即可；本地数据一个字都不动 |
| 想换服务器 | 在新机器上跑同样的服务；应用里改一个地址，客户端会自动从零拉一遍（旧服务器可留着当备份） |
| 想彻底删掉服务器上的数据 | `DELETE FROM records/heads/spaces WHERE space_handle='<句柄>'`（见 README 第 7 节） |
| 服务器到期 | 备份文件 + 各设备本地库都在，数据不会丢；换机器重跑一次部署即可 |
