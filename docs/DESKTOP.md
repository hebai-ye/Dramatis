# 桌面版：PWA 缺什么、要不要上壳

> 回答 [ROADMAP.md](./ROADMAP.md) P2-9 的那个条件性问题：**桌面壳（Tauri）到底触发了没有**。
> 结论先写在最前面，证据在后面一节一条条列。复核日期：2026-09-20。

## 结论

**不触发 Tauri，继续用「启动器 + PWA」。**

四条触发条件逐条量过（见下表）：唯一真正成立的是**第 1 条「后台任务会被打断」**，
而它成立的程度是「延后」而不是「丢」——队列本来就是可恢复的（实测：页面关着 22 秒
一动不动，重新打开 14 秒内自己跑完）。代价是「慢一点」，而 Tauri 的代价是
Rust 工具链 + 一套新的构建与发布链路，外加本机现在根本没装 Rust（`rustc` / `cargo`
都不在 PATH 里）。收益与代价不成比例，所以**先补强启动器**：

- `tools/desktop/launch.mjs` 的 `--prod` 现在会**判断构建产物是不是最新的**，
  最新的就直接用（不再每次白等一遍构建）；`--force-build` 可以强制重建。
- 新增 `tools/desktop/install-shortcut.ps1`：做一个能双击的快捷方式（桌面 / 开始菜单），
  带应用图标。图标是**本机从 `icon-192.png` 现场生成**的 `.ico`（不新增二进制资产进仓库）。
- 想完全不要那个命令行窗口的话，还有一条更省事的路：**把 `http://127.0.0.1:5273`
  装成 PWA**（浏览器地址栏右侧的「安装」）。manifest 与 Service Worker 都已经就绪，
  装完就是开始菜单里的一个独立窗口，没有常驻进程。

## 四条触发条件的实测

### 1. 后台任务会被打断 —— **成立，但可恢复**

先把事实摆清楚：应用的后台队列是**页面内的定时器**（`platform/background-runner.ts`
加 `lib/worker.ts` 每 8 秒看一次队列），所以页面一旦被关掉、冻结或回收，队列就停。
这一点不用猜，直接量：

在一台真实 Chrome（本机 Windows）加真数据库上，往队列里放一条 `turn.analyze`
（就是「一轮结束后抽取记忆」那个任务），然后比较「页面开着 / 关着」两种情形：

| 情形 | 任务状态 | 记忆条数 |
| --- | --- | --- |
| **应用页面关着**，任务已入队，等 22 秒 | 仍然 `pending`，`attempts 0` | 72 → 72（一条没写） |
| **应用页面开着**，同一个任务，等 14 秒 | `done` | 72 → 76（1 条客观 + 3 条视角） |
| **应用页面关着**，任务状态是 `running`（模拟被回收），等 9 秒 | 仍然 `running` | 76 → 76 |
| 之后**重新打开页面**，等 14 秒 | `done`，`attempts 1` | 76 → 80（自己把那一轮补完了） |

也就是说：**浏览器一暂停页面，后台就停摆；页面回来，它自己接着做。**
这就是 P0 时定下「后台队列必须幂等且可恢复」的那条约束在起作用
（`recoverInterrupted()` 加幂等键，见 `platform/background-runner.ts`）。

这件事的代价是：

- 记忆与情绪会**晚一点**写进去（下次打开页面时补），不影响这一轮已经落盘的回复；
- 自动同步晚一点推（同步请求同样排在页面里，见 `lib/sync.ts`）。

如果哪天这两样变成不可接受（例如想要「关着页面也在后台整晚跑剧情」），
第 1 条才算真正触发。

**没验到的**：标签页「冻结 / 回收」本身没能在这个自动化环境里造出来——
CDP 的 `Page.setWebLifecycleState('frozen')` 要求页面先处于 hidden，
而这台机器上被自动化接管的页面一律报 `visible`（真机有头窗口也一样）。
所以上面用的是**等价且更严格**的实验：直接把页面关掉（被回收的页面也就是不跑了）。

### 2. 需要 OS 级密钥存储 —— **缺口成立，但不触发壳**

在真浏览器里逐条问过（`apps/web/tools/platform-probe.html`，同一份页面在
浏览器与 Capacitor 壳里各跑一次就能对比）：

| 能力 | 结果 |
| --- | --- |
| `navigator.credentials` | 有，但只管 WebAuthn 与浏览器自动填充的密码，**没有「存一段任意密钥」的接口** |
| `chrome.runtime`（扩展上下文） | 没有——普通页面拿不到 `chrome.storage` |
| `crypto.subtle`（WebCrypto） | 有 |
| IndexedDB | 有（默认落盘方式，但明文） |

所以「把 API Key 交给 Windows 凭据管理器」在浏览器里确实**做不到**，
而 Tauri 能做到。但这不是非上壳不可的问题：P2-8 早就给了替代方案——
**用口令派生密钥、加密后落盘**（`crypto.subtle` 就够，`core/crypto` 里的那套
派生与封装也是现成的）。它比 OS 凭据管理器多一步「输入口令」，
但不用为它引入一整套原生构建链路。

**现状**：两档（仅本次会话 / 明文保存在本机浏览器）都如实写在设置里，
还没做「口令加密落盘」。要做的话是独立的一小步，与桌面壳无关。

### 3. 需要直接调用本地模型 —— **不需要，HTTP 就够了**

模型接入本来就是 OpenAI 兼容的 HTTP（`provider/openai-compatible.ts`），
而 Ollama、LM Studio、llama.cpp server 全都提供这个接口。
也就是说「本地模型」这条需求**今天就能满足**：把接口地址填成
`http://127.0.0.1:11434`（Ollama 默认）即可，不需要壳。

浏览器里多出来的那点能力是 `navigator.gpu`（WebGPU，探针里为真）：
理论上可以「模型直接跑在页面里」。这是**另一个产品方向**
（把推理权重下载进浏览器缓存），不是「壳 vs PWA」的问题——PWA 也能用 WebGPU。

### 4. 需要监控本地文件夹 —— **浏览器已经能做**

探针在这台机器的 Chrome 153 上读到的结果：

| 能力 | 结果 | 用途 |
| --- | --- | --- |
| `showSaveFilePicker` | 有 | 导出时直接选路径写入（封存、归档正文都走它） |
| `showDirectoryPicker` | 有 | 用户授权一个目录，之后可以整目录读写 |
| `FileSystemObserver` | **有** | 目录变更通知——「往目录里放一张卡就自动导入」这件事有原生入口 |

注意最后一行：以前这条要上壳，现在浏览器自己有了。
代价是权限要用户点一下（每次会话重新授权一次），以及目录句柄要持久化保存。

**要不要做**是另一个问题（优先级不高），但**做得了**这一点已经成立。

## 现在这条路线长什么样

```
双击快捷方式（可选）
  └─ node tools/desktop/launch.mjs --prod
       ├─ 构建产物是最新的？→ 直接用（否则构建一次）
       ├─ 起 vite preview（固定端口 5273 —— 换端口等于换一个空数据库）
       └─ 用 Chromium 的 --app 打开：没有地址栏、没有标签页、有任务栏图标

或者：浏览器里「安装应用」→ 变成 PWA（无常驻进程，开始菜单里有入口）
```

两者**共用同一个源**（`http://127.0.0.1:5273`），所以数据也是同一份——
换着用不会看到两个世界。

## 什么时候回来重新评估

出现下面任何一条，就重新读这一页、认真评估 Tauri：

1. 想要**关掉窗口之后后台还继续跑**（整晚推演、定时整理记忆）——
   这一条 PWA 原理上做不到，只能靠壳或服务端；
2. 真的要**把 API Key 放进系统凭据管理器**（而不是口令加密）；
3. 要在应用里**直接加载本地模型权重**（而不是连本地 HTTP 服务）；
4. 目录监控变成核心功能，而 `FileSystemObserver` 与权限模型挡路
   （例如用户不愿每次授权）。

真的要做的时候，先确认本机有 Rust：`rustc --version` 与 `cargo --version`
（**2026-09-20 这台机器上都没有**，要上壳得先装 Rust 工具链与 MSVC 构建工具）。
另外 P0-1 的平台能力适配层就是为这一天准备的：存储 / 密钥 / 文件读写 / 后台执行
各是一个接口，加壳等于「多写一组 adapter」，不用重写业务层。

## 复现这套证据

```bash
# 1) 起本地服务（在仓库根目录，沙箱外）
node apps/web/node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5273 --strictPort

# 2) 平台能力探针（浏览器里打开，逐条读结果）
#    http://127.0.0.1:5273/tools/platform-probe.html

# 3) 桌面启动器（真机：会打开一个应用窗口）
pnpm desktop:prod          # 或用 tools/desktop/install-shortcut.ps1 做快捷方式

# 4) 后台队列「停摆 / 恢复」那四个格子：步骤见 EVAL.md 第十四节
```
