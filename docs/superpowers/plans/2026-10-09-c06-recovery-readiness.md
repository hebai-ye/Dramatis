# C06 Windows 服务器隔离恢复准备方案

> 执行方按本方案分阶段验收。主任务负责实际检查与结果记录；子任务只做静态审阅，不运行测试或服务器命令。用户已授权沿用现有运维连接；root已完成真实SQLite副本及旁路迁移/health/停机后检查，详见[实演记录](./2026-10-09-c06-recovery-report.md)。账户读写、解密、同步及保留策略仍未关闭。

**Goal：** 在现役 Windows 服务器验证一份真实完成快照的可恢复性，先完成 SQLite 副本检查，再按条件完成应用账户读写和解密验收。

**Architecture：** 同卷旁路目录内保留未迁移副本，并另建可写服务副本。生产服务、数据库和源快照均不修改；旁路只启动同步进程，绑定独立回环端口。

**Tech Stack：** Windows、现役 Node 的 `node:sqlite`、已部署同步服务编译产物、文件 SHA-256。

**Spec：** [原验证规格](./2026-10-03-validation-brief.md)、[当前验证清单](../../VALIDATION-2026-10-03.md)、[现行运维入口](../../SYNC-DEPLOY.md#当前运维入口2026-10-03-文档校正)。

## 执行约束

- 不重新审计26项，不重跑已稳定的项目门禁，不新增依赖或修改服务端实现。
- 只用现成、确认已经完成的快照；不复制运行中的生产主库，不临时运行周期备份脚本。该脚本还会裁剪旧文件。
- 不替换生产数据库、不停生产、不配置反代、不安装服务，不启动管理台或模型网关。
- 地址、真实路径和最少必要的非秘密完成摘要只填 ignored `deploy/LOCAL-NOTES.md`；密钥、凭据、正文、空间句柄不写入该文件，不在聊天或公开报告输出账户、正文、密文、凭证或钥匙封装。
- 快照包含可读运营元数据；旁路权限仅供执行账户，不放入公开网页目录。
- 检查或隔离条件不明时停止在当前阶段；保留副本和证据，不通过删除 WAL/SHM 或覆盖源文件修复。

## 用户只需确定的事项

| 事项 | 默认建议 | 执行方负责确认 |
| --- | --- | --- |
| 主机与入口 | 现役 Windows 数据服务器 | 沿用已有运维连接，或由用户在服务器运行步骤；无需向聊天提供地址和凭据 |
| 演练窗口 | 一次30分钟 | 明确开始时间；超时停止新增步骤并安全收尾 |
| 快照 | 最新的**已确认完成**快照 | 在明确备份目录选择来源，核对完成记录并现场计算hash；用户不用手报hash |
| 旁路位置 | 数据目录同卷的 `recovery-drills/<本次时间戳>/` | 核对实际卷、可写权限、空间和解析后路径；排除链接及与源/生产库别名重合 |
| 测试端口 | 现场选择独立端口 | 仅应用阶段需要；启动前检查空闲且不同于生产端口 |
| 账户与解密 | 应用阶段再准备 | 使用独立测试账户；解密材料只由用户在隔离客户端输入，执行方不读取 |

没有账户材料时，可以完成SQLite副本检查；不能据此宣称应用解密通过。保留策略未统一不阻断检查一份已有完成快照。

## Review Focus

1. 最终 `.bak` 文件名并不总是完成信号；周期脚本会直接写该文件，必须取得成功退出与不再写入的证据。
2. 路径或链接可能指向生产文件；不能只靠目录名字或字符串前缀断言隔离。
3. 同步进程会在绑定端口前写库、迁移并生成缺失epoch；即使启动失败，也可能改变服务副本。
4. `/health` 不读数据库；200不能代替结构、行数或账户解密验收。
5. hash/schema变化和RPO/RTO需要按阶段解释；不能把迁移后hash变化误判为源损坏，也不能把mtime或打开副本耗时冒称完整恢复指标。

## 阶段一：真实 SQLite 副本恢复

**输入：** 已确认主机与窗口、明确的备份目录及完成快照、批准的同卷旁路根目录。

**输出：** 未迁移副本与文件/SQLite检查结果。此阶段不启动任何服务，不需要端口或解密材料。

- [ ] 核对快照是普通文件、非链接、非零字节，排除 `.partial`、生成中的文件和来源不明文件。管理端需确认所用发布流程包含只读quick_check后改名且所选最终文件不再写入，不要求停止常驻管理服务；周期 `.bak` 另需生成进程成功退出和文件不再写入的证据。hash稳定两次不能代替完成证据，不要仅按文件名或mtime选最新文件。
- [ ] 记录快照生成/完成证据、字节数和SHA-256。确认旁路路径不指向源或生产库，不包含生产文件；真实路径保留在私有记录。
- [ ] 在本次旁路目录创建一个全新的普通副本，命名为 `snapshot-original.db`。复制前确认目标不存在、权限和空间足够，不能覆盖已有文件。
- [ ] 核对源复制前后hash相同，副本字节数与hash等于源；任何不一致停止，不启动服务。
- [ ] 用现役Node的 `DatabaseSync(copyPath, { readOnly: true })` 打开副本，并设 `PRAGMA query_only=ON`。`PRAGMA quick_check` 必须恰好一行 `ok`；只记录布尔结果，失败时不公开原始检查文本或异常。
- [ ] 在内存核对实际schema和表列，输出schema摘要hash、静态预期名称的存在性和表级汇总行数。至少检查 `spaces`、`records`、`heads`；账户/运营表按快照所属版本检查，缺失记为missing，不能记为零，也不能直接断言旧版本快照损坏。
- [ ] 只核对已由相应版本源码确认的关键关联。禁止 `SELECT *`、按空间分组或输出账户/密钥/余额/请求明细。
- [ ] 关闭只读句柄，保存未迁移副本和精简证据；记录该阶段实际耗时。结果只可写“SQLite副本检查通过/失败”，应用阶段仍待验。

## 阶段二：旁路应用恢复

**输入：** 阶段一通过的未迁移副本、版本明确的部署产物与Node、空闲回环端口；账户读写/解密验收另需独立测试账户和用户输入材料。

**输出：** 迁移后的工作副本、服务状态及账户/同步验收结果。

- [ ] 从 `snapshot-original.db` 另复制全新的 `sync-working.db`，核对启动前hash一致。原始副本继续保留，只向工作副本提供写权限。
- [ ] 核对Node路径/版本和同步编译产物版本；不在本次演练临时构建、安装依赖或更新生产程序。版本不明则停止应用阶段。
- [ ] 只为本次子进程建立清洁环境，不修改系统、用户或生产服务环境。Node使用已核验的绝对路径；子进程环境白名单仅含 `SystemRoot`、`TEMP`、`TMP`（存在时）及下列明确设置，不继承PATH或其它项。不得继承 `NODE_OPTIONS`、TLS配置、生产启动配置或API Key。

| 子进程变量 | 值 |
| --- | --- |
| `DRAMATIS_SYNC_DATA` | 解析并确认的独立 `sync-working.db` 绝对路径 |
| `DRAMATIS_SYNC_HOST` | `127.0.0.1` |
| `DRAMATIS_SYNC_PORT` | 确认空闲且与生产不同的测试端口 |
| `DRAMATIS_SYNC_ORIGINS` | HTTP基本检查时为空；客户端阶段只填明确的隔离页面精确来源，禁止通配符 |
| `DRAMATIS_SYNC_TRUSTED_PROXY_HOPS` | `0` |
| `DRAMATIS_SYNC_QUIET` | `1` |

- [ ] 仅通过已部署 `start.mjs` 启动同步进程，记录本次PID与启动时间，验证监听地址/端口归属。禁止启动 `gateway.mjs` 或管理服务。
- [ ] 记录回环 `/health` 的状态码及 `ok`。它只证明进程可应答；无账户材料时可记录HTTP检查结果，仍不得关闭应用恢复验收。
- [ ] 账户材料就绪后，确认隔离客户端使用测试来源和新测试账户。由用户输入材料，执行方不读取；验证副本账户读写、正文解密、epoch/cursor、增量同步与重连。所有测试实体仅进入副本和隔离客户端。
- [ ] 停止本次旁路PID并确认端口释放；重新只读检查工作副本的quick_check、schema和汇总行数。迁移可能新增表/列及回填字段；将迁移影响与本次测试新增行分开说明，不要求启动后文件hash等于原快照。
- [ ] 应用解密或同步未执行时分别记待验；只测health不能写“恢复到应用可用”。原始副本和阶段一证据始终保留。

## 指标与收尾

| 字段 | 记录规则 |
| --- | --- |
| 快照恢复点 | 用快照完成证据，注明一致性读取区间；不以文件mtime替代 |
| RPO | 需要演练参考时点与可确认的生产写入/快照恢复点；无法确定则记未测或有依据的范围，不编造精确值 |
| SQLite检查耗时 | 分别记录复制耗时和只读检查耗时，并记录起止时间 |
| 应用可用RTO | 从已注明的恢复开始点到账户读写与解密成功的实测时间；单列人工等待材料的耗时，明确总耗时是否含等待；仅打开库或health成功不能替代 |
| 清理 | 默认保留旁路副本；如需清理，先确认仅属于批准的本次绝对目录和本次PID均退出，不删源、生产库或其WAL/SHM |

报告只记录阶段结果、精简摘要、实际耗时和未测项。原始日志可能含私有信息，不能转储到公开报告；异常只提取失败类别。

## 独立保留策略交接

`tools/sync-server/backup.mjs` 默认30份，按同basename前缀与`.bak`后缀筛选、文件名字典序裁剪，不检查有效性或来源分桶；同目录同basename的管理快照可能被纳入。`tools/sync-admin/src/backup.ts` 具有partial→quick_check→rename发布，但没有GC。每桶30个成功快照、失败不驱逐有效快照仍待部分一实现与独立验收。本演练只证明所选快照的恢复结果。
